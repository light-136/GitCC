# 02 — 模块契约（Module Contracts）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

> **文档性质**：每个模块的职责、公开接口、禁止事项。是 03 依赖规则与 06 测试规则的锚点。
> **约定**：每个模块必须能用一句话回答"它负责什么"，并能用 CMake target 依赖关系机械验证"它没越界"。

---

## 1. `dscope_utils`（工具库，无领域语义）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **职责**：字节序转换、位操作、时间戳格式化。**不感知**"设备/通道/报警"等任何业务概念。
- **公开接口**：
  - `ByteUtils`：大端/小端读写、CRC 表初始化辅助（纯函数，`static` 或自由函数）。
  - `TimeUtils`：`QDateTime` ↔ 时间戳/字符串格式化。
- **禁止**：include domain/protocol/infra/ui 任何头；不得含 `Q_OBJECT`；不得有单例。

## 2. `dscope_protocol`（协议引擎，字节级契约）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **职责**：定义帧格式、CRC、组帧/解帧、通道配置编解码。**只认识字节，不感知业务语义**。
- **公开接口**（保留 V2 已验证的高质量设计，重写以去 O(n)）：
  - `Crc16`：MODBUS CRC16 计算（查表法，纯函数）。
  - `FrameBuilder`：`build(func, cmd, payload) -> QByteArray`。
  - `FrameParser`：`feed(QByteArray)` ＋ `nextFrame() -> optional<ParsedFrame>`；内部 `std::deque<uint8_t>` 或读游标，`remove(0,n)` 改 O(1)。
    - `ParsedFrame`：合法帧（SOF/FUNC/CMD/LEN/DATA/CRC 已校验）**或**错误事件（错误类型＋位置＋计数），**不产出"带内容的坏帧"**。
  - `ChannelConfigCodec`：通道配置的编码/解码（往返、边界、脏数据防御）。
  - `ProtocolVersion`：帧头版本号字段＋版本协商（见 ADR-06）。
- **禁止**：include domain 任何头；不得用 `std::vector<uint8_t>` 替代 `QByteArray` 作为主容器；不得静默丢弃 CRC 错（须产出错误事件）。

## 3. `dscope_domain`（领域模型与编排逻辑）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **职责**：值对象、实体/聚合、端口接口定义、连接/采集状态机、报警规则评估逻辑。**只依赖 QtCore**。
- **公开接口**：
  - **值对象**（纯 struct，值语义，不继承 QObject）：
    - `DataPoint`：`channelIndex / value / deviceTimestamp / hostArrivalTimestamp`。
    - `ChannelConfig`：`name / unit / rangeMin / rangeMax / ...`。
    - `AlarmRule`：`channelIndex / threshold / operator / hysteresis`（阈值单一来源）。
    - `AlarmEvent`：`id / channelIndex / type(trigger|recover) / timestamp / message`。
  - **实体/聚合**：
    - `Device`：聚合根，含 `Connection` 状态机（Disconnected→Connecting→Connected/Error，指数退避）与 `Acquisition` 状态机（Idle→Running），两者**正交**（连接≠采集）。
    - `Connection/Acquisition` 状态机：`canTransition(from,to)` 纯函数，供测试确定性验证。
  - **端口接口（Port，由 domain 定义、infra 实现）**：
    - `IDevicePort`：`open/close/read/write` ＋ 能力位查询（TCP/Serial 差异见 ADR-07）。
    - `IClock`：`now()`（测试可伪造时间）。
    - `IDataSource`：`LiveSource`/`ReplaySource` 的统一接口（源切换状态机载体）。
  - **错误码**：`ErrorCode` 枚举（分类＋致命性维度），见 ADR-08。
- **禁止**：include `QtWidgets/QtGui/QtNetwork/QtSerialPort`；不得含 `QTcpSocket`/`QTcpServer`；不得把 `QAbstractItemModel` 编进本库（V2 错误地这么干了）。

## 4. `dscope_infra_device`（设备适配器）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **职责**：实现 `IDevicePort` 的具体传输——TCP、Serial（P9）、以及作为测试基础设施的 SimulatorDevice。
- **公开接口**：
  - `TcpDeviceAdapter : IDevicePort`：`QTcpSocket` 封装，`readyRead` 喂 FrameParser；连接超时用 QTimer（复用 `connectTimeoutMs`，**必须接线**）。
  - `SerialDeviceAdapter : IDevicePort`（P9 有代码后再建，本期不建空壳）。
  - `SimulatorDevice`：可复现异常注入的测试设备（复用 V2 的 FaultInjector＋5 模式＋`-p/-m/-f/-i`）。
- **禁止**：把 TCP/Serial 拆成两个静态库（同一库里两个实现类，端口照样可替换）；不得在 adapter 里做报警/业务判断。

## 5. `dscope_infra_support`（支撑设施）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **职责**：配置、日志、记录落盘。三者按**关注点**归入一个库，但**类级**边界清晰，不互相耦合。
- **公开接口**：
  - `ConfigAdapter`：INI 持久化（`QSettings`），**具体类＋构造注入**（不套接口、不做单例）。
  - `LogAdapter`：分级日志，**具体类＋构造注入**。
  - `RecordFileAdapter`：CSV 异步落盘（记录线程调用，不在主线程槽内同步写）。
- **禁止**：不做单例（V2 的 `LogManager::instance()/ConfigManager::instance()` 是"不可注入、不可替换、不可并行测试"的根因）；日志/配置不得互相依赖。

## 6. `dscope_ui`（界面层）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **职责**：QWidget 页面、自绘控件、Model/View。**只渲染与收集用户输入，不做业务判断**。
- **公开接口**：
  - `MainWindow`：组装页签、接线数据总线与页面、状态栏、退出确认。
  - `MonitorPage`：通道卡片（直绘控件）＋报警中心。**纯渲染页，用 Model/View＋信号槽直连，不套 Presenter**。
  - `DevicePage`：设备配置/列表/连接控制。**有交互编排（表单校验→入模型→持久化→状态回写），配 Presenter**。
  - `RecordPage`/`SettingsPage`/`LogPanel`：各自职责。
  - `DeviceListModel`/`AlarmEventModel`：`QAbstractItemModel`，**只承载低频结构化/事件数据**。
  - 自绘控件：`LineChartWidget`/`GaugeWidget`/`LedIndicator`，注入 `Theme` 对象，`paintEvent` 只读成员阈值。
- **禁止**：高频实时值走 `dataChanged`（须直绘 `setValue`）；报警阈值不得在 View 内自己算一遍（0.85 三进宫）；不得用裸 hex 颜色（走 Theme）。

## 7. 端口可替换性与"接缝"清单

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

依赖倒置只对**真接缝**（有第二实现＋接口稳定廉价）做接口，其余用具体类＋构造注入：

| 依赖 | 是否接口 | 理由 |
|------|---------|------|
| `IDevicePort` | ✅ 接口 | TCP/Serial/Simulator 三实现，真需求 |
| `IClock` | ✅ 接口 | 测试伪造时间价值巨大，`now()` 一个方法 |
| `IDataSource` | ✅ 接口 | 实时/回放切换，源状态机载体 |
| `ConfigAdapter` | ❌ 具体类 | 单一实现，构造注入即可替换 |
| `LogAdapter` | ❌ 具体类 | 同上，fake 日志的断言价值/成本不成比例 |
| `RecordFileAdapter` | ❌ 具体类 | 同上 |
