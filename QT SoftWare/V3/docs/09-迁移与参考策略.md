## 4. 迁移执行纪律

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

1. **迁移 = 重写，不是复制**：迁移项只搬"设计思路与字节契约"，代码按 V3 新架构（05 编码规则）重写，禁止 `cp` 后改两行。
2. **每迁移一项，先写其失败场景测试**（06 第 4 节），再写实现——测试资产先于实现落地。
3. **丢弃项进"墓碑清单"**：在本文件第 3 节留档，防止未来"咦，DeviceController 去哪了"时误以为遗漏。
4. **协议兼容基线**：V3 新帧格式必须能识别 V2 旧帧（version 字节区分），因 V2 simulator/固件已按旧契约交付（ADR-06）。
5. **SimulatorDevice 是 V3 的测试基础设施**，与生产代码同等质量对待——它被所有 Integration/E2E 测试依赖。
