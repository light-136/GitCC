## 1. 架构总览

V3 采用 **B 版最小专业架构**：4 个静态库 + 2 个可执行程序，无空层、无空接口、无空 target。

```
app（Composition Root，唯一知道具体类的地方）
 │
 ├──▶ ui ────────────┐
 │    │              │
 │    ├──▶ acquisition
 │    │      ├──▶ domain
 │    │      ├──▶ protocol
 │    │      └──▶ infra(logger)
 │    │
 │    ├──▶ domain
 │    ├──▶ protocol
 │    └──▶ infra
 │
 └──▶ simulator 独立程序：只依赖 protocol + QtNetwork
```

## 2. 模块职责（每模块一句话）

| 模块 | 一句话职责 | 禁止 |
|------|-----------|------|
| `protocol` | 帧的编解码与 CRC，只认字节 | include domain |
| `domain` | 值对象 + 报警规则 + 连接状态转移 + 错误码，纯规则无 I/O | include Widgets/Network/文件系统 |
| `acquisition` | 用 socket 收字节 → 喂 parser → 转发 DataPoint，管理采集线程 | 做业务判断/报警 |
| `ui` | 渲染 + 收集输入 + 交互编排 | 做协议解析/报警规则 |
| `infra` | logger 写日志（具体类） | 做业务/协议 |
| `simulator` | 可复现异常注入的模拟设备（独立进程） | 依赖 ui |

## 4. Domain 数据模型（纯值对象 + 纯函数）

```cpp
// 值对象：纯 struct，可拷贝可比较，不继承 QObject
struct DataPoint     { int channelIndex; double value; QDateTime deviceTs; QDateTime hostArrivalTs; };
struct ChannelConfig { QString name; QString unit; double rangeMin; double rangeMax; };
struct AlarmRule     { int channelIndex; double threshold; double hysteresis; };
struct AlarmEvent    { enum Type {Trigger, Recover}; Type type; int channelIndex; QDateTime ts; };

// 纯函数 / 纯规则
QVector<AlarmEvent> AlarmEngine::evaluate(const DataPoint&);  // 有内部状态（哪些通道在报警中），输入输出都是值对象
bool  canTransition(ConnectionState from, ConnectionState to);
int   nextRetryDelayMs(int attemptCount);   // 退避：1s→2s→4s→…封顶 30s

// 错误码：分类枚举，第一阶段无"致命性维度"
enum class ErrorCode { Ok, ConnectTimeout, ConnectionRefused, CrcError, ParseError, ReceiveTimeout, InvalidFrame };
```

- **DataPoint 双时间戳**：`deviceTs`（设备时间戳，第一阶段 Simulator 帧不含，留无效）+ `hostArrivalTs`（主机收到时刻，采集线程填写）。这是 v1 的关键差异，与 V2 单一时间戳不同。
- **AlarmEngine 放 domain 的约束（v1 R1 接受）**：它不继承 QObject、不发信号、不碰 QDateTime 之外的任何东西；它的状态是"评估上下文"，不是"对象生命周期"。

## 5. 协议与数据流

### 5.1 帧格式（V3，7 字节帧头）

```
| SOF(2B: 0xAA 0x55) | VERSION(1B: 0x01) | FUNC(1B) | CMD(1B)
| LEN(2B 大端) | DATA(LEN) | CRC16(2B 低字节在前) |
```

- `kHeaderLen = 7`（SOF2 + VERSION1 + FUNC1 + CMD1 + LEN2）。
- `kMaxPayloadLen = 1024`（LEN 超限即判非法帧头，防恶意超大长度囤积）。
- CRC16 = MODBUS（init 0xFFFF，poly 0xA001），**覆盖从 VERSION 起**（即 SOF 之后所有字节 = VERSION+FUNC+CMD+LEN+DATA）。标准向量 `"123456789" → 0x4B37`。

### 5.2 数据流

```
Simulator ──TCP──▶ AcquisitionWorker(采集线程) ──readyRead──▶ FrameParser.feed/next
                                                              │
                                            合法帧(Frame)      错误(Error: CrcError/InvalidHeader)
                                                              │                              │
                                         dispatchFrame 按 FUNC 分发              handleFrameError 计数+告警
                                                              │
                                       emit pointsReady(QVector<DataPoint>)  (QueuedConnection 跨线程)
                                                              ▼
                                                    主线程 MonitorPage（直绘控件 setValue）
```

### 5.3 FUNC / CMD

| FUNC | 含义 |
|---|---|
| `0x01` kFuncData | 实时采样数据帧 |
| `0x02` kFuncConfig | 配置下发帧 |
| `0x03` kFuncQuery | 查询请求 |
| `0x83` kFuncQueryResponse | 查询响应（= 0x03 \| 0x80） |

| CMD | 含义 |
|---|---|
| `0x01` kCmdQueryChannels | 查询通道配置 |

## 6. 线程模型（1 主线程 + 1 采集线程，非"固定 N"）

| 线程 | 数量 | 职责 |
|------|------|------|
| 主线程（GUI） | 1 | UI 渲染 + Composition Root |
| 采集线程 | 1 | 持有 AcquisitionWorker + FrameParser，收字节→解析→转发 |

- **没有队列**：`emit pointsReady(points)` 连多个 slot（渲染/报警）就是天然多播，QVector 隐式共享浅拷贝零压力。
- **没有分片器、没有"每设备一线程"**：单设备 1 线程；多设备阶段再长分片器。
- 跨线程只传值对象（`QVector<DataPoint>` / `QVector<ChannelConfig>`），元类型在 `AcquisitionWorker` 构造函数集中 `qRegisterMetaType`。

---

## 7. QObject 生命周期与关停协议

| 对象 | 归属线程 | 关停 |
|------|---------|------|
| `AcquisitionWorker`（QObject） | 采集线程 | 主线程 `stop()` → `quit()+wait()` |
| UI 对象 | 主线程 | 对象树回收；关闭事件先停采集 |

**关停顺序（Composition Root，顺序即正确性）**：

1. `QMetaObject::invokeMethod(worker, "stop", BlockingQueuedConnection)` —— 保证 stop 槽在采集线程执行完（abort socket、停定时器、状态落 Disconnected）。
2. `workerThread.quit()` + `workerThread.wait(5000)` —— 退出事件循环并等待线程结束。
3. **超时兜底（缺陷 #4 修复）**：`wait(5000)` 超时则 `qWarning` 告警 + `terminate()` 再 `wait()`，避免退出被永久卡住（正常路径 stop 已 abort，不会走到该分支）。
4. 随栈析构：stop 已把定时器停掉、套接字 abort，析构清理全是 no-op，栈对象安全析构。

## 8. 错误处理策略

| 错误 | 动作 |
|------|------|
| CRC 错（CrcError） | 丢弃 + 计数 + 告警，**不断线** |
| 非法帧头（InvalidHeader：LEN 超限 / VERSION 不符） | 丢弃 + 计数 + 告警（`InvalidFrame`），**不断线** |
| 连接超时（ConnectTimeout，5s） | 触发重连（指数退避） |
| 接收超时（ReceiveTimeout，3s） | 触发重连（指数退避） |
| 连接被拒（ConnectionRefused） | 触发重连（指数退避） |

- **断开触发 = 超时类错误**，单次 CRC/非法帧只计数告警不断开（v1 R6 采纳）。
- **重连退避**：1000 → 2000 → 4000 → 8000 → 16000 → 封顶 30000ms；`attempt >= 31` 时钳制返回 30000（规避有符号左移 UB，缺陷 #1 修复）。
- **错误码映射**：`FrameError::CrcError → ErrorCode::CrcError`，`FrameError::InvalidHeader → ErrorCode::InvalidFrame`（缺陷 #5 修复）。
- 错误通过 `connectionError(int)` 跨线程上抛，UI 用 `errorCodeName()` 翻译成中文展示。

## 9. Simulator / FaultInjector 设计

- **SimulatorDevice**：QTcpServer 监听端口，QTimer 周期广播（默认 20Hz）；每客户端独立 `FrameParser` 解析请求，命中通道配置查询回 `0x83` 配置帧。
- **FaultInjector**：纯函数 `正常帧 → 0..N 段异常字节流`，无状态、可复现（同一输入同一输出）。

| FaultType | 变换 | 测试目标 |
|---|---|---|
| Sticky | 一帧拆两半分两次发 | 接收端半包拼接 |
| Fragment | 两帧拼接一次发 | 接收端粘包拆分 |
| CrcError | 篡改 DATA 首字节 | 接收端 CRC 拒绝 |
| InvalidFrame | 篡改 LEN 为 0xFFFF | 接收端越界防御 |
| GarbagePrefix | 注入垃圾前缀（含游离 0xAA） | 接收端重同步 |

- 二者是**测试基础设施**，与生产代码同等质量；simulator 是独立进程，也是 Integration/E2E 的依赖。

## 10. UI 数据流（按频率分流）

| 数据 | 频率 | 载体 |
|------|------|------|
| 实时值（曲线/仪表/LED） | 10~20Hz × N 通道 | 直绘控件 `setValue`，不走 dataChanged |
| 报警事件 | 事件级 | `AlarmEventModel`（QAbstractListModel + beginInsertRows） |
| 通道配置 | 连接建立时一次 | `onChannelConfigReceived` → 重建卡片 |

- 阈值**一次性注入**（配置变化回调里 `chart->setThresholdLine`），非每帧查询。
- MonitorPage 纯渲染直连；连接入口在主窗口工具栏（**不建 DevicePage**，v1 R3 采纳）。
- 颜色走 `Theme` 单一来源，禁裸 hex。
- **UI 与 acquisition 解耦**：MainWindow 用 opaque worker 指针（前向声明）+ `QMetaObject::invokeMethod`（字符串方法名）+ 字符串式 SIGNAL/SLOT，**不 include acquisition 头**。

## 11. 测试策略（第一阶段两层，非四层）

| 层 | 框架 | 测什么 | 边界判据 |
|----|------|--------|---------|
| Unit | QtTest（`QTEST_APPLESS_MAIN`） | protocol（crc/半包粘包/重同步/越界）+ domain（报警触发去重恢复/状态转移/退避边界） | 只链接 domain+protocol，禁 QtNetwork |

## 12. Release / Deploy 策略

- **单一版本源**：`project(VERSION)` → `configure_file` 生成 `version.h`（代码用）+ `version.rc`（PE 资源用），只改一处。
- **windeployqt 配置期硬失败**：`find_program(... REQUIRED NO_DEFAULT_PATH)`，找不到 `FATAL_ERROR`（DoD R3）。
- **deploy 不入 git**：`.gitignore` 覆盖 `build/`、`build_release/`、`deploy/`、`*.zip`；发布包是带版本号 zip（DoD R6）。
- **工具链硬校验**：Qt 5.12.2 + MinGW 7.3.0 posix-seh + windres 来自 mingw730_64，配置期不匹配即 `FATAL_ERROR`。
- **PE 版本资源编译**：用 `add_custom_command` 手动调 windres 编译 `.rc`（不传 `-I`），规避 CMake 原生 RC 规则把含空格的 include 目录传给 windres 导致预处理失败的坑（项目路径 `D:/Gemi/QT SoftWare/V3` 含空格）。
- **完整性门禁**：`verify_deploy.ps1` 断言 10 个关键文件（exe + Qt DLL + 平台插件 + MinGW 运行时 DLL）。
- **e2e 探针**：`e2e_simulator_version`（`--version` 输出含版本号）+ `e2e_datascope_selftest`（`--selftest` 输出 `SELFTEST OK`）。

## 14. 第一阶段明确"不做什么"

不记录/回放、不串口、不多设备、不数据分析、不 JSON 场景文件、不 benchmark、不 CI 服务器、不空接口/空 target/空抽象、不以代码/测试/文档/commit 数量为 KPI、AlarmEngine 不加致命性维度、测试不做四层（只两层）、**不做 infra/config 持久化**（host/port 用单一常量）。

## 16. 修订结论（采纳 Reviewer R1~R6）

1. **合并 TcpClient 进 AcquisitionWorker**（R2）—— 砍一个 QObject，生命周期简化。
2. **砍 DevicePage + Presenter**（R3）—— 连接入口放主窗口工具栏。
3. **错误策略明确**（R6）—— 断开触发 = 超时类错误；单次 CRC/非法帧只计数告警。
4. **保留**（R1/R4/R5 有条件）—— AlarmEngine 在 domain（约束为纯规则）、ChannelConfigCodec（数据驱动）、infra logger（极薄非单例）。

---

## 17. 执行红线（机械遵守）

- 命名空间统一 `dscope`（`dscope::domain`/`protocol`/`acquisition`/`ui`/`infra`/`simulator`）。
- `domain` 与 `protocol` 只 link `Qt5::Core`，白名单机械验证。
- `FrameParser` 用读游标（`m_readPos`），禁 `remove(0,n)` 消费。
- 帧头 `kHeaderLen=7`，CRC16 覆盖从 VERSION 起。
- 断开只由「超时类错误」触发；单次 CRC/非法帧只计数告警。
- 每个阶段：编译 → 测试 → 修复 → 重编译 → 重测试，绝不最后一次性编译。
