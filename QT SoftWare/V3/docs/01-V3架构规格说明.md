## 1. 设计目标（为什么重做）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

V2 的死因不是"不够抽象"，是**"抽象没接线＋魔法数＋教学代码污染"**。V3 的目标不是堆更多层，而是：

1. **少而精**：5 层，不设空层、不建空 target、不写空接口。
2. **边界清晰**：每个模块的职责可用一句话说清，且能用 CMake target 依赖关系**机械验证**。
3. **可测试**：领域逻辑零 I/O、零事件循环；每个失败场景都有断言 ErrorCode/状态转移的测试。
4. **可维护**：单领域模型（消灭 V1/v2 平行宇宙）、单版本源、单阈值来源。
5. **可扩展**：端口可替换（TCP/Serial/Simulator 同接口）、数据源可切换（实时/回放），但不为"可能的未来"提前写代码。

## 3. 关键设计决策（每条对应一份 ADR，见 08）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

### 3.1 domain 依赖 QtCore，禁止 Widgets/Gui/Network/SerialPort

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **红线**：domain 的 `.h/.cpp` 只允许 include QtCore 头（`QString/QByteArray/QVector/QDateTime/QUuid/QSettings` 等值类型），禁止 `QtWidgets/QtGui/QtNetwork/QtSerialPort`。
- **理由**（否决"零 Qt"）：真正的可测性障碍是事件循环与 I/O（在 Adapter/UI 层），不是 QtCore 容器。保留 QtCore 拿到三样 V2 已验证的正确性资产——COW 跨线程浅拷贝（O(1)）、QDateTime 时区精度、QUuid＋中文显示名内聚。
- **连带收益**：消灭 V2 最痛的一块——`Q_DECLARE_METATYPE`/`qRegisterMetaType` 三要素不一致（V2 曾为同一类型注册两个名字）。

### 3.2 protocol 保留 QByteArray，去 O(n) 落点改容器语义

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- FrameParser 的输入/输出主容器是 `QByteArray`（与 QtNetwork 边界零转换、COW 零拷贝）。
- 真正该"去 O(n)"的是 `remove(0,n)` 的头部删除：FrameParser 内部改用 `std::deque<uint8_t>` 或"读游标＋环形缓冲"，只移动指针不搬字节。
- protocol 不 include domain（字节契约不感知业务语义）。

### 3.3 单一 IDataBus＋可切换 Source（不是"两个总线实现"）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- UI 永远只订阅**一个** `IDataBus`。
- 总线的数据源是一个 `Source` 状态机：`LiveSource` / `ReplaySource`。
- 源切换时序（显式原子协议）：`Live → pause → drain(清在途) → swap → resume`。切换在 UI 线程串行化，帧带"源标记/会话 ID"，漏帧可被检测而非静默混入。

### 3.4 报警引擎挂在丢帧之前的完整流

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- 报警评估在**采集线程内、数据入有界队列之前**同步完成（"同帧触发"）。
- 渲染可容忍丢帧，报警不能——报警要连续数据判趋势（连续 N 点超阈/斜率/突变）。

### 3.5 错误模型：`std::variant<T, Error>`＋`[[nodiscard]]`＋ErrorCode 分类

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- 跨模块边界返回 `std::variant<T, Error>`（或轻量 `std::optional<T>`＋ErrorCode 侧信道）。
- ErrorCode 是**分类枚举**（连接/CRC/解析/超时/配置），不再用 `QString` 糊一锅。
- 所有返回错误的结果对象标注 `[[nodiscard]]`；错误态取 value 触发 assert。

## 4. 数据流（完整链路）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

```
[SimulatorDevice / 真实设备] --TCP帧--> [TcpDeviceAdapter(I/O线程)]
                                              │ readyRead → QByteArray
                                              ▼
                                    [FrameParser::feed/nextFrame]  (protocol，保留QByteArray)
                                              │ 完整帧(合法) / 错误事件(非法)
                                              ▼
                                    [采集线程内：帧→DataPoint 映射]
                                              │
                        ┌─────────────────────┴─────────────────────┐
                        ▼(完整流，丢帧之前)                            ▼(完整流)
                 [AlarmEngine.evaluate]                     [Source状态机 → IDataBus]
                        │ 触发/恢复                                  │
                        ▼                                           ▼
                 [AlarmEventModel]                     [扇出：渲染队列 / 记录队列]
                        │                                    (各独立SPSC，渲染允许丢旧)
                        ▼                                           │
                 [报警中心ListView]                     ┌──────────┴──────────┐
                                                        ▼                      ▼
                                              [MonitorPage直绘控件]   [RecordFileAdapter落盘]
```

**关键点**：
- 报警在丢帧之前的完整流上（见 3.4）。
- `IDataBus` 只承载**高频数据点流**；设备列表、报警事件走各自的 Model（低频/事件流，不经 DataBus）。
- 记录（落盘）走独立队列，在记录线程异步执行，不在主线程槽内同步写文件。

## 5. 生命周期模型

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

| 对象 | 创建线程 | 销毁/关停协议 |
|------|---------|--------------|
| `IDevicePort`（socket） | 所属 I/O 线程内 | 关停用 `abort()`（立即关闭），不用 `disconnectFromHost()`（优雅关闭可能卡死） |
| `Device` 聚合根 | UI 线程 | 请求→确认握手：`stop()` 后等 Worker 回 `stopped()` 确认，再 `quit()+wait()` |
| 各 I/O 线程 | 分片器 | 固定 N 个，随进程存活，不随设备数增删 |
| 记录线程 | UI 线程启动 | 同握手协议，队列 drain 带 deadline（如 100ms，超时丢弃剩余） |
| UI 对象 | 主线程 | 对象树统一回收；关闭事件先 `stopAcquisition()` 再退出 |

**铁律**：`wait()` 必须带超时，但超时后**不得继续析构共享资源**（V2 的 `delete m_mutex` 就是超时后继续析构才崩的）。超时兜底 = `abort()`＋再 `wait()`，仍失败则泄漏该线程但记录日志告警。

## 6. 第一阶段最小切片（V3-MVP）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

**必须交付**：
1. `dscope_utils`＋`dscope_protocol`（Crc16/FrameBuilder/FrameParser，保留 QByteArray，deque 去 O(n)）。
2. `dscope_domain`（单领域模型：DataPoint/ChannelConfig/AlarmRule/Device 聚合根＋Connection/Acquisition 状态机＋IDevicePort/IClock/IDataSource 端口）。
3. `dscope_infra_device`（TcpDeviceAdapter＋SimulatorDevice，实现 IDevicePort）。
4. `dscope_infra_support`（ConfigAdapter/LogAdapter/RecordFileAdapter）。
5. `dscope_ui`（MainWindow＋MonitorPage＋DevicePage＋自绘三控件＋DeviceListModel/AlarmEventModel）。
6. 固定 N I/O 线程＋SPMC 扇出＋报警挂完整流＋连接/采集状态机接线＋关停握手。
7. 完整测试门禁（见 06/07）。

**明确不做（后续阶段）**：serial 落地、多设备、回放、数据分析、JSON 场景文件、benchmark、CI 服务器。这些**不建空 target、不写空接口**。
