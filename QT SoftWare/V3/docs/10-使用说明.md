# 10 — 使用说明（用户手册）

> **文档性质**：DataScope Studio V3 的最终用户操作手册。
> **适用对象**：需要在本机构建、运行、操作该系统的开发者与测试人员。
> **权威基准**：本文描述的行为与参数以 `AUTHORITATIVE-SPEC-v1.md` 与最终代码为准。

---

## 1. 产品简介

**DataScope Studio V3** 是一个工业多通道数据采集与实时监控系统（学习项目）。

- **采集端**：`DataScope.exe` —— Qt 图形界面程序，通过 TCP 连接模拟设备，实时接收协议帧、解析数据点、渲染曲线/仪表/LED、触发报警。
- **模拟设备**：`simulator.exe` —— 独立控制台程序，作为"可复现异常注入"的测试设备，周期广播协议数据帧，供采集端 E2E 联调与健壮性测试。

两者可同机运行，构成一条真实的 TCP 数据闭环。

## 3. 构建与发布

### 3.1 一键构建（Debug）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1
```

- 产出：`build/` 目录（Debug 构建）。
- 产出可执行文件：`build/DataScope.exe`、`build/simulator.exe`、`build/tst_v3_unit.exe`、`build/tst_v3_integration.exe`。

### 3.2 一键构建（Release）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -Release
```

- 产出：`build_release/` 目录（Release 构建）。

### 3.3 完整发布（推荐，一次性完成构建 + 测试 + 部署 + 打包）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/release.ps1
```

该脚本按顺序执行：清理旧产物 → configure(Release) → build → ctest（4 项测试）→ windeployqt 部署 → 完整性门禁 → 运行时冒烟 → 打包带版本号 zip。

- 产出目录：`deploy/`（可双击运行）。
- 发布包：`DataScope-V3-<版本>-win64.zip`（位于项目根目录）。

> `scripts/build.ps1` 与 `scripts/release.ps1` 已固化本机工具链绝对路径，零远程依赖。

## 4. 运行方式

### 4.1 快速体验（本机联调）

1. **启动模拟设备**（先开设备，采集端才能连上）：

   ```powershell
   deploy\simulator.exe
   ```

   控制台输出形如：`模拟设备已启动：0.0.0.0:45678  模式=normal  帧间隔=50ms  通道数=4`

2. **启动采集端**：

   ```powershell
   deploy\DataScope.exe
   ```

3. 在 DataScope 主窗口工具栏，确认主机为 `127.0.0.1`、端口为 `45678`，点击 **「连接」**。

4. 连接成功后，监控页开始刷新 4 路通道的实时曲线、仪表与 LED。

5. 点击 **「断开」** 可停止采集；关闭窗口程序自动退出。

### 4.2 独立运行参数

#### 模拟设备 simulator.exe

```powershell
simulator.exe                           # 默认：normal 模式，0.0.0.0:45678，50ms/帧
simulator.exe -p 41000                  # 指定监听端口
simulator.exe -m fault                  # 故障模式（轮询注入五类异常）
simulator.exe -i 20                     # 帧间隔 20ms
simulator.exe -p 45678 -m fault -i 50   # 组合参数
```

| 参数 | 全名 | 说明 | 默认 |
|---|---|---|---|
| `-p` | `--port` | 监听端口（1~65535） | 45678 |
| `-m` | `--mode` | `normal`（正常）/ `fault`（故障注入） | normal |
| `-i` | `--interval` | 数据帧发送间隔（毫秒） | 50 |
| `--version` | | 打印版本号 | — |
| `--help` | | 打印帮助 | — |

#### 采集端 DataScope.exe

| 参数 | 说明 |
|---|---|
| `--version` | 打印版本号后退出 |
| `--selftest` | 运行协议级自检（CRC 标准向量 + 帧往返），输出 `SELFTEST OK` 后退出 |

> `--version` / `--selftest` 主要用于发布前的 e2e 探针（DoD R4），也可手动验证产物可用。

## 6. 数据与报警

### 6.1 默认通道配置（设备是唯一事实来源）

| 通道 | 名称 | 单位 | 量程 |
|---|---|---|---|
| 0 | 温度 | ℃ | 0 ~ 100 |
| 1 | 压力 | kPa | 0 ~ 100 |
| 2 | 流量 | L/min | 0 ~ 100 |
| 3 | 转速 | rpm | 0 ~ 100 |

- 通道 0~2 波形中心 50、幅度 < 50，值域落在 (0, 100) 内（正常，不报警）。
- 通道 3（转速）中心 85、幅度 30，波形在 55~115 间摆动，**周期性越过量程上限 100**，用于演示"越限报警 → LED 亮 / 报警中心记录触发与恢复"的完整链路。

### 6.2 报警规则

- 采集端默认阈值 = 量程上限 100，回差 = 量程 5%（即 5）。
- 触发：值 > 100 → 报警触发，LED 亮、报警中心记录 Trigger。
- 恢复：值 < 95（threshold − hysteresis）→ 报警恢复，记录 Recover。

## 7. 连接与错误处理说明

- **默认连接**：`127.0.0.1:45678`（单一常量源 `src/domain/connectiondefaults.h`）。
- **连接超时**：5 秒未连上 → 判定 `ConnectTimeout`，按指数退避自动重连。
- **接收超时**：3 秒无数据 → 判定 `ReceiveTimeout`，自动重连。
- **重连退避**：1s → 2s → 4s → 8s → 16s → 封顶 30s。
- **坏帧（CRC 错 / 非法帧）**：只计数告警，**不触发断线**（这是权威规格的硬性规定，避免单次脏数据放大成重连风暴）。

## 9. 常见问题（FAQ）

| 现象 | 原因与处理 |
|---|---|
| 连接后一直"连接中"，5 秒后变"错误" | 模拟设备未启动，或端口不一致。先启动 `simulator.exe`，确认端口 45678。 |
| 提示"监听失败，端口可能被占用" | 45678 已被占用。用 `simulator.exe -p 41000` 换端口，并在界面输入对应端口。 |
| 双击 `deploy/DataScope.exe` 报缺 DLL | 未走 `release.ps1` 部署。用 `scripts/release.ps1` 重新发布（会自动 windeployqt + 补 MinGW 运行时 DLL）。 |
| 想验证产物是否完整 | 运行 `scripts/release.ps1`（内含 `verify_deploy.ps1` 完整性门禁 + `--version`/`--selftest` 冒烟）。 |
