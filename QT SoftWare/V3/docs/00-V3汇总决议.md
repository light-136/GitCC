## 一、裁决总纲（一句话）

**V3 草案的诊断全对（V2 是"为凑指标堆代码/测试/文档"），但草案自己的处方同样患了"为架构而架构"——它把 V2 的门面病换了一层更重的洋葱皮。本决议砍掉 Application 层、推翻"domain 零 Qt"与"每设备一线程"两个伪红线、把报警/回放/超时三个被写空的时序问题补成显式状态机，最终收敛为"少而精、边界清晰、可测试、可维护、可扩展"。**

| # | 裁决内容 | 推翻草案的哪条 | 发起角色 |
|---|---------|--------------|---------|

| P0-6 | **帧格式升级必须带协议版本号＋完整新帧布局＋版本协商** | 草案第十三节"加 SEQ+时间戳"却不定义共存 | 03(攻1) |

### 2.2 采纳为 P1 的收敛修正（影响设计，但非架构红线）

| # | 裁决内容 | 发起角色 |
|---|---------|---------|
| P1-1 | protocol 层**保留 QByteArray**，"去 O(n)"落点改为 FrameParser 内部 `std::deque`/读游标，而非裸 `std::vector<uint8_t>` | 02(攻C)/03(攻3) |
| P1-2 | 弃用手写 `Result<T>`，改用 `std::variant<T, Error>`（或 `std::optional<T>`＋`[[nodiscard]]`） | 02(攻E)/05(攻4)/01(P2-3) |

| P1-4 | 半开连接/连接超时/接收超时给出**具体落点**（V2 已示范"建模不接线"，V3 不许第三次） | 03(攻2) |
| P1-5 | infra 按**关注点**合并（device/support），不建 `infra_serial` 空壳 target；serial 等 P9 有代码再建 | 01(P1-2) |

### 2.3 采纳为 P2 的纪律性修正（防止过度工程重演）

| # | 裁决内容 | 发起角色 |
|---|---------|---------|
| P2-1 | 依赖倒置只对**真接缝**做接口（`IDevicePort`/`IClock` 等），`Logger/ConfigStore` 用具体类＋构造注入 | 01(P2-1) |
| P2-2 | 第一阶段的**最小切片**：domain＋protocol＋device port（TCP＋simulator）＋单领域模型＋连接/采集状态机＋报警 domain 化；serial/多设备/数据分析/JSON 场景文件/benchmark 显式标"后续阶段" | 01(P2-2) |
| P2-3 | 每层测试给**可机械验证的边界判据**（CMake 链接白名单＋头文件白名单＋时间预算），统一断言框架（纯逻辑 gtest，含 Qt 事件循环 QtTest，二选一） | 05(攻1) |
| P2-4 | 单一版本源（`project(VERSION)`＋`configure_file` 生成 version.h/version.rc），windeployqt **配置期硬失败**，`deploy/` 不入 git | 07(攻2/3/6) |
| P2-5 | 主题 token 落地：单一 C++ Theme 源＋QSS 模板占位符替换＋自绘控件注入；亮色是独立 token 集而非"卸载 QSS" | 06(攻5) |

| P2-7 | 错误处理补**阈值策略**：单次错误不断开，连续 N 错或持续 T 秒无有效帧才断开；ErrorCode 补"致命性"维度 | 03(攻8) |

### 2.4 明确"驳回/有条件保留"的意见（Principal 有独立判断，不盲从）

| 草案/审查主张 | 裁决 | 理由 |
|--------------|------|------|
| 草案"domain 零 Qt" | **驳回**（见 P0-1） | 三个理由（可测/可移植/可消费）全部不成立，代价是 COW 丢失＋转换税＋QUuid/时区/中文名无处安放 |
| 草案"每页一个 Presenter"一刀切 | **有条件保留** | 仅 DevicePage 类"有交互编排"的页用 Presenter；MonitorPage 类纯渲染页用 Model/View＋信号槽直连（06 攻1） |
| 草案"所有表格走 QAbstractItemModel" | **驳回"所有"** | 高频实时值走 dataChanged 是性能灾难，须按频率分流（06 攻2） |
| 草案"回放是独立 IDataBus 实现" | **驳回** | 会导致"两个源在总线层打架"，竞态本质未变（01 P0-2） |
| 草案"每设备一个 I/O 线程" | **驳回**（见 P0-3） | Qt 非阻塞 socket 单线程天然多路复用，场景数据量（20Hz×4）根本不需并发 |
| 草案"CI 自动化发布" | **有条件驳回** | 本机无远程 CI 服务器，"理想国 CI"落不了地；改为本机脚本＋CTest 门禁，GitHub Actions 留作未来同源迁移（07 攻1） |
| 草案"handwritten Result<T>" | **驳回**（见 P1-2） | `std::variant<T,Error>` 由标准库保证拷贝/移动/无默认构造陷阱 |

## 三、V3 最终架构总览（一句话版）

```
UI（QWidget 页面 + 自绘控件，只认 Model/View 与直绘接口）
  │  依赖 ↓
domain（依赖 QtCore 的领域模型：值对象 + 状态机 + 报警规则 + 端口接口定义）
  │  依赖 ↓
application 已删除 → 编排逻辑回归 domain 状态机 + UI Presenter
  │
protocol（保留 QByteArray 的帧解析，纯字节契约，不依赖 domain）
  │
infra（device: TCP/Serial/Simulator 适配器；support: config/log/record）
  │
utils（byte/time 工具）
```

**关键结构决策**：5 层（UI / domain / protocol / infra / utils），**没有**独立 Application 层。端口接口由 domain 定义，Adapter 由 infra 实现，依赖倒置方向不变，但"接缝"只保留少数真接口。

## 五、对用户的三点诚实声明

1. **V2 的"金子"只有 5 样**：FrameParser 流式解析、FaultInjector 纯函数注入、SimulatorDevice 组件化、"数据源可替换"思想、元类型注册三要素一致的经验。其余（DeviceController 死代码、双领域模型、0.85 硬编码、services 门面、教学代码污染）一律不迁移，只作"失败样本"参考。
2. **V3 的第一阶段不做"大而全"**：只做最小切片（domain＋protocol＋TCP/simulator 适配器＋单领域模型＋连接/采集状态机＋报警 domain 化＋监控页）。serial/多设备/回放/数据分析/JSON 场景文件/benchmark 全部列为"后续阶段"，不提前建空 target、不提前写空接口。
3. **所有规格的可执行性由"机械判据"保证，不由"愿望"保证**：测试有链接白名单、门禁有"失败即非零"、版本有"单一源＋configure_file"、部署有"windeployqt 配置期硬失败"。凡是无法机械验证的定性条款，都标注为"纪律"而非"红线"，并给出其对应的机械判据。
