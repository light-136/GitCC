# 06 — 测试规则（Testing Rules）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

> **文档性质**：V3 测试架构。核心目标是**防止"为凑指标写测试"重演**——V2 失败的根因不是"没画四层表"，是"没有任何机械手段强制测试必须证明行为、失败必须阻塞"。
> **总原则**：每一层测试必须有**可机械验证的边界判据**；测试独立于开发 Agent（防"自己测自己"）。

---

## 1. 四层测试与机械边界判据（本文件的核心）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

| 层 | 测什么 | 断言框架（二选一，不许"或"） | 机械边界判据 |
|----|--------|--------------------------|------------|
| **Unit** | 纯函数/纯逻辑：Crc16、FrameParser、状态机转移、退避计算、时间戳回退 | **gtest**（无 Qt 事件循环） | CMake 只链接 `dscope_domain`＋`dscope_protocol`＋`dscope_utils`；**白名单禁止 QtNetwork/QtWidgets/QtSql**；构建期检查 `LINK_LIBRARIES` |
| **Component** | 单个 Adapter 面对模拟 socket | **QtTest**（含事件循环） | 允许链接单个 `dscope_infra_*`；被测对象只能有一个；**时钟必须 fake** |
| **Integration** | 应用级用例＋真实模拟器（随机端口） | **QtTest** | 必须链接 `dscope_simulator`（真实 socket 内嵌）；**禁止链接任何 fake/mock socket** |
| **E2E** | 双进程全真实（DataScope＋simulator） | 脚本 | 测试体**独立进程启动**（`Start-Process`/`fork+exec`），进程边界由脚本断言 |

> **关键升级**：V2 的四层靠"文件头注释自证"，`tst_dataservice.cpp` 自称单元测试却 `#include <QTcpServer>` 起真 socket。V3 用 CMake 链接白名单机械验证"这个测试真的在测它声称的那一层"。

## 2. fake 预算梯度（每层 fake 到哪，写死）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

| 层 | fake 预算 |
|----|----------|
| Unit | 全 fake（含 IClock） |
| Component | I/O 用真实 QtNetwork 回环＋设备侧真实 SimulatorDevice 或最小 fake；**时钟必须 fake** |
| Integration | socket 全真实，SimulatorDevice 真实内嵌；**禁止 mock socket**（红线，与"domain 不 include Qt"同地位） |
| E2E | 双进程全真实 |

> **为什么"Integration 禁止 mock socket"是红线**：fake socket 不暴露真实 TCP 的粘包/半包/断连时序，而这些恰是 Integration 层存在的唯一理由。若 Integration 也 fake，就退化成"单元测试马甲"，精确复刻 V2 的"名字不同、内容相同"。

## 3. 时序测试的诚实划分（确定性测 vs 探针测）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **可确定性测**（gtest 干）：
  - 状态机转移、退避计算、超时判定、时间戳回退——全部抽成**纯函数/纯状态机**（`IClock` 注入），用 fake clock 确定性验证。
  - QTimer 只做"每个 tick 调一次纯函数"的薄壳，**Qt 世界不做时序决策**。
- **只能探针测**（QtTest 干，如实标注"探针"而非"证明"）：
  - 真正的 socket 断连/线程退出，明确接受 `QTRY_VERIFY_WITH_TIMEOUT`＋宽松超时＋失败重试一次。
  - **负向时序断言**（"永不发生"）无法用任何事件驱动宏断言——只能用"等一个窗口然后赌它没发生"，须在用例注释里如实标注。

> **禁止 `qWait(固定毫秒)`/裸 `sleep`**（V2 残留 `qWait(300)/qWait(1200)/sleep 1.5`）。`QTRY_VERIFY_WITH_TIMEOUT` 不是确定性方案，只是 flaky 的缓释——不能把"不确定设计"测成"确定"。

## 4. 失败场景必须覆盖（工业软件生命线）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

每个失败场景至少一条**断言了 ErrorCode 或状态转移**的用例（不是"不崩"）：

| 场景 | 断言目标 |
|------|---------|
| CRC 错帧 | 产出错误事件（类型＋计数），不产出"带内容的坏帧" |
| 非法帧（LEN 越界/未知 FUNC） | 丢弃＋计数，不立即断开 |
| 半包/粘包 | FrameParser 正确重组 |
| 连接超时 | `ErrorCode::Timeout`（且证明 `connectTimeoutMs` 真的接线了） |
| 半开连接（拔网线） | 接收超时触发断开重连 |
| 断线重连 | 指数退避序列（1s→2s→4s→封顶） |
| 线程退出时序 | 握手协议下不崩、不泄漏（超时兜底路径） |
| 报警触发/恢复 | 状态机去重、恢复、通道过滤 |

## 5. 门禁（本地单命令，失败即非零）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- 交付一条 `build_and_verify.ps1`，串起：`configure → build → ctest --output-on-failure → smoke → e2e`，**任一环节非零即整体非零**。
- 本机无 CI 服务器，"失败即阻塞"的载体就是这条命令，写进 DoD（见 07）——完成 = 这条命令返回 0，不是"开发者记得跑了"。
- e2e/smoke **必须用 `add_test` 收编进 CTest**（V2 的 probe/smoke 没进 CTest，门禁覆盖不到）。

## 6. 防"测了等于没测"的唯一硬判据：变异冒烟

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **变异冒烟**：删掉被测代码的一行关键逻辑，对应测试必须转红。
- 这是防 `tst_signalslotdemo`（测已删除的教学对象，删掉生产代码＋测试文件一起删就"全绿"）的唯一硬手段。
- 时间预算（超时视为"测试写重了，返工"）：Unit＋Component ≤ 2 分钟，Integration ≤ 1 分钟。
