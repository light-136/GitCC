# 03 — 依赖规则（Dependency Rules）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

> **文档性质**：把 01 架构规格的依赖方向，落成 CMake target 级别的可机械验证规则。
> **核心原则**：依赖方向 = UI → domain →（protocol 平行）→ infra → utils；**domain 与 protocol 不互相依赖，protocol 不依赖 domain**。

---

## 1. CMake target 依赖白名单（唯一允许的链接关系）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

```
dscope_ui          -->  dsope_domain, dsope_protocol, dsope_utils
dscope_domain      -->  dsope_utils            （仅 QtCore）
dscope_protocol    -->  dsope_utils            （仅 QtCore）
dscope_infra_device --> dsope_domain, dsope_protocol, dsope_utils
dscope_infra_support-> dsope_utils             （仅 QtCore，不依赖 domain）
dscope_utils       -->  Qt5::Core              （仅 QtCore）
```

> **注意**：`dscope_infra_support` 不依赖 domain——配置/日志/记录是纯支撑设施，不应感知领域对象（记录的是"序列化后的字节/CSV 行"，不是 `DataPoint` 对象本身）。

## 2. Qt 模块白名单（红线）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

| 模块 | 允许的 Qt 模块 | 禁止的 Qt 模块 |
|------|--------------|--------------|
| dsope_utils | Core | 其余全部 |
| dsope_protocol | Core | 其余全部 |
| dsope_domain | Core | **Widgets/Gui/Network/SerialPort** |
| dsope_infra_device | Core + Network（＋P9 时 SerialPort） | Widgets/Gui |
| dsope_infra_support | Core | 其余全部 |
| dsope_ui | Core + Widgets + Gui | Network/SerialPort |

> **机械验证**：`dscope_domain`/`dscope_protocol` 的 target 若在 `target_link_libraries` 里出现 `Qt5::Widgets/Qt5::Network/Qt5::SerialPort`，构建期直接报错。这条不是"纪律"，是 CMake 白名单硬约束。

## 3. 头文件白名单（lint 规则）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- domain 的 `.h/.cpp` 顶部 include 检查：出现 `#include <QWidget>`、`<QTcpSocket>`、`<QTcpServer>`、`<QAbstractItemModel>` 任一即违规。
- protocol 的 `.h/.cpp`：出现任何 `domain/*` include 即违规。
- 用一个极简脚本（`tools/check_includes.ps1`）在构建期扫描，命中即非零退出。

## 4. 依赖倒置的落地边界

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **Port 接口由 domain 定义**（`IDevicePort/IClock/IDataSource` 在 `dscope_domain`），**Adapter 由 infra 实现**——依赖方向指向 domain，不反向。
- Composition Root 只在 `main.cpp` 与 `MainWindow` 组装：这里知道具体 Adapter（`new TcpDeviceAdapter`），其余代码只认 Port 接口。
- **不做的倒置**：`ConfigAdapter/LogAdapter/RecordFileAdapter` 不套接口，用具体类＋构造注入（见 02 第 7 节）。

## 5. 禁止的依赖模式（V2 病根对照）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

| 禁止模式 | V2 实例 | V3 规则 |
|---------|--------|---------|
| domain 混入 Model | `devicelistmodel.cpp/alarmeventmodel.cpp` 编进 `datascope_domain` | Model 只属于 UI 层 |
| 双领域模型并存 | V1 `models.h` ＋ V2 `domainmodel_v2.h` 平行宇宙 | 单领域模型，一个 `DataPoint` 定义 |
| 死代码控制器 | `DeviceController` 无人引用 | 状态机放 domain `Device` 聚合根，主窗口直接驱动，无中间控制器 |
| 硬编码在 View | `monitorpage.h kAlarmRatio=0.85` | 阈值来自 `AlarmRule.threshold`，UI 只消费 |
| 单例基础设施 | `LogManager::instance()/ConfigManager::instance()` | 构造注入的具体类 |

## 6. 验证方式（门禁的一部分）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

1. **CMake 链接白名单**：`target_link_libraries` 只允许第 1 节列出的关系；任何越界链接在 configure 期 `message(FATAL_ERROR)`。
2. **Qt 模块白名单**：第 2 节的"禁止列"进入 CMake 断言。
3. **头文件扫描**：`tools/check_includes.ps1` 纳入构建后检查，命中即红。
4. **人工审查**：Code Review 检查"是否出现双领域模型/单例/View 内算阈值"这三类 V2 病根。

---

*本规则的可执行部分（1/2/3）全部为机械判据，不由开发者自觉保证。第 4/5 条属设计纪律，由 Code Review 保证。*
