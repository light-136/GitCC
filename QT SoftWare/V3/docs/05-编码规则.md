# 05 — 编码规则（Coding Rules）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

> **文档性质**：V3 源码的强制编码规范。目标：代码可读、边界自明、错误不可忽略、无魔法数、无教学污染。
> **适用范围**：所有 `src/` 下生产代码（教学代码另行隔离，见 09）。

## 1. 命名规范

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

| 类别 | 规则 | 示例 |
|------|------|------|
| 类/结构体 | PascalCase，名词或名词短语 | `FrameParser` / `AlarmRule` / `TcpDeviceAdapter` |
| 接口（Port） | `I` 前缀 | `IDevicePort` / `IClock` / `IDataSource` |
| 函数/方法 | camelCase，动词开头 | `feed()` / `nextFrame()` / `canTransition()` |
| 成员变量 | `m_` 前缀 | `m_buffer` / `m_sourceState` |
| 常量 | `k` 前缀，或 `constexpr` | `kMaxPayloadLen` |
| 命名空间 | 全小写，分层对应 | `datascope::domain` / `datascope::protocol` |

## 2. 注释规范（中文，但"解释为什么"而非"翻译代码"）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **类头注释**：必须含"这个类负责什么＋它不负责什么（边界）"。V2 的病是注释过浓且讲"教学"，V3 的注释讲"设计意图与边界"。
- **函数注释**：只写"前置条件/后置条件/线程上下文/抛错条件"，不写"这行代码在做什么"。
- **教学式注释（WPF 对照）**：本学习项目允许生产源码含"对应 WPF 的 X"这类迁移对照注释——这是照顾用户 WPF 背景学 Qt 的明确学习目标，是特性而非违规。决议见 docs/12 第 7 节。
- **魔法数必须命名**：任何裸数字（`0.85`、`1024`、`5000`）必须提取为具名常量或配置项，并注释其来源/理由。

## 3. 值语义与对象模型

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **值对象**（DataPoint/ChannelConfig/AlarmRule/AlarmEvent）：纯 struct，值语义，**不继承 QObject**，可拷贝、可比较。
- **实体/聚合根**（Device）：有状态、有生命周期、需通知 UI 的，允许用 QtCore 的 QObject 信号槽（或 `std::function` 通知接口），**并显式规定与 Model/View 的桥接路径**，禁止 UI 层再造 DTO/ViewModel（那是 V2 双模型问题的翻版）。
- **Model 只属于 UI 层**：`QAbstractItemModel` 直接消费 domain 值对象（经 QVariant 包装），中间不再引入 DTO 层。
- **跨线程只传值对象**：禁止裸指针/引用跨线程。

## 4. 错误处理（`std::variant<T, Error>`＋`[[nodiscard]]`＋ErrorCode 分类）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **禁止手写 `Result<T>`**：用 `std::variant<T, Error>`（语义明确、拷贝/移动由标准库保证），或轻量 `std::optional<T>`＋ErrorCode 侧信道。
- **强制 `[[nodiscard]]`**：所有返回错误的结果对象标注 `[[nodiscard]]`，调用方忽略即编译告警。
- **错误态禁取 value**：`std::variant` 的 `std::get<T>` 在错误态下抛 `bad_variant_access`，或配 `std::visit` 强制处理两分支。
- **ErrorCode 是分类枚举**（连接/CRC/解析/超时/配置），并带**致命性维度**（瞬态可丢弃 vs 致命需断开），见 ADR-08。
- **禁止静默丢弃**：CRC 错/解析异常必须产出错误事件（计数＋可选日志），不得无声吞掉。

## 5. 错误降级策略（阈值，不是孤立计数器）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

| 错误类型 | 致命性 | 动作 |
|---------|--------|------|
| CRC 错 | 瞬态 | 丢弃＋计数，**不重发**（周期连续流，最新值胜出） |
| 非法帧（LEN>上限/未知 FUNC） | 严重 | 丢弃＋计数＋告警，**不立即断开**（单次脏数据断开会放大成重连风暴） |
| 连接超时/接收超时 | 致命 | 触发重连（退避） |
| 连续 N 错 或 持续 T 秒无有效帧 | 致命 | 断开重连（阈值策略见 ADR-08） |

## 6. 禁止清单（V2 病根，Code Review 必查）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

1. 禁止双领域模型（一个概念只一个定义）。
2. 禁止单例（`instance()` 模式）。
3. 禁止死代码控制器（无人引用的状态机/服务）。
4. 禁止 View 内自己算报警阈值（阈值唯一来源是 `AlarmRule.threshold`）。
5. 禁止裸 hex 颜色（走 Theme 注入）。
6. 禁止 `qWait(固定毫秒)`/裸 `sleep`（测试用 `QTRY_VERIFY_WITH_TIMEOUT` 或 fake clock，见 06）。
7. 禁止 `wait(固定毫秒)` 兜底析构共享资源（见 04 第 5 节）。
8. 禁止教学代码进生产 exe（`SignalSlotDemo/DemoPage/onDemoTick` 正弦波演示）。

## 7. 单版本源（编码层面）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- 版本号只出现在 `CMakeLists.txt` 的 `project(DataScope VERSION x.y.z)` 一处。
- `main.cpp`/`simulator/main.cpp` 的 `setApplicationVersion` 一律读 `DATASCOPE_VERSION_STRING` 宏（由 `configure_file` 从 `version.h.in` 生成）。
- 代码里禁止出现手写版本字符串（V2 的 `"0.1.0"`/`"2.0.0"` 五处硬编码即反面教材）。
