# 04 — 线程规则（Threading Rules）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

> **文档性质**：V3 并发模型的强制规则。核心推翻"每设备一线程"，改为"固定 N 个 I/O 事件循环线程＋socket 多路复用"。
> **前提认知**：Qt 的 `QTcpSocket` 是事件驱动、非阻塞的（`readyRead` 立即返回，底层 `select/epoll/WSAPoll` 多路复用）。本场景数据量（20Hz×4 通道＝80 点/s）**不需要**并发 CPU，需要的是**清晰的多路复用与扇出**。

---

## 1. 线程拓扑（固定 N，不随设备数增长）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

| 线程 | 数量 | 职责 | 创建/销毁 |
|------|------|------|----------|
| 主线程（GUI） | 1 | UI 渲染、Composition Root 组装、用户交互 | 进程生命周期 |
| I/O 事件循环线程 | 固定 N（默认 1，可按 CPU 核数设 2~4 分片） | 承载**所有设备**的 socket，`readyRead` 驱动解析 | 进程启动创建，随进程存活 |
| 记录线程 | 1 | CSV 异步落盘（消费记录队列） | 启动采集时创建，停止时握手销毁 |
| （未来）解析工作线程池 | N:M | 仅当出现 CPU 密集解析（如 1kHz 振动×100 设备 FFT）才加 | 分析阶段再建，不现在写死 |

- **设备与 I/O 线程的归属由"分片器"决定**（如按 `deviceId` 哈希分配到固定线程），不是"一设备一线程"。
- **禁止"每设备一线程"**：上百设备＝上百线程（栈预留、TCB、EventDispatcher、notifier ×N 常驻开销），且把 V2 最脆弱的关停代码复制 N 份。

## 2. 跨线程通信：两套机制，二选一，不得混用

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

| 机制 | 适用 | 语义 | 成本 |
|------|------|------|------|
| **方案 A：Qt 信号槽（QueuedConnection）** | 默认（小规模，20Hz 主场景） | **拷贝**语义，`QVector` 隐式共享浅拷贝 | 引用计数原子操作＋一次 `QMetaCallEvent` 分配 |
| **方案 B：自研 SPSC 环形队列＋move-only 槽＋对象池** | 高频（>1000 批/s，如振动诊断） | **move** 语义，稳态零分配 | 失去 Qt 信号槽类型安全，自管槽归还生命周期 |

- **铁律**：不能既要求 `move` 又要求 `QueuedConnection`（二者语义互斥：QueuedConnection 是拷贝，move 只适用于自研队列）。
- 元类型注册（`Q_DECLARE_METATYPE`＋`qRegisterMetaType`）**集中在一个编译单元**（`metatype_registry.cpp`，属于 `dscope_domain` 或 `dscope_ui`，规格里写死归属，不留真空），moc 规范化名 == 注册名 == 全限定名，三者一致。

## 3. 数据流扇出：SPMC，不是 SPSC

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

架构图里有**三个消费者**（渲染/报警/记录），所以是 **SPMC（多生产者多消费者）**，不是 SPSC。落地方式：**扇出为每消费者独立 SPSC 队列**。

| 消费者 | 队列 | 丢帧策略 | 容量 |
|--------|------|---------|------|
| 渲染（MonitorPage） | 渲染队列 | **允许丢旧**（drop-oldest，保留最新值） | `dataRate × maxAllowedLatency` |
| 报警（AlarmEngine） | — | **不丢帧**（挂在丢帧之前的完整流，见下） | 不适用 |
| 记录（RecordFileAdapter） | 记录队列 | 允许丢旧＋**丢帧计数通知** | 同上公式 |

- **报警不经过 DataBus 队列**：在采集线程内、数据入队列**之前**同步评估（连续数据判趋势不能被丢帧打断）。
- 扇出的代价是 N 份 `QVector` 浅拷贝（隐式共享下便宜），换来每队列严格 SPSC、全程无锁。

## 4. 背压 = 丢弃式降级（drop），不是阻塞式反压（block）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

- **采集线程的 `push` 永远非阻塞**：队列满就丢弃＋计数，绝不等待。若阻塞等待，`readyRead` 不处理 → TCP 接收缓冲积压 → 对端工业设备内存溢出/死机（比丢帧更糟）。
- 丢帧必须**诚实通知**：`droppedFrames` 计数器＋`dataGapDetected` 信号，UI 在曲线上标缺口或显示"数据降级"，用户可区分"设备没发"还是"我丢了"。
- 容量是**显式参数**，不是拍脑袋：`capacity = dataRate × maxAllowedLatency`（例：80 点/s × 2s ＝ 160 点）。这是"允许的最大陈旧度"的产品决策。

## 5. 线程关停协议（五件套，缺一不可）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

1. **握手**：`stop()` 后等 Worker **主动回 `stopped()` 确认**信号，主线程收到确认才 `quit()+wait()`，不是 fire-and-forget。
2. **socket 用 `abort()`**：立即关闭、丢弃缓冲、不发优雅 FIN。禁用 `disconnectFromHost()`（半关闭下 `disconnected` 迟迟不来，`deleteLater` 迟迟不释放）。
3. **超时兜底**：连接超时挂 QTimer（`connectToHost` 无限等待必须定时器兜底）＋协议层"帧超时"（多久无帧判对端死亡，见 ADR-05）。
4. **关停期抑制信号**：关停期间抑制 `connected/disconnected/error` 信号，杜绝 V2 的"disconnected 双发→主动断开被误判意外断线→触发自动重连"。
5. **`wait()` 超时不析构共享资源**：超时后 `abort()`＋再 `wait()`，仍失败则泄漏该线程但记录日志告警（符合"超时兜底＋日志告警，不静默崩溃"）。

## 6. 共享数据清单（每份数据写清同步机制）

> ⚠️ **本文为早期草案（v1 之前），已被 `AUTHORITATIVE-SPEC-v1.md` 取代**：凡与 v1 冲突以 v1 为准；对齐落地设计见 `docs/11-工程设计说明.md`。

| 共享数据 | 写者 | 读者（数量） | 同步机制 |
|---------|------|------------|---------|
| 采集数据流 | I/O 线程 | 渲染(1)＋记录(1) | 扇出独立 SPSC 队列 |
| 报警评估结果 | I/O 线程 | UI(1) | 信号槽（低频事件） |
| 连接/错误状态 | I/O 线程 | UI＋分片器(多) | `std::atomic<bool>` 或状态机串行化 |
| 设备集合 | UI 线程 | I/O 线程遍历 | 锁，或 QObject 事件串行化 |
| 配置 | UI 线程 | I/O 线程读 | `shared_ptr<const T>` 不可变快照（无锁） |

> **点破 V2 假锁**：`dataservice.cpp` 的 `lastData()` 锁保护的是"同线程内的防御性访问"（写者/读者都在主线程），跨线程边界已由 QueuedConnection 保证，这把锁**多余**。V3 必须先写清"谁写谁读几个读者"，再决定锁/原子/无锁，禁止无脑加锁。
