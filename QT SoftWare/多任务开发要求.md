> **不要简单命令“开 10 个 Agent”。**

# 三十六、必须采用多任务 / 多 Agent 协同开发

由于本项目规模较大，而且我今晚无法持续参与交互，请不要让单个 Agent 从头到尾串行完成全部工作。

在当前 Coding Agent 能力允许的情况下，必须采用：

> **主 Agent + 多个专项 Agent / 子任务并行协作**

的方式推进项目。

---

## 1. 主 Agent：项目总负责人

指定一个主 Agent 作为：

> **Project Lead / Architect**

它负责：

* 总体架构
* 任务拆分
* 技术决策
* Git 管理
* 分支管理
* 子任务协调
* 代码集成
* 冲突解决
* 编译
* 集成测试
* 最终验收
* 文档汇总

其他 Agent 不得擅自改变总体架构。

所有重要架构变化必须由主 Agent 统一决定并记录。

# 3. 不要机械地创建 Agent

必须根据实际任务决定是否并行。

例如：

```text
P1
```

主要是：

```text
CMake
Qt
工程骨架
```

这种阶段不需要同时创建 10 个 Agent。

可以：

```text
主 Agent
   ↓
CMake/环境专项 Agent
   ↓
测试专项 Agent
```

即可。

而到了：

```text
P8～P14
```

模块之间相对独立时，可以明显增加并行度。

---

# 4. 并行开发必须避免互相覆盖

如果平台支持 Git：

推荐：

```text
master/main
      │
      ├── feature/ui
      ├── feature/model
      ├── feature/network
      ├── feature/protocol
      ├── feature/thread
      ├── feature/test
      └── feature/docs
```

各 Agent 在独立任务/分支中工作。

完成后：

```text
专项 Agent
    ↓
Commit
    ↓
主 Agent Review
    ↓
Merge
    ↓
Build
    ↓
Test
```

禁止多个 Agent 同时无规则修改同一个核心文件。

---

# 5. 主 Agent 必须进行代码 Review

专项 Agent 完成任务以后，主 Agent 不能直接相信结果。

必须检查：

```text
代码是否能编译
↓
架构是否符合规划
↓
Qt API是否正确
↓
线程是否安全
↓
生命周期是否正确
↓
错误处理是否完整
↓
测试是否存在
↓
文档是否对应
```

发现问题：

> 主 Agent 可以要求专项 Agent 修改。

---

# 三十七、AI 协作的最终原则

整个项目采用：

```text
                    主 Agent
                       │
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
      UI Agent       Core Agent     Network Agent
        ↓              ↓              ↓
      Model Agent    Thread Agent    Protocol Agent
        ↓              ↓              ↓
       Test Agent   Documentation   Deploy Agent
        └──────────────┼──────────────┘
                       ↓
                  主 Agent Review
                       ↓
                    Merge
                       ↓
                  Integration
                       ↓
                     Test
                       ↓
                    Release
```

目标不是：

> **“让更多 Agent 干活。”**

而是：

> **“让 AI 像一个真正的软件开发团队一样协作。”**

并且始终保持：

> **架构统一、接口统一、代码可集成、测试独立、文档跟随源码。**

---

### 还有一个我建议你特别加上的东西

让它**自己判断哪些任务可以并行，哪些必须串行**。

因为真正成熟的 Agent 协作不是：

> “10 个 Agent 一起开工。”

而是：

```text
有依赖 → 串行

无依赖 → 并行

代码冲突风险高 → 不并行

接口已经确定 → 可以并行

架构尚未确定 → 不并行
```

比如：

```text
P8 Model/View
      ↓
先定义 Device / Channel 数据模型
      ↓
确定接口
      ↓
       ┌──────────────┬──────────────┐
       ↓              ↓              ↓
    UI Agent       Test Agent    Documentation
       ↓              ↓              ↓
       └──────────────┴──────────────┘
                      ↓
                  主 Agent
                      ↓
                    Merge
```
