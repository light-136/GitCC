## 六、V2-执行③：模拟设备升级 + 测试体系补强（2026-08-15）

### 6.1 背景与目标

V2 审查结论：V1 的 Simulator 只是"发正弦波让曲线动"的过程式代码，无法注入任何异常，
主机健壮性没有可复现的验证手段 → 本阶段把模拟设备升级为**测试基础设施**，
并把测试体系从单测升级为 Unit / Simulator / Integration / Smoke 四层。

### 6.2 完成内容

| 块 | 内容 | 文件 |
|----|------|------|
| 异常注入器 | FaultInjector 纯逻辑字节变换（8 类异常：None/Sticky/Fragment/CrcError/IllegalFrame/Delay/Surge/Disconnect） | `src/simulator/faultinjector.*` |
| 模拟设备 | SimulatorDevice：5 运行模式（Normal/Alarm/Stress/Busy/Error）+ 异常注入 + 通道配置应答 + 多客户端隔离 | `src/simulator/simulatordevice.*` |

### 6.4 关键节点与踩坑

- **通道配置链路测试（两次失败修复）**：`readyRead` 连接时 peer 为空 / Qt 不对已缓冲数据重发
  `readyRead` → 改为连接建立后由伪设备**主动写应答帧**（协议允许设备上报）——异步网络测试的确定性关键；
- **Stress 模式合成配置**：`setMode(Stress)` 一次完成"10ms 高频 + Sticky 粘包"，杜绝两者不同步；
- **Surge 语义修正**：突变帧**重算 CRC**（帧合法、值超量程），否则报警引擎收不到超限值，"突变→报警"链路断裂；
- **DataScope 探活路径**：双进程联动必须用**绝对路径**启动（后台 `cd && ./simulator &` 会丢 cwd）。

### 6.5 验证结果

- 21/21 CTest 全绿；SMOKE 全 11 模式/异常组合探活通过；
- DataScope + simulator 双进程端到端联动正常（连接→配置上报→曲线/报警→日志流）；
- 12 维评分平均 ≈ 8.8（见 `docs/reviews/03-V2 执行③ 模拟设备与测试体系验证.md`）。
