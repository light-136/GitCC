# DataScope Studio 多 Agent 协作报告

> **范围**：P1~P15 全程的主 Agent（Project Lead）+ 专业 Agent 协作模式复盘
> **日期**：2026-08-14

---

## 一、协作组织模型

```
┌────────────────────────────────────────────────────┐
│              主 Agent（Project Lead）               │
│  角色：架构师 + 集成者 + 测试设计者 + 发布工程师      │
│  职责：阶段规划 / 共享文件(CMakeLists) / 架构决策     │
│        测试设计 / 集成验证 / 文档体系 / git 提交      │
├────────────────────────────────────────────────────┤
│        专业 Agent（按任务即时派发，并行执行）          │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐            │
│  │ UI 页面   │ │ 文档撰写  │ │ 契约文档  │            │
│  │ Agent     │ │ Agent(×N)│ │ Agent    │            │
│  └──────────┘ └──────────┘ └──────────┘            │
│      ▲            ▲           ▲                     │
│      └──── 接口契约先行，产出经编译+测试门槛 ────┘      │
└────────────────────────────────────────────────────┘
```

## 三、并行与串行调度规则

### 3.1 判定规则

- **接口已定义 → 可并行**：如 P5 阶段 5 个 UI 页面接口明确，UI Agent 并行开发。
- **有依赖 → 串行**：如协议引擎（P10）必须在 TcpClient（P11）之前；CMakeLists 是共享文件，由主 Agent 独占维护，Agent 只读不写。
- **测试独立**：测试 Agent 独立于开发 Agent 编写，防止"自己测自己"。

### 3.2 接口先行实例

MonitorPage 只暴露一个数据入口 `onDataUpdated(QVector<DataPoint>)`：

- P14 演示数据源接入它 → 真实链路（DataService）接入它 → P15 回放数据接入它
- UI Agent 开发 MonitorPage 时无需等待数据层完成，接口契约先行保障并行成立

## 四、集成纪律

1. **共享文件单写者**：`CMakeLists.txt`、`mainwindow.h/cpp`（集成中枢）仅主 Agent 修改。
2. **Agent 产出门槛**：页面/文档 Agent 的代码产出必须经「编译 + CTest 全绿」后合入。
3. **集成冻结**：P15 前进入冻结期，只做集成验证与文档，不引入新功能，保证交付稳定性。

## 六、经验与教训

### 有效做法

1. **接口契约先行**是并行开发能成立的根本前提。
2. **主 Agent 专注不可并行部分**（架构/网络/线程/集成），把可并行部分（UI/文档）外包，吞吐量显著提升。
3. **Agent 只读共享文件**避免了构建脚本冲突。

### 需要改进

1. **文档编号缺乏统一分配**：Agent 撰写时各自规划编号，曾出现《07》编号归属分歧。改进：主 Agent 在派发任务时**预先分配好文件编号与路径**。
2. **Agent 上下文隔离**：每个 Agent 需重新读源码，token 开销高于主 Agent 内联完成。改进：对高频复用的架构信息（帧格式、状态机）以契约文档形式沉淀，让新 Agent 快速对齐。
3. **后台 Agent 生命周期**：跨会话残留的后台 Agent（如 M1）需在收尾时明确归集，避免工作重叠。

---

## 七、结语

多 Agent 协作在本项目中的价值是**让"串行依赖"与"并行吞吐"并存**：依赖链（协议→网络→线程→UI）严格串行保正确性，无依赖面（UI 页面、文档、契约）充分并行保效率。配合接口契约与集成冻结，V1 实现"12/12 测试全绿 + 全套文档 + 免安装发布包"，V2 后扩至"21/21 测试全绿 + 分层测试体系 + 学习体系 + 免安装发布包"的完整交付。
