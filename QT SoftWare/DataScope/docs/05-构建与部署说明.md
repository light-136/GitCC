# DataScope Studio —— 构建与部署说明

> 适用版本：DataScope 0.1.0（主分支最新）
> 工具链：Qt 5.12.2 (mingw73_64) + MinGW-w64 7.3.0 + CMake 3.25 + Ninja
> 平台：Windows 11 / Windows 10（64 位）
> 文档编号：05；上一文档：《04-…》（按工程文档体系顺序编号）

本文档面向构建工程师与发布工程师，说明从源码到可交付运行包的完整流程：
环境准备 → 构建（Debug/Release）→ 测试 → 部署 → 排错。

---

## 1. 环境准备

| MinGW-w64 编译器 | 7.3.0 (posix-seh) | `D:\Qt\Tools\mingw730_64\bin` | `g++.exe` / `gcc.exe` / `ar.exe` 等 |

| 目标名 | 类型 | 依赖 | 说明 |
|--------|------|------|------|
| `datascope_utils` | 静态库 | Qt5::Core | 字节序 / 十六进制 / 时间工具 |
| `datascope_infra` | 静态库 | Qt5::Core | 日志 / 配置 |
| `datascope_domain` | 静态库 | Qt5::Core | 领域模型（纯数据） |
| `datascope_protocol` | 静态库 | Qt5::Core | 帧协议引擎 |
| `datascope_services` | 静态库 | Qt5::Core + Network + protocol + domain | 采集链路业务服务 |

每个可执行目标在构建完成后都会自动执行 `ds_deploy_qt` 把 Qt 运行库部署到
其输出目录（详见第 4 节）。

## 2. 构建步骤

### 2.1 通用约定（务必遵守）

1. **`CMAKE_CXX_COMPILER` 与 `CMAKE_PREFIX_PATH` 必须使用正斜杠**（`/`）传参。
   若写成反斜杠 `-DCMAKE_PREFIX_PATH=D:\Qt\...`，CMake 会把 `\Q` 之类的片段当作
   转义序列解析，导致路径损坏、`find_package(Qt5)` 找不到 Qt，产生形如
   `Could not find a package configuration file provided by "Qt5"` 的错误。
2. **禁止 `cd 目录 && cmake ...` 链式写法**。统一使用 CMake 的 `-S <源码目录> -B <构建目录>`
   参数对，命令与当前工作目录无关，逻辑清晰且不易写错。
3. Debug 与 Release **各用独立的构建目录**，互不干扰，避免切换配置触发全量重编。

### 2.2 Debug 构建（开发联调用）

```bat
:: 1) 配置：生成 Ninja 工程到 build_debug 目录
cmake -S D:/Gemi/QT\ SoftWare/DataScope -B D:/Gemi/QT\ SoftWare/DataScope/build_debug ^
    -G Ninja ^
    -DCMAKE_BUILD_TYPE=Debug ^
    -DCMAKE_C_COMPILER=D:/Qt/Tools/mingw730_64/bin/gcc.exe ^
    -DCMAKE_CXX_COMPILER=D:/Qt/Tools/mingw730_64/bin/g++.exe ^
    -DCMAKE_MAKE_PROGRAM=C:/Users/lenovo/AppData/Roaming/Python/Python310/Scripts/ninja.exe ^
    -DCMAKE_PREFIX_PATH=D:/Qt/5.12.2/mingw73_64

:: 2) 构建：编译 + 链接 + 自动 windeployqt
cmake --build D:/Gemi/QT\ SoftWare/DataScope/build_debug
```

> 若使用 PowerShell，去掉行尾 `^`（PowerShell 续行为反引号 `` ` ``，或用单行命令）。
> 路径含空格时，`-S/-B` 参数可用引号包裹，如
> `cmake -S "D:/Gemi/QT SoftWare/DataScope" -B "D:/Gemi/QT SoftWare/DataScope/build_debug" ...`。

### 2.3 Release 构建（交付发布用）

```bat
:: 1) 配置：独立构建目录 build_release
cmake -S D:/Gemi/QT\ SoftWare/DataScope -B D:/Gemi/QT\ SoftWare/DataScope/build_release ^
    -G Ninja ^
    -DCMAKE_BUILD_TYPE=Release ^
    -DCMAKE_C_COMPILER=D:/Qt/Tools/mingw730_64/bin/gcc.exe ^
    -DCMAKE_CXX_COMPILER=D:/Qt/Tools/mingw730_64/bin/g++.exe ^
    -DCMAKE_MAKE_PROGRAM=C:/Users/lenovo/AppData/Roaming/Python/Python310/Scripts/ninja.exe ^
    -DCMAKE_PREFIX_PATH=D:/Qt/5.12.2/mingw73_64

:: 2) 构建
cmake --build D:/Gemi/QT\ SoftWare/DataScope/build_release
```

要点说明：

- `-DCMAKE_BUILD_TYPE=Release` 会开启 `-O2` 优化并定义 `QT_NO_DEBUG_OUTPUT`，
  产物体积更小、运行更快，用于对外发布。
- Release 构建时 `windeployqt` 会自动部署**非 Debug**（无 `d` 后缀）的 Qt DLL，
  这正是发布包要用的版本。
- 构建成功后主程序位于 `build_release/DataScope.exe`。

### 2.4 增量构建 / 清理重建

- **增量构建**：重复执行 `cmake --build <构建目录>` 即可，Ninja 只重编改动过的源文件。
- **清理重建**：删除整个构建目录后重新执行 2.2 / 2.3 的两条命令。
  不要手工删散落的 `*.o`，Ninja 对缺失产物会自己处理。
- **切换 Qt 版本 / 编译器**：必须删除旧构建目录重新配置，避免缓存了旧路径。

## 3. 测试运行方法

### 3.1 全量运行（CTest）

```bat
:: 进入构建目录后执行（ctest 需要能找到测试程序与 Qt DLL，二者都在构建目录）
cmake -S D:/Gemi/QT\ SoftWare/DataScope -B D:/Gemi/QT\ SoftWare/DataScope/build_debug
cd D:/Gemi/QT\ SoftWare/DataScope/build_debug
ctest --output-on-failure
```

`enable_testing()` + 12 个 `add_test(NAME tst_xxx COMMAND tst_xxx)` 已把所有套件
注册进 CTest。`--output-on-failure` 让失败时直接打印测试日志，便于定位。

> 说明：`ctest` 需要工作目录位于构建目录（或 `-C` 指定），因为 12 个测试 exe
> 与 Qt DLL、`platforms/qwindowsd.dll` 都部署在构建目录根下。

### 3.2 单独运行某个套件

```bat
ctest -R tst_protocol --output-on-failure          :: 只跑协议套件
ctest -R "tst_tcpclient|tst_dataservice" --output-on-failure   :: 正则匹配多个套件
```

### 3.3 直接运行测试可执行文件（带详细信息）

```bat
D:/Gemi/QT\ SoftWare/DataScope/build_debug/tst_protocol.exe -v1        :: 每个用例一行
D:/Gemi/QT\ SoftWare/DataScope/build_debug/tst_protocol.exe -v2        :: 含详细输出
D:/Gemi/QT\ SoftWare/DataScope/build_debug/tst_protocol.exe halfPacket :: 只跑指定用例
```

> Qt Test 参数说明：`-v1` 打印每个测试函数名与结果；`-v2` 额外打印数据驱动行；
> 不带参数则只输出汇总。数据驱动测试支持 `tst_xxx 函数名:数据行名` 精确过滤。

## 4. 部署方法

### 4.1 windeployqt 原理

Qt 应用程序运行依赖两类文件：

1. **Qt 动态库**（`Qt5Core.dll`、`Qt5Gui.dll`、`Qt5Widgets.dll`、`Qt5Network.dll` 等）；
2. **Qt 平台插件**（`platforms/qwindows.dll`，负责对接 Windows 窗口系统）与可选
   **样式/图标/图片插件**（`styles/qwindowsvistastyle.dll`、`iconengines/qsvgicon.dll`、
   `imageformats/q*.dll`）。

`windeployqt` 扫描目标 exe 的导入表，自动拷贝其依赖的 Qt DLL、插件与运行库
（`libgcc_s_seh-1.dll`、`libstdc++-6.dll`、`libwinpthread-1.dll`），使 exe 在
无 Qt 环境的机器上也能运行。

### 4.2 ds_deploy_qt 函数原理

`CMakeLists.txt` 中定义了部署函数：

```cmake
function(ds_deploy_qt TARGET_NAME)
    if(WIN32)
        find_program(QT_WINDEPLOYQT windeployqt HINTS "${CMAKE_PREFIX_PATH}/bin")
        if(QT_WINDEPLOYQT)
            add_custom_command(TARGET ${TARGET_NAME} POST_BUILD
                COMMAND "${QT_WINDEPLOYQT}" --dir "$<TARGET_FILE_DIR:${TARGET_NAME}>" "$<TARGET_FILE:${TARGET_NAME}>"
                COMMENT "windeployqt: 部署 ${TARGET_NAME} 的 Qt 运行库"
                VERBATIM)
        endif()
    endif()
endfunction()
```

工作流程：

- 在 `find_package(Qt5 ...)` 之后，`CMAKE_PREFIX_PATH` 指向 Qt 安装目录，
  `find_program` 据此在 `${CMAKE_PREFIX_PATH}/bin` 找到 `windeployqt.exe`；
- 为**每个可执行目标**挂一个 `POST_BUILD` 自定义命令：exe 链接完成后立即执行
  `windeployqt --dir <exe 所在目录> <exe 路径>`；
- `$<TARGET_FILE_DIR:...>` / `$<TARGET_FILE:...>` 是 CMake 生成器表达式，
  自动展开为目标输出目录与完整路径，因此主程序、simulator、12 个测试 exe 都会
  自动完成部署，无需手工逐个运行 windeployqt。

### 4.3 发布包结构

发布一个构建目录（Release）到目标机器即可交付。以 `build_release/` 为例：

> 本工程同时提供 `deploy/` 目录作为**精编正式发布包**：由 `windeployqt --release` 手动部署生成，
> 已实测可独立运行（双进程连接验证通过），并随包携带《07-使用说明》《09-最终报告》《README 文档索引》，
> 可直接整体拷贝分发。两者均包含下列结构：

```
build_release/
├── DataScope.exe              # 主程序（GUI）
├── simulator.exe              # 模拟设备（可选随包）
├── Qt5Core.dll                # Qt 核心库
├── Qt5Gui.dll                 # Qt GUI 库
├── Qt5Widgets.dll             # Qt Widgets 库
├── Qt5Network.dll             # Qt 网络库（TCP 采集链路）
├── Qt5Svg.dll                 # SVG 图标支持
├── libgcc_s_seh-1.dll         # MinGW 运行时（C/C++ 运行库）
├── libstdc++-6.dll
├── libwinpthread-1.dll
├── libEGL.dll  libGLESv2.dll  opengl32sw.dll   # OpenGL/ANGLE 软渲染
├── platforms/
│   └── qwindows.dll           # Windows 平台插件（缺失则程序无法启动）
├── styles/
│   └── qwindowsvistastyle.dll # Windows Vista 风格插件
├── iconengines/
│   └── qsvgicon.dll           # SVG 图标引擎
├── imageformats/              # 图片格式插件（gif/ico/jpeg/svg/tiff...）
├── bearer/                    # 网络承载插件（仅用到 TCP 时可精简）
├── translations/              # Qt 自带翻译（可精简）
└── resources/
    └── main.qss               # 应用样式表（由 resources.qrc 编译进 exe，可随包保留源码样式）
```

> 说明：本工程的 `main.qss` 通过 `resources.qrc` + AUTORCC 编译进 exe，
> 运行时无需外部样式文件；`translations/`、`bearer/`、`imageformats/` 按需精简。
> Debug 目录中同名插件带 `d` 后缀（如 `qwindowsd.dll`），Release 目录则不带。

### 4.4 最小运行包检查清单

分发前在**干净机器**上验证：

1. 双击 `DataScope.exe` 能弹出主窗口；
2. 删除 `platforms/` 目录后应报“无法定位程序输入点 / 应用程序无法启动”，
   证明平台插件是必需的（验证后还原）；
3. 关闭程序后无残留进程，日志/配置文件按设计写入用户目录或临时目录。

## 5. 常见问题与排错

### 5.1 运行时报“找不到 Qt5Widgets.dll” / 错误码 0xc000007b

- **现象**：双击 exe 提示缺少 DLL，或弹“0xc000007b 应用程序无法正常启动”。
- **原因**：exe 目录缺少对应 Qt DLL，或部署了 Debug/Release 版本混搭、位数不匹配
  （32 位 DLL 配 64 位 exe）。
- **解决**：
  1. 确认构建时 `ds_deploy_qt` 已执行（查看构建日志的 `windeployqt:` 行）；
  2. 若没执行，手动运行一次：
     `D:/Qt/5.12.2/mingw73_64/bin/windeployqt.exe D:/path/to/DataScope.exe`；
  3. 用 `Dependency Walker` 或 `dumpbin /dependents` 检查缺失项；
  4. 确认 exe 与 DLL 都是 64 位（本工具链为 x86_64）。

### 5.2 DLL 被进程锁定，导致删除/重建失败

- **现象**：`cmake --build` 时报 `Permission denied`，或无法删除
  `build/DataScope.exe` / `Qt5Cored.dll`。
- **原因**：上一轮运行的程序或测试进程尚未退出，Windows 锁定了文件。
- **解决**：
  1. 关闭所有 DataScope / simulator / tst_*.exe 窗口；
  2. 在任务管理器中结束残留进程；或执行
     `taskkill /F /IM DataScope.exe`（simulator 同理）；
  3. 重新构建。若仍锁定，检查是否有资源管理器预览窗口占用目录。

### 5.3 端口被占用，simulator 启动失败

- **现象**：`simulator` 启动后输出
  `模拟设备已启动，监听 0.0.0.0:40001`（正常）或
  启动即退出、报 `Unable to bind` / “地址已在使用”。
- **原因**：默认端口 `40001` 被其他程序占用（或上次 simulator 未退出）。
- **解决**：
  1. 换端口：`simulator.exe --port 50001`（支持 `-p` 短参数）；
  2. 或在 DataScope 主程序设置页把采集地址改为新端口；
  3. 定位占用者：`netstat -ano | findstr 40001`，用 PID 结束进程。

### 5.4 CMake 配置阶段报 Qt5 找不到（路径反斜杠转义坑）

- **现象**：`Could not find a package configuration file provided by "Qt5"`。
- **原因**：`-DCMAKE_PREFIX_PATH=D:\Qt\5.12.2\mingw73_64` 中的反斜杠被 CMake
  当作转义符，路径实际变成非法值。
- **解决**：一律使用正斜杠
  `-DCMAKE_PREFIX_PATH=D:/Qt/5.12.2/mingw73_64`，
  编译器路径同理（`D:/Qt/Tools/mingw730_64/bin/g++.exe`）。
  修改后务必删除构建目录重新配置。

### 5.5 CTest 报“找不到测试程序” / 测试 exe 无法运行

- **现象**：`ctest` 报 `Test not found`，或测试进程闪退。
- **原因**：
  1. `ctest` 工作目录不在构建目录（测试 exe 与 Qt DLL 在构建目录内）；
  2. 构建目录缺 `platforms/qwindowsd.dll` 等插件（`ds_deploy_qt` 未生效）。
- **解决**：在构建目录内执行 ctest；确认构建日志包含 windeployqt 输出；
  必要时在构建目录手动运行 `windeployqt` 补齐。

### 5.6 编译器版本不匹配导致链接错误

- **现象**：链接时大量 `undefined reference to ...`，或 C++ 库 ABI 告警。
- **原因**：`CMAKE_CXX_COMPILER` 指向了与 Qt 不配套的 MinGW。
- **解决**：本工程必须使用 `D:/Qt/Tools/mingw730_64/bin` 下的
  `g++.exe`/`gcc.exe`（与 `D:/Qt/5.12.2/mingw73_64` 配套），不要混用 MSVC 或其他 MinGW。

### 5.7 Debug 与 Release DLL 混装

- **现象**：Debug 程序启动时报版本不匹配，或 Release 程序报缺少带 `d` 的 DLL。
- **原因**：把 `build/`（Debug）与 `build_release/`（Release）目录文件互相拷贝。
- **解决**：Debug 包用 `Qt5Cored.dll`/`qwindowsd.dll`；Release 包用
  `Qt5Core.dll`/`qwindows.dll`。发布只取 Release 目录，且勿混用。
