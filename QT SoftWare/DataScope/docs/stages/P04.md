# P04 阶段学习文档 —— 元对象系统与 Signal/Slot

> 提交：`2f90b07`（P3~P7 合并提交）｜ 里程碑：`tst_signalslotdemo` 单测全绿

## 1. 阶段目标

实现 SignalSlotDemo 教学对象，系统掌握 Qt 元对象系统三件套（QObject + Q_OBJECT + moc）与**信号槽五种连接写法**，并用 QTimer + 事件循环实证"事件驱动"模型。

## 2. 关键技术点（WPF 迁移锚点）

- **QObject ≈ DependencyObject**：对象身份、父子树、事件/信号能力来源。
- **信号槽 connect ≈ C# `event += handler`**：但 Qt 有五种写法（成员函数指针 / lambda / 信号→信号转发 / disconnect / deleteLater），是 C# 转 Qt 最大的心智跃迁点。
- **moc ≈ 反射**：C# 反射在运行时读程序集元数据；Qt 的 moc 在**编译期**生成静态 QMetaObject。
- **对象树（parent 析构自动 delete child）**：WPF 逻辑树只描述层级、不负责内存；QObject 对象树是**内存所有权**。
- **QTimer + 事件循环 ≈ DispatcherTimer**：没有事件循环，`start()` 什么也不会发生。

## 3. 实现内容

- `src/app/signalslotdemo.h/.cpp`：纯 QObject 演示类（不依赖 UI），5 个私有演示函数分别对应五种连接写法，`runAllDemos()` 依次执行；`startClock()` 把 QTimer::timeout 翻译成业务信号 `timeTicked`。
- `src/ui/mainwindow.cpp`：主窗口"布线"——按钮→runAllDemos、timeTicked→QLabel；状态栏时钟每秒跳动。
- `tests/unittests/tst_signalslotdemo.cpp`：4 个测试函数，用 `QSignalSpy` 断言信号次数与参数，`QTest::qWait(1200)` 实证 QTimer 依赖事件循环。

## 4. 测试与验证

`tst_signalslotdemo` 全绿。关键验证：`clock_emitsAfterEventLoop` 等待 1.2s 收到 timeTicked，证明"只 start() 不够，必须有事件循环"。

## 5. 遇到的难点与解决

- **字符串内嵌 ASCII 双引号报 "stray character"**：`"【方式5】安全的"延迟删除"机制"` 内层 `"` 把字符串提前切断。解法：改中文引号「」或转义 `\"`。
- **lambda 捕获 `this` 却漏传 context 参数**：漏第三个参数时编译能过但接收者析构后连接仍在，触发即悬垂调用。解法：lambda 作槽**必须**把 `this` 作为 context 传入，Qt 才能在析构时自动断连。
- **"信号触发两次"的 90% 原因是重复 connect**：`runAllDemos` 开头 `disconnect(this, nullptr, this, nullptr)` 清场，保证演示可重复执行。

## 6. 阶段成果小结

信号槽是 Qt 对象间通信的唯一官方通道，也是跨线程安全投递（QueuedConnection）的基础——P6 的 `messageLogged`、P12 的线程 Worker 全部建立在它之上。核心认知：`Q_OBJECT` 漏写通常不报编译错，而是"运行时行为诡异"。
