# P06 阶段学习文档 —— 日志系统（LogManager）

> 提交：`2f90b07`（P3~P7 合并提交）｜ 里程碑：`datascope_infra` 库 + `tst_logmanager` 单测全绿

## 1. 阶段目标

自建全局日志系统 LogManager，实现分级日志、按天命名、UTF-8 落盘、线程安全写盘、UI 实时订阅（信号广播）。Qt 没有官方日志库（`qDebug()` 只打控制台），必须用 Qt 方式重建 WPF 里 NLog/Trace 的能力。

## 2. 关键技术点（WPF 迁移锚点）

- **Meyer's Singleton** ≈ `Lazy<T>`：`static LogManager &instance()` 函数内 static 局部变量，C++11 起首次初始化线程安全。
- **QMutex + QMutexLocker（RAII 加锁）** ≈ `lock` 语句：但 Qt 的 QMutex **默认不可重入**（同线程重锁死锁），C# Monitor 可重入——"锁里再调锁"在 Qt 里是死锁。
- **`messageLogged` 信号** ≈ `Trace.Listeners` 事件订阅：UI 实时订阅日志流。
- **QStandardPaths::writableLocation(AppDataLocation)** ≈ `Environment.GetFolderPath(ApplicationData)`。

## 3. 实现内容

- `src/infrastructure/logmanager.h`：`LogManager` 接口 + `enum class LogLevel`（Trace~Fatal）+ `Q_DECLARE_METATYPE`。
- `src/infrastructure/logmanager.cpp`：单例、`init()`、`log()` 写盘（QMutexLocker 保护"格式化+写入+flush"区间）、`info/warn/error` 便捷方法、`qRegisterMetaType<LogLevel>("LogLevel")`。
- `CMakeLists.txt`：新增 `datascope_infra` 静态库 + `tst_logmanager` target。
- `main.cpp`：启动即 `LogManager::instance().init()`，写启动日志。

## 4. 测试与验证

`tst_logmanager` 5 个测试函数全绿：`QTemporaryDir` 隔离（用例间重新 init 到全新临时目录，杜绝污染真实 AppData）+ `QSignalSpy` 验证 `messageLogged` 参数与次数。

## 5. 遇到的难点与解决

- **`QTextStream::setCodec` 写成静态调用编译失败**：`setCodec` 是成员函数，必须 `stream.setCodec("UTF-8")` 在实例上调用。
- **QSignalSpy 无法处理自定义枚举参数 LogLevel**：`Q_DECLARE_METATYPE` 注册的是带命名空间名 `datascope::infrastructure::LogLevel`，而 moc 生成的参数类型名是不带命名空间的 `LogLevel`，两者不一致。解法：构造函数里 `qRegisterMetaType<LogLevel>("LogLevel")` 显式注册别名。
- **多线程写日志不加锁会撕开整行**：`QFile::write` 非原子，必须一把 QMutex 保护整行区间。
- **设计红线**：日志失败永不抛异常、永不中断业务——"日志炸了不能把程序炸了"。

## 6. 阶段成果小结

全局日志地基落定。核心领悟：**C# 的日志靠框架开箱即用，Qt 必须自己写；而自己写日志时最大的敌人不是"怎么写进文件"，而是"什么时候、被谁并发地写"**——QFile 非线程安全，这把并发安全从框架的隐性责任变成你的显式责任。
