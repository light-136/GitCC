# P12 阶段学习文档 —— 多线程采集链路与数据总线

> 提交：`a0510e4` + `b778ed1`（P12 UI 集成段）｜ 里程碑：`DataService` 数据总线 + `tst_dataservice` 全绿（10/10 套件）

## 1. 阶段目标

把 TCP 采集挪进独立线程，实现 `AcquisitionWorker`（采集线程 Worker）+ `DataService`（数据总线），并把真实链路接入主窗口替换演示数据源。工业采集是 50ms/帧的高频 I/O，绝不能阻塞 UI 线程。

## 2. 关键技术点（WPF 迁移锚点）

- **QThread + moveToThread ≈ `Task`/`async-await` + 后台线程**：UI 线程不做网络 I/O；工作对象迁到采集线程，跨线程通信用信号槽（QueuedConnection ≈ WPF 跨线程 Dispatcher 排队）。
- **DataService 数据总线 ≈ ViewModel + 数据总线**：主线程门面对象，UI 只认它（连接/采集/订阅数据/取快照），不感知线程。
- **`QMetaObject::invokeMethod(worker,"start",Qt::QueuedConnection,Q_ARG(...))`**：把"请求"作为消息投递到采集线程——跨线程函数调用的 Qt 标准姿势。
- **数据源可替换设计**：MonitorPage 只认 `onDataUpdated(QVector<DataPoint>)` 一个入口，P14 演示源 → P12 真实链路无缝切换，UI 零改动。

## 3. 实现内容

- `src/services/acquisitionworker.h/.cpp`：Worker 在 `start()` 槽内 new TcpClient（parent=this，**QTcpSocket 必须在所属线程内创建**），收帧→转 DataPoint→emit `pointsReady`。
- `src/services/dataservice.h/.cpp`：持有 QThread + Worker；`connectTo`/`startAcquisition`/`stopAcquisition`、`dataUpdated` 信号、`lastData()` 快照（QMutex 保护）；析构时停 Worker→quit→wait(3000)。
- `src/ui/mainwindow.cpp`：P12 集成段——创建 DataService，dataUpdated→MonitorPage，工具栏三动作接线，启动后自动 `connectDevice()` 连 127.0.0.1:40001。
- `tests/unittests/tst_dataservice.cpp`：4 测试函数（连接/采集/停止/断开全链路）。

## 4. 测试与验证

`tst_dataservice` 全绿，CTest 升到 **10/10**。端到端冒烟：simulator + DataScope 双进程连通，TCP ESTABLISHED，数据帧流入 UI 曲线。

## 5. 遇到的难点与解决

- **跨线程 `QVector<DataPoint>` 参数丢失（警告 "Cannot queue arguments"）**：moc 对模板参数里的相对名规范化为不带命名空间前缀的 `QVector<domain::DataPoint>`，与 `qRegisterMetaType` 注册的全限定名不一致。解法：**信号参数用全限定名** `QVector<datascope::domain::DataPoint>`，保证 moc 规范化名 == 注册名 == Q_DECLARE_METATYPE 名。
- **`onConnectedChanged(bool connected)` 参数遮蔽信号**：参数叫 `connected` 会遮蔽同名信号 `connected()`，导致 `emit connected()` 被解析成"把参数当函数调用"而编译失败。解法：参数改名 `nowConnected`。
- **连接失败后 Worker 残留 m_client**：`start()` 里 `if (m_client) return` 会吞掉重连请求。解法（P13 前置）：错误时 `deleteLater` 销毁客户端，使下次 start 能重建。
- **QThread 生命周期**：析构必须先停 Worker（队列投递 stop）→ quit → wait(3000)，否则"线程在清理中途销毁"是崩溃温床。
- **QSignalSpy 辅助函数返回冲突**：QVERIFY 展开为无值 return，与返回 quint16 的辅助函数冲突。解法：if+return 0，调用点加断言。

## 6. 阶段成果小结

真实采集链路接入主窗口，UI 与传输彻底解耦。核心领悟：**跨线程信号槽的 QueuedConnection 是参数拷贝进队列，自定义容器类型必须三处命名一致**（声明名/注册名/moc 规范化名）——这是 Qt 多线程编程最隐蔽也最高发的坑。
