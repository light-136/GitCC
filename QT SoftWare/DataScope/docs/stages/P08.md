# P08 阶段学习文档 —— Domain 领域模型

> 提交：`5b68130`（P8/P10/P14 合并提交）｜ 里程碑：`datascope_domain` 库 + `tst_domain` 单测全绿（6/6 套件）

## 1. 阶段目标

建立领域模型层（Device/Channel/DataPoint/DeviceStatus），作为"设备是什么"的唯一定义。契约先行（《02-领域模型接口契约.md》先定死接口），M1 专项 Agent 照契约实现、T3 照契约验证——这是"接口已定→可并行"的协作模式样板。

## 2. 关键技术点（WPF 迁移锚点）

- **struct vs class**：`Channel`/`DataPoint` 用 `struct`（值类型 ≈ C# `record`/POCO）；`Device` 用 `class`（拥有并管理一组 Channel，暴露只读视图与写入入口）。
- **`enum class DeviceStatus`** ≈ C# `enum`：但强类型不隐式转 int，编译器挡住"脏数据"。
- **`const QVector<Channel>& channels() const`** ≈ `IReadOnlyList<T>`：只读引用返回，零拷贝 + 只读安全。
- **QVector/QString 隐式共享（CoW）**：拷贝 Device 非常便宜（引用计数 +1），写入才 detach——这是 P12 采集线程跨线程投递数据的前提。

## 3. 实现内容

- `src/domain/models.h/.cpp`：`Device`（id/name/status、`channels()` 只读视图、`setChannel`/`clearChannels`）、`Channel`（index/scale/offset/unit）、`DataPoint`（timestamp/channelIndex/value）、`enum class DeviceStatus`（Disconnected/Connecting/Connected/Error）。类内成员初始化保证"构造即合法状态"，`Device() = default`。
- `tests/unittests/tst_domain.cpp`：7 个测试函数 / 9 断言组，覆盖契约 6 个强制项 + Device 拷贝独立性。
- `CMakeLists.txt`：新增 `datascope_domain` 静态库（只依赖 QtCore）。

## 4. 测试与验证

`tst_domain` 全绿，CTest 升到 6/6 套件。`device_copyIndependent` 专门验证隐式共享：`Device copy = original;` 后两对象底层 QVector 何时真正分开（写时复制 detach 触发点）。

## 5. 遇到的难点与解决

- **枚举与整数混用（C# 习惯延续）**：`if (dev.status() == 2)` 在 C# 合法、C++ `enum class` 编译不过。解法：一律 `DeviceStatus::Connected`，需要数值用显式 `static_cast`。
- **返回 QVector 值类型（每次调用深拷贝）**：采集线程高频调用白白浪费带宽。解法：读接口返回 `const&` 只读视图。
- **忘记 `= default` 导致"没有默认构造"**：声明任何构造函数后默认构造不再自动生成。解法：显式 `Device() = default;` 把"默认构造存在"写进契约。

## 6. 阶段成果小结

领域层只依赖 QtCore，UI/网络/串口一概不碰，保持可测试、可复用。核心领悟：**C# 的"值语义"靠 record/struct 显式声明，Qt 的"值语义"是容器默认行为（隐式共享）**——拷贝便宜到近乎免费，但"改了副本不碰原对象"必须靠理解 CoW 才能写对。
