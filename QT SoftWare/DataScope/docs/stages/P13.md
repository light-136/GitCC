# P13 阶段学习文档 —— 设备状态机与错误处理

> 提交：`b778ed1`（P12 UI 集成 + P13）｜ 里程碑：`DeviceController` 状态机 + 退避自动重连 + `tst_devicecontroller` 全绿（11/11 套件）

## 1. 阶段目标

实现 `DeviceController` 设备状态机（Disconnected/Connecting/Connected/Error），带指数退避自动重连，并区分主动断开与意外断开。工业现场设备随时可能掉线（断电/网线松动/复位），"能自动恢复"是可靠性的分水岭。契约《07-设备状态机契约.md》先行定稿。

## 2. 关键技术点（WPF 迁移锚点）

- **显式状态机建模 ≈ 状态模式/状态枚举**：设备连接是典型状态机，用一个枚举 + 转移函数显式管理，比散落的 bool 标志（isConnected + isAcquiring...）可靠得多。
- **状态转移的四类驱动**：用户操作（connect/disconnect）、外部事件（TCP connected/error/disconnected）、定时器（重连）、幂等保护（`setStatus` 里 `if (m_status == s) return`，状态不变不发信号）。
- **主动断开 vs 意外断线的语义判别**：DataService 的 `disconnected` 两种情况下都触发，控制器用 `m_userDisconnected` 标志区分——主动断开安静退出，意外断线进 Error 并自动重连。
- **指数退避 `min(1s << n, 30s)`** ≈ `Math.Min` 位运算实现：1s→2s→4s→…→30s 封顶，防止重连风暴。

## 3. 实现内容

- `src/services/devicecontroller.h/.cpp`：状态查询（`status()`）、驱动操作（`connect()`/`disconnect()`）、信号 `statusChanged(DeviceStatus)`/`errorOccurred(QString)`；QTimer 单次触发重连（`setSingleShot(true)`，每次超时由槽决定是否再起）。
- `src/services/acquisitionworker.cpp`：错误处理修复——连接失败 `deleteLater` 销毁 m_client 并置空，使重连可重建。
- `tests/unittests/tst_devicecontroller.cpp`：6 测试函数 / 8 断言，覆盖契约 6 个强制项（含 Connecting 中间态可观察、伪设备先拒后收→退避重试最终 Connected）。

## 4. 测试与验证

`tst_devicecontroller` 全绿，CTest 升到 **11/11**。关键验证：状态转移全部 QSignalSpy/QTRY 断言；自动重连用"伪设备先拒后收"模拟现场掉线恢复。

## 5. 遇到的难点与解决

- **QSignalSpy 无法处理 enum class 参数（警告 "Unable to handle parameter"）**：`statusChanged(DeviceStatus)` 参数取不出 → `toInt()` 得 0 → 断言失败。解法：`Q_DECLARE_METATYPE(DeviceStatus)` + initTestCase 注册裸名/相对名/全限定名三种别名。
- **连接失败到 Error 超过 3s（实测最快 ~3.3s）**：Windows 对"刚释放的 LISTEN 端口"约 2s 才回 RST，叠加线程投递。解法：等待放宽到 6s（与 tst_tcpclient 的 5s 同源教训）。
- **worker 残留 m_client 吞重连**（P12 遗留缺陷）：错误时不销毁客户端，`start()` 的 `if (m_client) return` 让重连永远发不出去。解法：errorOccurred 时 deleteLater + 置空，P13 重连测试验证生效。
- **QTimer::setSingleShot 避免空转**：重连定时器单次触发，避免周期定时器在 Error 态反复空转。

## 6. 阶段成果小结

设备链路具备"掉线自动恢复"能力。核心领悟：**状态机让"连接"这个复杂时序变得可测试、可推理**；"自动断连/自动重连"都不是免费的，前提是正确登记接收者生命周期（context 对象）与 Worker 资源（错误时销毁重建）——这两点共同决定重连能否真正生效。
