# P03 阶段学习文档 —— Qt 核心类型与隐式共享（TimeUtils 工具库）

> 提交：`2f90b07`（P3~P7 合并提交）｜ 里程碑：`tst_timeutils` 单测全绿

## 1. 阶段目标

在 P2 基础上实现 TimeUtils 工具库，系统掌握 Qt 核心值类型（QString/QDateTime/QTime）与**隐式共享（写时复制）**机制，练熟时间格式化/解析/间隔换算——这是 P6 日志时间戳、P8 数据打点、P12 耗时统计的共同地基。

## 2. 关键技术点（WPF 迁移锚点）

- **QDateTime/QTime/QString** ≈ C# `DateTime`/`TimeSpan`/`string`：都是值类型，直接赋值即复制语义。
- **隐式共享（Copy-on-Write）**：`QString` 赋值是 O(1) 浅拷贝 + 引用计数，真正修改才深拷贝——这是"Qt 代码敢到处按值传 QString"的原因。
- **`QString::arg(value, 2, 10, '0')` 补零** ≈ `value.ToString("D2")`。
- **TryParse 风格**：`bool parseTime(const QString &text, QTime &out)`，失败时**绝不修改 out** ≈ `DateTime.TryParse`。
- **`QRegularExpression` 校验自由文本形状**：`nowString()` 无法断言固定值，改用正则校验格式。

## 3. 实现内容

- `src/utils/timeutils.h/.cpp`：`formatDateTime`/`nowString`/`fileTimestamp`（`yyyyMMdd_HHmmss` 无分隔符文件名）、`parseTime`（先试 `HH:mm:ss` 再试带毫秒格式）、`formatDuration`、`elapsedMicros`。格式串集中在匿名命名空间常量。
- `tests/unittests/tst_timeutils.cpp`：8 个测试函数，其中 `parseTime` 数据驱动 4 组、`formatDuration` 数据驱动 5 组。
- 复用 `datascope_utils` 静态库（P2 基建不重造）。

## 5. 遇到的难点与解决

- **文件被误写到 `D:\Gemi\QT Soft Ware\`（多一个空格）**：专项 Agent 凭记忆拼路径，真实目录是 `QT SoftWare`（无空格）。解法：主 Agent 评审时发现文件不在工程树内，复制归位到 `src/utils/`。教训：**写文件前先验证目标目录存在**。

## 6. 阶段成果小结

掌握 Qt 值类型与隐式共享：`QString a = b;` 先共享底层数据、被修改才深拷贝。确立传参铁律：默认按 const 引用收、解析类统一 TryParse 风格、拼接优先 `arg()`。此习惯延续到 P6/P7 所有基础设施接口。
