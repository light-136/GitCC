# P11 阶段学习文档 —— TCP 客户端与模拟设备

> 提交：`a0510e4`（P11/P12 合并提交）｜ 里程碑：`TcpClient` + `simulator` + `tst_tcpclient` 全绿

## 1. 阶段目标

实现 TCP 采集链路两端：`TcpClient` 服务类封装 QTcpSocket（连接/发送/收帧/错误），`simulator` 独立可执行程序模拟采集设备（TCP 服务端 + 正弦波数据帧），并用回环测试验证半包/粘包/连接失败等边界。

## 2. 关键技术点（WPF 迁移锚点）

- **QTcpSocket ≈ .NET `Socket`/`NetworkStream`**：连接/可读/错误/断开全是信号（connected/readyRead/error/disconnected）——事件驱动，Qt 没有同步阻塞网络 API（`waitFor*` 绝不用于生产）。
- **`QOverload<QAbstractSocket::SocketError>::of(&QAbstractSocket::error)`**：Qt 5.12 只有 `error(...)` 信号（5.15 才有 `errorOccurred`），它与"错误码查询方法 error()"同名重载，必须用 QOverload 精确指定带 SocketError 参数的那一个——**Qt 重载信号的标准姿势**。
- **半包/粘包复用 P10 FrameParser**：`readyRead` 表示"有数据可读"不保证一帧；`readAll()` 读走全部字节喂解析器。
- **每客户端独立解析器**：simulator 里每个连接独立 FrameParser，多客户端字节流互不污染。

## 3. 实现内容

- `src/services/tcpclient.h/.cpp`：封装 QTcpSocket，暴露 `connectTo(host,port)`/`sendFrame`/信号 `connected/errorOccurred/frameReceived`；读到字节喂 FrameParser，取出帧 emit。
- `src/simulator/main.cpp`：QTcpServer 监听 0.0.0.0:40001，每 50ms 发 4 通道正弦帧，回发 `func|0x80`；独立可执行程序。
- `tests/unittests/tst_tcpclient.cpp`：4 测试函数（回环 / 连接拒绝 / 半包 / 粘包）。
- `CMakeLists.txt`：`datascope_services` 库雏形 + `simulator` target + `tst_tcpclient` target（链接 Qt5::Network + datascope_protocol）。

## 4. 测试与验证

`tst_tcpclient` 全绿，CTest 全套件无回归（9/9）。验证方法：本地回环建立真实 TCP 连接，用 QTcpServer 当伪设备喂半包/粘包字节流。

## 5. 遇到的难点与解决

- **`waitForNewConnection` 随机竞态失败**：它是同步阻塞 API，等待 `newConnection` 信号；而该信号可能已被前面 `QSignalSpy::wait()` 的事件循环"消费"（Qt 信号一次性，发出时无接收者即丢弃）。解法：改用**事件驱动**——`connect(newConnection, lambda)` + `QTRY_VERIFY_WITH_TIMEOUT`。
- **"连接失败"测试的端口陷阱**：相邻端口法（probe+1）撞上系统活跃监听端口→连接"成功"→error 永不触发；且 Windows 对刚释放的 LISTEN 端口有约 2s 拒绝延迟。解法：回归"验证空闲"法（listen 成功=此刻空闲→释放→立即连接），等待放宽到 5s。
- **`Qt::hex`/`Qt::dec` 不存在**：QDebug 的流操作符是 `hex`/`dec`（无 Qt:: 前缀）。
- **QSignalSpy 处理自定义类型 ProtocolFrame**：initTestCase 里 `qRegisterMetaType`，且 moc 规范化名可能记成裸名/相对名/全限定名三种，全部登记为别名。

## 6. 阶段成果小结

采集链路的"通道"打通，主程序可连模拟设备收真实格式帧。核心领悟：**信号槽的 AutoConnection 是跨线程安全投递的基础**；网络字节流的随机切分必须靠"事件驱动 + 有状态解析器"消化，这是与 C# `NetworkStream.Read` 阻塞模型最大的心智差异。
