# P14 阶段学习文档 —— 实时监控 + 自绘控件

> 提交：`5b68130`（P8/P10/P14）+ `6afcf5e`（P14 监控页集成）｜ 里程碑：三个自绘控件 + `tst_widgets` 全绿（8/8 套件）

## 1. 阶段目标

用 QWidget 自绘实现工业监控三件套：`LineChartWidget`（实时滚动曲线）、`GaugeWidget`（仪表盘）、`LedIndicator`（LED 指示灯），并集成到 MonitorPage 形成 4 通道实时监控总览。

## 2. 关键技术点（WPF 迁移锚点）

- **`paintEvent(QPaintEvent*)` ≈ 重写 `OnRender(DrawingContext)`**：继承 QWidget → 重写 paintEvent → 数据改动后调 `update()` 请求重绘。
- **QPainter ≈ DrawingContext**：`drawLine/drawRect/drawArc/drawText/drawPath/setPen/setBrush`，但更接近 GDI+。
- **`update()` ≈ `InvalidateVisual()`**：异步合并——连续调 10 次只在回到事件循环时合并成一次重绘，这是滚动曲线高效刷新的原因。
- **`sizeHint/minimumSizeHint` ≈ Measure/Arrange**：告诉布局管理器控件想要多大。
- **数据驱动绘制 ≈ INotifyPropertyChanged 殊途同归**：控件成员只存数据/状态，paintEvent 只读成员画图；Qt 里"数据变了"和"画面刷新"是两个动作，必须手动 `update()` 桥接。

## 3. 实现内容

- `src/ui/widgets/linechartwidget.h/.cpp`：网格 + 折线 + 标题；`appendPoint` 追加、超出 500 点 `removeFirst` 滚动淘汰（内存有界）、`clearData`、`setRange` 非法输入忽略（`min<max` 才生效）。
- `src/ui/widgets/gaugewidget.h/.cpp`：扇形刻度 + 指针 + 数值/单位；`setValue` 对 NaN 用 `qIsNaN` 保护、越界 `qBound` 钳制（150→100）。
- `src/ui/widgets/ledindicator.h/.cpp`：同心圆 + QRadialGradient 径向渐变发光，`setState` 切换亮/灭。
- `src/ui/pages/monitorpage.cpp`：4 通道卡片（每卡 = LED + 数值标签 + 曲线 + 仪表），演示数据源 QTimer 100ms 生成 4 路正弦波走统一入口 `onDataUpdated`；P12 后演示源停用，改由 DataService 真实数据驱动。
- `tests/unittests/tst_widgets.cpp`：11 测试函数 / 33 断言（LineChart 5 / Gauge 4 / Led 2）。

## 4. 测试与验证

`tst_widgets` 全绿，CTest 升到 8/8 套件（与 P10 同批）。控件继承 QWidget，测试 target 需链接 Qt5::Widgets。关键用例：越界钳制 150→100、NaN 保护、非法 setRange 忽略、空数据、量程读写往返。

## 5. 遇到的难点与解决

- **drawArc 角度方向画反（表盘不显示）**：Qt 角度单位是 **1/16 度**（非度）、0° 在 **3 点钟**、正值为**逆时针**——写 `270` 而非 `270*16`，或方向写反，弧就"消失/镜像"。解法：表盘从 225° 顺时针扫 270°，跨度角写 `-270*16`。
- **paintEvent 里做耗时操作卡顿**：把浮点运算/容器遍历放进 paintEvent，高频重绘下累积卡顿。解法：paintEvent 只做"读成员 + 画"，计算放业务方法。
- **忘记 `update()` 数据变了但不重绘**：修改成员变量不会自动触发重绘（Qt 无 INPC 机制）。解法：每个修改状态的业务方法末尾调 `update()`。

## 6. 阶段成果小结

监控页完整可用，配合 P12 真实链路实时显示 4 通道波形/仪表/LED。核心领悟：**WPF 是声明式 + 数据绑定，Qt Widgets 是命令式 + 手动重绘——渲染模型从"框架自动刷新"切换到"你决定何时刷新、画什么"**；paintEvent 是纯函数式（无副作用、只读状态、画完即走），这是 Qt 渲染高性能的秘密。
