# P02 阶段学习文档 —— C++ 现代特性筑基（ByteUtils 工具库）

> 提交：`1047b6f` ｜ 里程碑：`datascope_utils` 静态库 + `tst_byteutils` 单测全绿

## 1. 阶段目标

用 C++17 现代特性实现第一个工具库 ByteUtils（十六进制互转 + 大小端读写），把"内存谁负责"的 RAII 心智建立起来，并搭好"静态库 + 独立测试 target"的工程基线。

## 2. 关键技术点（WPF 迁移锚点）

- **RAII**：栈对象离开作用域自动析构，`QByteArray`/`QString` 无需手动释放——替代 C# GC 的核心思维。
- **const 引用入参 / 引用出参**：`const QByteArray &data` 只读不拷贝；`quint16 &out` 配合返回值实现 TryParse 风格（≈ C# `int.TryParse`）。
- **匿名命名空间**：`.cpp` 内 `namespace { ... }` 文件私有常量 ≈ C# `private const`。
- **静态库 target** ≈ WPF 类库项目：一个库被主程序和测试共用。
- **QtTest 数据驱动**（`_data()`/`QFETCH`/`QCOMPARE`）≈ NUnit `[TestCase]`。

## 3. 实现内容

- `src/utils/byteutils.h/.cpp`：`ByteUtils` 静态方法——`toHexString`/`fromHexString`（含 0x 前缀容忍）、`readUInt16BE`/`appendUInt16BE` 等大端读写。命名空间 `datascope::utils`。
- `tests/unittests/tst_byteutils.cpp`：14 个断言组的单测，覆盖正常值/边界（空、单字节、越界）/脏输入。
- `CMakeLists.txt`：新增 `datascope_utils` 静态库（PUBLIC 传播 `src` 头文件路径与 Qt5::Core），`tst_byteutils` 可执行 target + `add_test`。

## 4. 测试与验证

`ctest` 集成 QtTest：`tst_byteutils` 全 PASS，主程序仍可运行。P2 后 ctest 含 2 个测试 target（byteutils + 后续逐步累积）。

## 5. 遇到的难点与解决

- **hex 解析"0x 前缀"被误解析**：`fromHexString("0xAA,bb,0c")` 把 `0x` 里的 `'0'` 当高半字节拼出 `0x0A`。解法：遇 `x/X` 且已捕获一个为 0 的高半字节时撤销该 `'0'`。
- **ctest 报 0xc0000135（找不到 DLL）**：windeployqt 只部署了主程序，测试程序缺 Qt5Test.dll。解法：把 windeployqt 封装成 `ds_deploy_qt(TARGET)` 函数，主程序与**所有**测试 target 都调用。

## 6. 阶段成果小结

工具库 + 测试基建确立。核心领悟：**C# 的 GC 让内存隐形，C++ 的 RAII 让资源生命周期显式化**——"对象归属"成为后续对象树（P4）、单例（P6）、线程 Worker（P12）生命周期管理的思维基础。
