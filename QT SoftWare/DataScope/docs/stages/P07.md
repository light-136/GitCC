# P07 阶段学习文档 —— 配置系统（ConfigManager）

> 提交：`2f90b07`（P3~P7 合并提交）｜ 里程碑：`tst_configmanager` 单测全绿

## 1. 阶段目标

实现全局配置系统 ConfigManager：基于 QSettings 的 INI 纯文本持久化、类型化读取（int/bool/string/double 都强制带默认值）、QMutex 线程安全、懒加载 + 兜底目录。设备参数（通道数、采样率、串口/网口参数）不能写死在代码里。

## 2. 关键技术点（WPF 迁移锚点）

- **QSettings ≈ Properties.Settings / app.config**：但**在 Windows 上 `NativeFormat` 默认写注册表**（HKEY_CURRENT_USER），不是文件！必须显式 `IniFormat` 打破默认——这是 C# 转 Qt 必踩的大坑。
- **QVariant ≈ `object` 装箱**：`QSettings::value(key)` 永远返回 QVariant，读取必须 `toInt()/toString()` 拆箱；空 QVariant 的 `toInt()` 是 0、`toString()` 是空串（静默归零陷阱）。
- **QMutex + QMutexLocker ≈ lock**：QSettings 本身非线程安全，单例被 UI/采集线程共享必须加锁。
- **懒加载 + 兜底目录 ≈ 依赖注入**：路径可注入，测试才可隔离。

## 3. 实现内容

- `src/infrastructure/configmanager.h/.cpp`：Meyer's Singleton；`init(dir)`、`setValue(key,val)`、`value(key,default)`、`intValue/boolValue/stringValue/doubleValue`、`sync()`、`remove`；组合持有 `QSettings*`（不是继承）；`QSettings::setDefaultFormat(IniFormat)` 全局兜底；`resolveConfigDir` 兜底链（显式 → AppDataLocation → ./config）+ `QDir().mkpath()`。
- `CMakeLists.txt`：并入 `datascope_infra` 库 + `tst_configmanager` target。

## 4. 测试与验证

`tst_configmanager` 7 个测试函数全绿：init 建文件 / 写读回环 / 类型化读取 / 默认值 / remove / **持久化跨重载**（写→sync→重新 init 同一目录读回）/ 类型强转。

## 5. 遇到的难点与解决

- **Windows 上 QSettings 默认写注册表，"配置文件找不到"**：`QSettings("x.ini")` 单参数构造 format 默认 `NativeFormat`，字符串被当注册表路径。它不报错、看起来一切正常，最隐蔽。解法：**绝对路径 + IniFormat 两个条件缺一不可**。
- **读取不给默认值 → 空 QVariant 静默拿到 0/空串**：C# 的 `Settings` 永远有 app.config 兜底，Qt 没有。解法：类型化读取一律强制带默认值，把陷阱堵死在门面层。
- **QSettings 非线程安全**：单例被多线程共享，每次读/写/删进同一把锁。

## 6. 阶段成果小结

配置地基落定，与 P6 日志并列构成基础设施层。核心领悟：**C# 的配置是"编译期强类型 + 文件默认在 exe 旁"；Qt 的配置是"运行时字符串 key + QVariant + Windows 默认进注册表"**——默认值责任完全落在调用方，"配置代码处处带默认值"成为铁律。
