# P01 阶段学习文档 —— 环境搭建与工程骨架

> 提交：`52f51a9` ｜ 里程碑：Qt5.12.2 + MinGW + CMake3.25 + Ninja 空主窗口可运行

## 1. 阶段目标

搭建可运行的 Qt 工程骨架，为后续 P2~P15 全部模块提供"载体"。具体实现：用 CMake 组织 Qt5 工程、打通 AUTOMOC/AUTORCC 三开关、生成并运行一个空主窗口，验证工具链（Qt/编译器/CMake/Ninja）可用。

## 2. 关键技术点（WPF 迁移锚点）

- **QApplication + app.exec()** ≈ `App.xaml` + `Application.Run()`：全局对象 + 阻塞式事件循环，所有"看似同时发生"的定时器/网络/UI 都由它驱动。
- **QMainWindow** ≈ WPF `MainWindow`：自带菜单栏/工具栏/状态栏/中央区四块骨架。
- **Q_OBJECT + moc + AUTOMOC** ≈ C# 编译器生成/反射：moc 在**编译期**读含 Q_OBJECT 的头文件生成元对象代码（静态 QMetaObject），而非运行时反射。
- **CMakeLists.txt + find_package(Qt5)** ≈ `.csproj` + NuGet 引用。
- **WIN32_EXECUTABLE** ≈ `WinExe`：GUI 子系统链接，启动不弹控制台黑窗。

## 3. 实现内容

- `src/app/main.cpp`：程序入口——创建 QApplication、设置组织名/应用名/版本、栈上创建 `MainWindow window;` 并 `show()`，最后 `return app.exec()`。
- `src/ui/mainwindow.h/.cpp`：主窗口类（`Q_OBJECT` + `Q_DISABLE_COPY`），设置标题与 1280×800 初始尺寸。
- `CMakeLists.txt`：`project(DataScope VERSION 0.1.0)`、`CMAKE_CXX_STANDARD 17`、`set(CMAKE_AUTOMOC/AUTORCC/AUTOUIC ON)`，链接 Qt5 Core/Gui/Widgets。

## 4. 测试与验证

本阶段无单测，以"人工验收 + 进程验证"为准：`cmake --build` 生成 `DataScope.exe`；验证时检测 `MainWindowTitle`（真正出现窗口）而非"进程存活"——避免错误弹窗挂起被误判为正常。

## 5. 遇到的难点与解决

- **中文路径导致 moc 崩溃**：工程原在 `QT软件` 目录，Qt5.12 MinGW 的 moc/g++ 在 Windows 以 ANSI 处理路径，中文变成乱码 `QT??`，AUTOMOC 直接失败。根因是 **Qt MinGW 限制：工程路径必须纯 ASCII**。解法：目录改名 `QT SoftWare`，问题消失。
- **双击 exe 报"找不到 Qt5Widgets.dll"**：Qt 程序运行时动态链接 Qt DLL。解法：用 `windeployqt` 部署运行库，并封装成 CMake `ds_deploy_qt()` 函数写进 POST_BUILD，此后每次构建自动部署。
- **pip 安装的 cmake 不在 PATH**：用全路径调用。

## 6. 阶段成果小结

工程骨架可编译、可运行、目录分层（app/ui/.../tests）、.gitignore 排除 build 产物。确立两条铁律：工程路径纯 ASCII；GUI 验证必须检查窗口句柄而非进程存活。
