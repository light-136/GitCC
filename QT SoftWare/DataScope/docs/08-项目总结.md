## 一、项目回顾

DataScope Studio 用 15 个渐进阶段完成了一个**可交付的工业级软件**。它既是 Qt 学习载体，也是真实可用的数据采集与监控工具。项目的意义不在于功能多复杂，而在于**完整走通了工业软件从零到发布的全部工程环节**。

## 二、阶段复盘

### 完整闭环的阶段（P1~P15）

每个阶段都严格执行 **「编译 → 测试 → 文档 → 验收 → 进入下一阶段」**：

- **P1~P5（地基）**：工程骨架 + C++ 语言筑基 + Qt 核心机制 + UI 框架。这一阶段最大的价值是**把"会用"变成"理解"**——信号槽的队列投递、QSS 的层叠规则、对象树生命周期。
- **P6~P10（中场）**：日志 / 配置 / 领域模型 / 协议引擎。开始出现**真实工程的复杂性**：日志的线程安全、协议的半包粘包、CRC 校验的字节序。
- **P11~P14（攻坚）**：TCP 通信 / 多线程 / 状态机 / 自绘控件。这是**难度陡增**的阶段——网络竞态、跨线程信号、事件驱动调试。
- **P15（收官）**：记录回放 + 集成测试 + 部署 + 全套文档，工程从"能跑"升级为"能交付"。

### 难点与突破（按投入排序）

| 难点 | 现象 | 突破方案 |
|------|------|----------|
| 网络信号竞态 | `waitForNewConnection` 与 QSignalSpy 事件循环竞争 | 事件驱动 + `QTRY_VERIFY_WITH_TIMEOUT` |
| 跨线程信号注册 | 自定义类型参数在队列连接中丢失 | 全限定名 + qRegisterMetaType 与 moc 规范化名一致 |
| 枚举元类型 | QSignalSpy 无法处理 enum class 参数 | Q_DECLARE_METATYPE + 三种名字别名注册 |
| Windows 端口语义 | 释放端口约 2s 才返回拒绝；相邻端口被系统服务占用 | listen 验证空闲端口 + 放宽等待时间 |
| Worker 重连吞掉 | 错误后 m_client 残留，start() 保护逻辑拦下重连 | 错误时销毁客户端并置空 |
| CMake 转义 | Windows 反斜杠路径触发 `Invalid character escape` | 工具路径一律用正斜杠 |
| DLL 锁定 | 运行中的进程锁定 Qt5Cored.dll 导致 windeployqt 失败 | 先停止测试进程再重新部署 |

## 三、技术认知跃迁

### 3.1 从 WPF 到 Qt 的迁移锚点

学习最有效的方式是**映射而非重学**。对照表（详见《09-最终报告》第七章）：

- WPF 的 `INotifyPropertyChanged` → Qt 的信号驱动 UI 刷新
- WPF 的 `async/await` → Qt 的线程 + 队列信号（语义更"原始"，也更接近本质）
- WPF 的 `DependencyObject` → Qt 的 `QObject`（信号槽、属性、父子树）
- WPF 的 XAML 样式 → Qt 的 QSS（同为样式表，语法类似 CSS）

### 3.2 最重要的三个理解

1. **信号槽的三种连接方式**（直连/队列/阻塞直连）是 Qt 多线程的基石——**"谁发、谁收、在哪个线程"** 决定了一切竞态问题。
2. **对象树所有权**：`new` 出带父对象的 QObject，销毁由父负责——既是便利也是约束。
3. **隐式共享**：QString/QVariant 的写时复制让值传递高效，但跨线程传递自定义容器必须显式注册元类型。

## 五、协作与效率复盘

- **多 Agent 并行**显著加速了 UI 与文档这类可并行任务；主 Agent 专注架构与测试，职责清晰。
- **接口先行**是并行能成立的前提——MonitorPage 的 `onDataUpdated` 单一入口让数据源可替换、UI 零改动。
- **教训**：Agent 产出必须统一经「编译 + 测试」门槛再合入，避免"看起来对、跑起来错"。

---

## 六、对后续项目的启示

1. **先搭分层骨架，再填业务**：静态库划分的成本远低于后期拆模块。
2. **测试先行不是口号**：本项目的每一个"必现难点"都是测试先复现、再修复的。
3. **发布思维提前到 P1**：`ds_deploy_qt` 函数在 P1 就内置，后期部署零成本。
4. **文档即交付**：CLAUDE.md 要求的文档体系让整个项目"可交接、可传承"。

## 七、结语

DataScope Studio 的完成证明了一件事：**用真实工程学习技术栈，远比教程学习深入**。真正的收获不是写了 4000 行 Qt 代码，而是建立了"从需求到架构、从架构到测试、从测试到交付"的完整工程思维——这种能力可以迁移到任何技术栈。
