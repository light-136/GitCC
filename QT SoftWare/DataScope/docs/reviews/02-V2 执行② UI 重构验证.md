## 四、遗留项（移交 V2-执行③）

1. **监控页通道元数据仍为内置默认**（名称/量程来自 MonitorPage 常量数组）。
   计划：#23 模拟设备升级时，由 Simulator 上报通道配置（名称/单位/量程），
   MonitorPage 改为从"当前设备通道配置"构建通道卡片，消除最后一批演示硬编码。
2. **日志面板**：审查建议的"日志/报警区域"中报警已上线，日志实时面板
   依赖 LogManager 信号流（已存在 messageLogged），列入 #23 随测试体系补强。
3. **设备管理 → 监控联动的设备-通道模型化**：设备页只管理"设备节点"，
   尚未把通道级配置（ChannelConfig）关联到具体设备，待 DeviceManager 服务层。

## 五、工程质量自评（对照审查要求的"真实软件"标准）

- **UI 分层**：页面不再持有业务逻辑，数据修改走 Model 的 dataChanged 通知 View
  自动刷新（对应 WPF 的 ObservableCollection + Binding）。
- **配置持久化**：设备列表、系统设置均落盘 ConfigManager，重启不丢失，非演示数据。
- **连接驱动**：连接目标来自用户配置（设备页表单 / 全局默认），不再写死在代码。
- **报警链路**：数据→引擎→事件模型→列表，四段各自可测（tst_alarmengine、
  tst_alarmeventmodel 已有 15 项单测覆盖）。
- **仍有待提升**：通道级配置未模型化、无独立日志面板、DeviceManager 未建 ——
  这些需要服务层/模拟器协同，列入 V2-执行③，不靠 UI 层硬凑。
