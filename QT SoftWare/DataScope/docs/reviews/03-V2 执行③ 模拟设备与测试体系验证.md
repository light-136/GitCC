## 二、已完成项（模拟设备 + 测试分层，已编译通过）

### 2.1 异常注入器 FaultInjector（纯逻辑字节变换层，src/simulator/faultinjector.*）

| 能力 | 实现 |
|------|------|
| None 无异常 | 原样返回正常帧 |
| Sticky 粘包 | 每次输出两帧合发（考验主机流式重组） |
| Fragment 分包 | 一帧拆成多段字节（考验半包缓冲） |
| CrcError CRC 错误 | 翻转 CRC 字节（主机应整帧丢弃） |
| IllegalFrame 非法帧 | 篡改 SOF 标志（主机应丢弃并重新同步） |
| Delay 延迟 | 推迟到下一周期输出（模拟网络/设备延迟） |
| Surge 数据突变 | 通道值推到超量程并**重算 CRC**（突变帧必须合法，才能触发主机报警引擎） |
| Disconnect 断线 | 设备层主动断开全部客户端 |

**语义要点**：Surge 突变帧重算 CRC 是"语义修正"而非测试取巧——设备"存活"但值越限，
主机报警引擎才能真正收到该值并产生报警事件。

### 2.2 模拟设备 SimulatorDevice（QObject 网络层，src/simulator/simulatordevice.*）

- **运行模式**：Normal / Alarm（每 20 帧翻转报警相位，通道 0=200.0f 超限）/
  Stress（10ms 高频 + 每帧粘包） / Busy（每 50 帧周期内末尾 20 帧静默）/ Error；
- **客户端请求应答**：每客户端独立 FrameParser，响应通道配置查询（FUNC=0x03 → 0x83）；
- **通道配置**：默认 4 通道（温度℃0-100 / 压力MPa0-10 / 流量m3/h0-50 / 振动mm/s0-5），
  `rebuildChannelConfig()` 由通道数驱动。

### 2.3 通道配置协议编解码 ChannelConfigCodec（src/protocol/channelconfigcodec.*）

- 常量：kFuncQuery=0x03 / kFuncQueryResponse=0x83 / kCmdQueryChannels=0x01；
- 定长布局：`[count:1B] + N × [index:1B][name:16B UTF-8][unit:8B UTF-8][min:4B float BE][max:4B float BE]`，
  kChannelConfigWireSize=33；
- 防御：空列表/超 255 通道编码失败；长度不符/通道数非法解码失败；超长名截断、短名补零。

### 2.4 模拟设备程序入口（src/simulator/main.cpp）

命令行参数：`-p/--port`、`-m/--mode`（normal/alarm/stress/busy/error）、
`-f/--fault`（crc/sticky/fragment/illegal/delay/surge/disconnect）、`-i/--frame-interval`。

### 2.5 测试分层（已注册 CTest）

| 层 | 套件 | 覆盖 |
|----|------|------|
| Unit | tst_faultinjector（8 例） | 注入器纯逻辑变换断言 |
| Simulator | tst_simulatordevice（7 例） | 设备启动/广播/客户端管理/模式行为（真实回环） |
| Unit | tst_channelcodec（7 例） | 编解码往返/边界/脏数据防御 |
| Integration | tst_integration（4 例） | 配置查询链路/正常采集/粘包重组/CRC 丢弃 |

后续 UI 补强新增 tst_logpanel（4 例，日志面板黑盒 UI 测试）与 tst_dataservice 通道配置链路用例
（详见《06-测试文档.md》1.4 统计表）。

### 3.1 日志面板设计（对照 WPF）

- **工程问题**：工业软件必须能看到系统运行日志（连接/错误/告警），排查问题靠日志；
- **Qt 技术**：LogManager::messageLogged 观察者信号（P6 已存在）→ UI 订阅；
- **控件**：QPlainTextEdit（只读，大量文本性能好）承载；级别用 QTextCharFormat 着色；
  工具栏：级别过滤下拉（All/Debug+/Info+/Warn+/Error+/Fatal，QVariant 存 LogLevel）、清空按钮、
  计数标签；环形缓冲上限 1000 条，超限整体重绘（性能有界）；
- **接入**：主窗口新增"日志"页签（第 5 个页签）；连接/断开/停止采集/错误/主题切换等关键路径打日志。

### 3.2 通道元数据数据驱动链路设计

**工程问题**：监控页通道名/单位/量程硬编码（温度/压力/流量/振动），
真实设备通道配置可能不同 → UI 必须由"设备上报的配置"驱动，设备变了 UI 自动适配。

**链路（三层改造）**：

```
采集线程                              主线程
AcquisitionWorker                     DataService             MonitorPage
   │ 连接成功后自动发查询帧(0x03/0x01)    │                       │
   │←──── 设备应答 0x83 配置帧 ────       │                       │
   │ handleFrame: 识别 0x83 → decode      │                       │
   │ channelConfigReceived(QVector<...>)──→ 转发信号 ────────────→ onChannelConfigReceived
   │                                     │                       │ 更新通道名/单位/量程
   │                                     │                       │ 重建报警规则
```

- **Worker**：`handleFrame` 按 func 分流——采集帧(0x01/0x01)走原 DataPoint 路径；
  配置响应帧(0x83/0x01)走 decode → emit channelConfigReceived（跨线程队列）；
- **Worker.start()**：连接成功后调用 `sendFrame({0x03, 0x01})` 主动拉取配置；
- **DataService**：新增信号 `channelConfigReceived(const QVector<ChannelConfigInfo> &)` 转发；
- **MonitorPage**：`m_channels` 静态数组改 `QVector<ChannelUi>`，收到配置后重建卡片标题/
  单位/仪表量程，`setupAlarmRules()` 改从真实量程派生；
- **元类型**：`Q_DECLARE_METATYPE(QVector<ChannelConfigInfo>)` + qRegisterMetaType（三个名字）。
