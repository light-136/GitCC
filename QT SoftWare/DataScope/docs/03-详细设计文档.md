## 2. 核心类详细设计

### 2.1 `datascope::services::TcpClient`

- **继承**：`public QObject`
- **定位**：服务层；封装 `QTcpSocket`，对外提供"连接/断开/发帧/收帧"四个业务动作。

**关键成员：**

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `m_socket` | `QTcpSocket*` | 底层 socket，构造时 `new QTcpSocket(this)`，挂 QObject 对象树回收 |
| `m_parser` | `protocol::FrameParser` | 流式帧解析器（值成员），处理半包/粘包 |

**方法签名与职责：**

| 方法 | 签名 | 职责 |
| --- | --- | --- |
| 构造 | `explicit TcpClient(QObject *parent = nullptr)` | 创建 socket；连接 `connected`/`disconnected`/`error`(QOverload)/`readyRead` 四个原生信号到内部槽 |
| 连接 | `void connectToHost(const QString &host, quint16 port)` | 异步发起连接（`m_socket->connectToHost`），结果由信号通知 |
| 断开 | `void disconnectFromHost()` | 主动断开 |
| 查询 | `bool isConnected() const` | 仅 `ConnectedState` 算已连接 |
| 发帧 | `bool sendFrame(const protocol::ProtocolFrame &frame)` | 未连接直接 false；`FrameBuilder::build` 组帧（空数组=false）；`m_socket->write` 全量写出 |

**信号：**

| 信号 | 签名 | 触发时机 |
| --- | --- | --- |
| `connected` | `void connected()` | socket 连接成功 |
| `disconnected` | `void disconnected()` | 主动断开/对端关闭/网络异常 |
| `errorOccurred` | `void errorOccurred(const QString &message)` | 底层 socket 错误统一转 QString |
| `frameReceived` | `void frameReceived(const protocol::ProtocolFrame &frame)` | 每解析出一帧合法帧（CRC 通过） |

**关键实现（`onReadyRead`）：**

```cpp
const QByteArray chunk = m_socket->readAll();   // 一次读走全部就绪字节
m_parser.feed(chunk);                           // 喂解析器（只追加）
protocol::ProtocolFrame frame;
while (m_parser.nextFrame(frame))               // 循环取帧：粘包场景可出多帧
    emit frameReceived(frame);
```

### 2.2 `datascope::services::AcquisitionWorker`

- **继承**：`public QObject`
- **定位**：采集线程工作对象，被 `moveToThread()` 迁到采集线程；`TcpClient` 在 `start()` 槽内创建，确保 socket 与线程同生。

**关键成员：**

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `m_client` | `TcpClient*` | 采集线程内的 TCP 客户端，`start()` 时创建、`stop()`/错误时销毁 |

**公开槽（均在采集线程内执行）：**

| 槽 | 签名 | 职责 |
| --- | --- | --- |
| `start` | `void start(const QString &host, quint16 port)` | 防重入（已存在 m_client 直接 return）；new TcpClient(this)；接 `connected`/`disconnected`/`errorOccurred`/`frameReceived` 四个信号；发起 `connectToHost`。错误时 `deleteLater()` 并置空 m_client——这是自动重连能工作的关键 |
| `stop` | `void stop()` | `m_client->disconnectFromHost()` → `deleteLater()` → 置空 |

**信号：**

| 信号 | 签名 | 说明 |
| --- | --- | --- |
| `pointsReady` | `void pointsReady(const QVector<datascope::domain::DataPoint> &points)` | 解析出的一批采样点（跨线程投递主线程） |
| `connectedChanged` | `void connectedChanged(bool connected)` | 连接状态变化 |
| `errorOccurred` | `void errorOccurred(const QString &message)` | 链路错误统一字符串 |

**关键实现（`handleFrame`，私有）：**

```cpp
void handleFrame(const protocol::ProtocolFrame &frame) {
    constexpr int kFloatBytes = 4;
    const int channelCount = frame.payload.size() / kFloatBytes;
    if (channelCount <= 0) return;
    QVector<domain::DataPoint> points;
    for (int i = 0; i < channelCount; ++i) {
        // 大端 4 字节 → quint32 → memcpy 位模式解释为 float
        float value = 0.0f; memcpy(&value, &raw, sizeof(value));
        domain::DataPoint dp;
        dp.channelIndex = i; dp.value = value; dp.timestamp = QDateTime::currentDateTime();
        points.append(dp);
    }
    emit pointsReady(points);
}
```

### 2.3 `datascope::services::DataService`

- **继承**：`public QObject`
- **定位**：主线程与采集线程之间的**唯一数据通道**（数据总线）。UI 只认它。

**关键成员：**

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `m_thread` | `QThread*` | 采集线程（objectName="AcquisitionThread"） |
| `m_worker` | `AcquisitionWorker*` | 采集线程工作对象（moveToThread） |
| `m_mutex` | `QMutex*` | 保护快照与状态标志 |
| `m_lastData` | `QVector<domain::DataPoint>` | 最新数据快照 |
| `m_connected` / `m_acquiring` | `bool` | 连接/采集状态标志 |

**方法签名与职责：**

| 方法 | 签名 | 职责 |
| --- | --- | --- |
| 构造 | `explicit DataService(QObject *parent = nullptr)` | 注册 `QVector<DataPoint>` 元类型；创建线程+Worker+moveToThread；连接 Worker 信号；`m_thread->start()` |
| 析构 | `~DataService() override` | `stopAcquisition()` → `quit()` → `wait(3000)`；释放互斥锁 |
| 连接 | `void connectTo(const QString &host, quint16 port)` | 已连接直接报错；`invokeMethod(worker,"start",QueuedConnection)` |
| 断开 | `void disconnectFromDevice()` | 简化：等价 `stopAcquisition()` |
| 查询 | `bool isConnected() const` / `bool isAcquiring() const` | 锁内读状态 |
| 采集 | `void startAcquisition()` / `void stopAcquisition()` | 启/停采集；`stopAcquisition` 同时 `invokeMethod` 投递 `Worker::stop` |
| 快照 | `QVector<domain::DataPoint> lastData() const` | 锁内返回快照拷贝 |

**信号：**

| 信号 | 签名 | 说明 |
| --- | --- | --- |
| `connected` | `void connected()` | 连接成功（主线程收到） |
| `disconnected` | `void disconnected()` | 断开 |
| `connectionError` | `void connectionError(const QString &message)` | 连接/采集错误 |
| `dataUpdated` | `void dataUpdated(const QVector<datascope::domain::DataPoint> &points)` | 实时数据分发（MonitorPage 消费） |
| `acquisitionStarted` / `acquisitionStopped` | `void` | 采集启停通知 |

**关键实现（`onPointsReady` / `onConnectedChanged`，主线程槽）：**

```cpp
void DataService::onPointsReady(const QVector<domain::DataPoint> &points) {
    { QMutexLocker locker(m_mutex); m_lastData = points; }   // 覆盖式快照
    emit dataUpdated(points);
}
void DataService::onConnectedChanged(bool nowConnected) {
    { QMutexLocker locker(m_mutex); m_connected = nowConnected; }
    if (nowConnected) emit connected(); else emit disconnected();
}
```

### 2.4 `datascope::services::DeviceController`

- **继承**：`public QObject`
- **定位**：设备状态机控制器，把 DataService 的"无状态"信号翻译成"有状态"状态机，并实现退避自动重连。

**关键成员：**

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `m_service` | `DataService*` | 数据总线（构造时 `new DataService(this)`） |
| `m_reconnectTimer` | `QTimer*` | 重连定时器（单次触发） |
| `m_status` | `DeviceStatus` | 当前状态（初始 Disconnected） |
| `m_userDisconnected` | `bool` | 用户主动断开标志 |
| `m_retryAttempts` | `int` | 重连尝试计数（驱动退避间隔） |
| `m_host` / `m_port` | `QString` / `quint16` | 重连目标 |

**方法签名与职责：**

| 方法 | 签名 | 职责 |
| --- | --- | --- |
| 构造 | `explicit DeviceController(QObject *parent = nullptr)` | 创建 DataService + 单次 QTimer；连接 DataService 四个信号与定时器 timeout |
| 查询 | `datascope::domain::DeviceStatus status() const` | 当前状态 |

| 断开 | `void disconnectDevice()` | `m_userDisconnected=true`；停定时器；`m_service->disconnectFromDevice()`；`setStatus(Disconnected)` |
| 采集 | `void startAcquisition()` / `void stopAcquisition()` | 透传给 DataService |

**信号：**

| 信号 | 签名 | 说明 |
| --- | --- | --- |
| `statusChanged` | `void statusChanged(datascope::domain::DeviceStatus status)` | 状态转移通知（状态不变不重发） |
| `errorOccurred` | `void errorOccurred(const QString &message)` | 错误/降级通知（连接失败、断线、重连提示） |
| `dataUpdated` | `void dataUpdated(const QVector<datascope::domain::DataPoint> &points)` | 实时数据转发 |

**私有槽：**

| 槽 | 签名 | 职责 |
| --- | --- | --- |
| `onServiceConnected` | `void` | `m_userDisconnected=false`、`m_retryAttempts=0`；停定时器；`setStatus(Connected)` |

| `onServiceError` | `void onServiceError(const QString &message)` | emit errorOccurred；`setStatus(Error)`；非用户主动断开则 `startReconnectTimer()` |

**私有工具：**

| 方法 | 签名 | 职责 |
| --- | --- | --- |

**关键实现（`onReplayTick`）：**

```cpp
void RecordManager::onReplayTick() {
    if (m_replayIndex >= m_replayFrames.size()) {
        stopReplay(); emit replayFinished(); return;
    }
    emit replayData(m_replayFrames.at(m_replayIndex));
    ++m_replayIndex;
    emit progressChanged(m_replayIndex);
}
```

### 2.6 `datascope::protocol::Crc16`

- **继承**：无（静态工具类）
- **定位**：MODBUS CRC16 计算。

| 方法 | 签名 | 职责 |
| --- | --- | --- |
| `compute` | `static quint16 compute(const QByteArray &data)` | 初始 `0xFFFF`，查表驱动：`crc = (crc >> 8) ^ table.values[(crc ^ byte) & 0xFF]` |

- 私有实现：匿名命名空间内 `Crc16Table` 结构体（构造函数一次性算好 256 项表），`crc16Table()` 返回函数局部 static 表（线程安全，仅构造一次）。

### 2.7 `datascope::protocol::FrameBuilder`

- **继承**：无（静态工具类）
- **定位**：组帧器，与 FrameParser 严格互逆。

| 方法 | 签名 | 职责 |
| --- | --- | --- |
| `build` | `static QByteArray build(quint8 func, quint8 cmd, const QByteArray &payload)` | 载荷超 `kMaxPayloadLen` 返回空数组；否则按 SOF→FUNC→CMD→LEN(大端)→DATA→CRC16(低字节在前) 组帧 |

### 2.8 `datascope::protocol::FrameParser`

- **继承**：无（值类型解析器）
- **定位**：流式解析器，处理半包/粘包/错位重同步。

| 方法 | 签名 | 职责 |
| --- | --- | --- |
| `feed` | `void feed(const QByteArray &chunk)` | 追加字节到内部缓冲（不做解析） |
| `nextFrame` | `bool nextFrame(ProtocolFrame &out)` | 三态状态机尝试取帧；成功写 out（isValid=true）并消费；失败不破坏缓冲 |
| `bufferedBytes` | `int bufferedBytes() const` | 未消费字节数 |

**关键成员：** `QByteArray m_buffer`（累积缓冲）。
**私有辅助：** 匿名命名空间内 `findSof()` 逐字节重叠扫描 `0xAA 0x55`（`"0xAA 0x00 0xAA 0x55"` 场景下第二个才是帧头，必须逐字节推进）。

## 4. 关键状态机：DeviceController

### 4.1 状态定义（`datascope::domain::DeviceStatus`）

| 状态 | 枚举值 | 含义 |
| --- | --- | --- |
| `Disconnected` | 0 | 未连接（初始状态） |
| `Connecting` | 1 | 正在连接（异步过程中） |
| `Connected` | 2 | 已连接（采集可用） |
| `Error` | 3 | 出错（通信异常/设备离线） |

### 4.2 状态转移图

```
                     connectDevice()
  ┌────────────┐  ──────────────────►  ┌─────────────┐
  │ Disconnected│                        │ Connecting  │
  └────────────┘  ◄──────────────────  └─────────────┘
      ▲     ▲          主动断开              │     │
      │     │  disconnectDevice()           │     │  connectDevice() 失败
      │     │                               │     ▼
      │     │                         ┌─────────────┐
      │     └─────────────────────────│   Error     │
      │        用户主动断开            └─────────────┘
      │                                    │  意外断线 / 错误
      │  onServiceConnected()              ▼
      │                          ┌──────────────────┐
      └──────────────────────────│    Connected     │
                                 └──────────────────┘
                                     │  意外断线（设备掉电/网线断开）
                                     ▼
                                ┌─────────┐
                                │  Error  │ ──► startReconnectTimer() 退避重连
                                └─────────┘
```

### 4.3 转移表

| 触发事件 | 前提条件 | 动作 | 下一状态 |
| --- | --- | --- | --- |
| `connectDevice()` | 当前非 Connected | 保存 host/port；`m_userDisconnected=false`；`m_retryAttempts=0`；停重连定时器；`m_service->connectTo` | Connecting |
| `onServiceConnected()` | — | `m_userDisconnected=false`；`m_retryAttempts=0`；停定时器 | Connected |
| `onServiceDisconnected()` | `m_userDisconnected==true` | 复位标志 | Disconnected |
| `onServiceDisconnected()` | 意外断线 | 启动退避重连 | Error |
| `onServiceError(msg)` | — | emit errorOccurred；非主动断开则启动重连 | Error |
| `onReconnectTimeout()` | — | 重新 `m_service->connectTo(m_host, m_port)` | Connecting |
| `disconnectDevice()` | — | `m_userDisconnected=true`；停定时器；`m_service->disconnectFromDevice()` | Disconnected |

### 4.4 退避重连策略

- 间隔计算：`intervalMs = min(1000 << m_retryAttempts, 30000)`（1s→2s→4s→8s→16s→30s，封顶 30s）。
- 每次超时重连前 `++m_retryAttempts`，连接成功后归零。
- 仅当 `m_status == Error` 且 `m_userDisconnected == false` 且定时器未激活时才启动，防止"断线+错误"双重触发让退避跳档。
- 重连每次都是**新建全新连接**：Worker 在错误时 `deleteLater()` 并置空 `m_client`，保证 `start()` 不因残留客户端吞掉重连请求。

## 5. 数据格式设计

### 5.1 CSV 记录格式（RecordManager 落盘）

**表头：**
```
timestampMs,channelIndex,value
```

**数据行：** 每行一个采样点，`QTextStream` 按行写，UTF-8 文本：

```
timestampMs,channelIndex,value
1734168000123,0,42.5
1734168000123,1,5.2
1734168000123,2,25.8
1734168000123,3,3.1
```

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `timestampMs` | qint64 | `QDateTime::toMSecsSinceEpoch()`，自 1970-01-01 的毫秒数 |
| `channelIndex` | int | 通道序号（0..3） |
| `value` | double | 采样值（工程值，已换算） |

**说明：**
- 同一时间戳下的多行 = 同一采集帧的多个通道（模拟设备一帧 4 通道 → 4 行）。
- 文件以 `WriteOnly|Text|Truncate` 打开，写入即覆盖。
- `startRecording` 时写表头；`appendData` 仅当记录开关开启且文件打开时写行。

### 5.2 回放格式与重组

**加载（`loadReplay`）：**
1. 以 `ReadOnly|Text` 打开 CSV；
2. 跳过表头行（`reader.readLine()` 一次）；
3. 逐行 `split(',')`，不足 3 列视为畸形行跳过（不中断整个文件）；
4. 按时间戳分组：`QHash<qint64, QVector<DataPoint>> framesByTime`；
5. 取全部时间戳键 → `std::sort` 升序 → 依序构建 `m_replayFrames`（QHash 无序，必须显式排序保证回放顺序）。

**回放（`startReplay(intervalMs=100)`）：**
- `QTimer` 每 tick 发一帧 `replayData(m_replayFrames.at(m_replayIndex))`；
- 默认 100ms/帧（10 帧/秒）；
- 发完最后一帧：停定时器、`emit replayFinished()`；
- 进度信号 `progressChanged(current)` 驱动 `RecordPage` 的 `QProgressBar`。

### 5.3 通信帧字节序约定（协议层）

| 字段 | 字节序/顺序 |
| --- | --- |
| SOF | `0xAA 0x55`（固定） |
| LEN | 大端序（高字节在前） |
| DATA 内 float | 大端序 4 字节（模拟设备采集帧；PC 内存小端，需手动重排） |
| CRC16 | MODBUS CRC16；帧尾"低字节在前"追加（先 CRC_L 再 CRC_H） |
| CRC 覆盖范围 | FUNC(1) + CMD(1) + LEN(2) + DATA(len)，即 frame 跳过 SOF 的所有字节 |
