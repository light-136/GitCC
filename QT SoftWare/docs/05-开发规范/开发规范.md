# DataScope Studio 开发规范（v1.0）

> 文档编号：05　建立：P1　修订：随阶段更新
> 所有参与本工程的专项 Agent 必须遵守；违反者由主 Agent Review 打回。

---

## 1. 通用规范

| 项 | 规范 |
|----|------|
| 语言 | C++17，关闭编译器扩展（`CMAKE_CXX_EXTENSIONS OFF`） |
| 编码 | 源码文件统一 **UTF-8（无 BOM）**；注释与日志字符串使用中文 |
| 工程路径 | 必须纯 ASCII（本工程根已为 `QT SoftWare`） |
| 换行 | LF（QtCreator 默认即可） |
| 缩进 | 4 空格，不用 Tab |

## 2. 命名规范

| 对象 | 规则 | 示例 |
|------|------|------|
| 类 | 大驼峰 | `DeviceTableModel` |
| 函数/方法 | 小驼峰 | `startAcquisition()` |
| 信号 | 小驼峰，动词过去式/进行式 | `dataUpdated` / `connectionStateChanged` |
| 槽 | `on` + 信号名或事件 | `onStartButtonClicked` |
| 变量（局部/成员） | 小驼峰；成员用 `m_` 前缀 | `m_deviceList` |
| 常量/枚举值 | 大驼峰或大写 | `enum class State { Idle, Running }` |
| 文件 | 与类同名小写 | `devicetablemodel.cpp/h` |
| 宏/Q_OBJECT 标记 | 大写 | `Q_DISABLE_COPY` |

## 3. 文件组织规范

- 每个类一对 `.h/.cpp`，头文件只放声明，实现放 `.cpp`。
- `.h` 中先 `#include` 系统/第三方，再 `#include` 工程内头文件。
- 头文件尽量 `前向声明（forward declaration）` 而非 include，减少编译依赖。
- 每个头文件加 `#pragma once`。

## 4. 类设计规范

- **继承自 QObject 的类**：构造函数接受 `QWidget *parent = nullptr`（UI）或 `QObject *parent = nullptr`（Core），父对象负责析构。
- 禁止拷贝的 QObject 子类：构造函数后跟 `Q_DISABLE_COPY(ClassName)`。
- 类职责单一：一个类只做一件事，防止 QWidget 变 God Object。
- 对外暴露接口通过公有方法 + 信号；实现细节放 `private` 区。

## 5. Signal / Slot 规范

- **连接方式**：优先用 `QObject::connect(sender, &Sender::signal, receiver, &Receiver::slot)` 的函数指针式（编译期检查）。
- **lambda 槽**：捕获 `this` 时，注意 receiver 生命周期——用 `QPointer` 或确保对象不提前析构。
- **跨线程**：一律依赖 `AutoConnection`（自动转 QueuedConnection），**禁止**直接跨线程调用 UI 方法。
- **断连**：对象析构自动断连；需要显式时用 `disconnect`。
- 槽函数原则上只做轻量工作，耗时逻辑移入 Service/Worker。

## 6. 内存管理规范（RAII 优先）

- 栈对象优先：`MainWindow w;` 直接声明。
- 堆对象（必须 new）时：
  - UI 控件 → 挂 parent（`new QPushButton(this)`），由对象树回收；
  - 线程对象 → `moveToThread` 后由 QObject 父子树管理 + `deleteLater()`；
  - 非 QObject 资源 → `std::unique_ptr` / `std::shared_ptr`，禁止裸 `delete`（例外：极少数明确自管理的场合需注释）。
- **禁止** `new` 之后无归属且不 delete 的裸指针。
- 资源获取即初始化：RAII 类（QMutexLocker、QFile 等）用局部栈对象。

## 7. 线程安全规范

- GUI 线程只操作 QWidget；后台线程的数据更新通过**信号槽投递**到 GUI 线程的 Model/UI。
- 跨线程共享的容器用 `QMutex` 保护；读多写少用 `QReadWriteLock`。
- 需要多线程并发操作时用 `QtConcurrent` / `QThreadPool`，避免手搓线程。
- Worker 线程退出：发退出信号 → 线程事件循环结束 → `wait()` / `deleteLater()`，禁止强行 terminate。

## 8. 错误处理规范

- 返回 `bool` + 出参错误信息，或抛出 `std::runtime_error`（协议/配置解析层）。
- 对外部输入（配置、网络字节流、文件）一律校验，非法输入走日志 + 默认值，不让程序崩溃。
- 每类错误必须写日志（含时间/线程/级别/模块）。

## 9. 日志规范

- 统一走 `LogManager`（P6 起）：`LOG_DEBUG/INFO/WARNING/ERROR/FATAL`。
- 禁止裸 `qDebug()/qWarning()` 到控制台（教学演示例外，需注释说明）。
- 日志消息模板：`[时间] [线程ID] [级别] [模块] 消息`。

## 10. CMake 规范

- 所有新源文件必须同步进 `CMakeLists.txt`（由主 Agent 统一集成，专项 Agent 在文件登记表申请）。
- 新 Qt 模块引用统一由主 Agent 在顶层 `find_package(Qt5 ...)` 追加。
- 测试 target 独立 `add_executable`，用 `add_test` 注册进 CTest。

## 11. 注释规范（教学项目强要求）

- 每个类：`@file` / `@brief` / 关键设计说明。
- 每个公有方法：一句功能 + 参数/返回值说明（必要时）。
- **关键教学点必须写"为什么"注释**，例如：
  - 为什么 moveToThread；
  - 为什么这里用 QueuedConnection；
  - 为什么 parent 是 this。
- 禁止无意义注释（`// 设置标题` 这类）。

## 12. 提交规范（Git）

- 提交信息格式：`P<N> <模块>: <改动摘要>`，例如 `P2 utils: 新增 ByteUtils 与单测`。
- 不提交：build/ 产物、测试输出、个人临时文件。
- 每个阶段一个清晰里程碑提交；多 Agent 并行时按文件模块拆分提交。
