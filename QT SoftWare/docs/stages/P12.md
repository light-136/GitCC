## 1. 学了什么

1. **Qt 线程模型**：UI 线程绝不能做网络 I/O。`QThread + moveToThread` 把工作对象迁到采集线程，跨线程通信用信号槽（QueuedConnection）。
2. **DataService 数据总线**：主线程的门面对象，内部持有采集线程 + Worker。UI 只认 DataService（连接/采集/订阅数据/取快照），不感知线程——对应 C# 的 ViewModel + 后台线程数据总线。
3. **QTcpSocket 必须在所属线程内创建**：Worker 在 start() 槽内 new TcpClient（parent=this），杜绝"主线程 new 再 moveToThread"的未定义行为。
4. **跨线程投递数据**：Worker 的 `pointsReady(QVector<DataPoint>)` 队列投递回主线程，DataService 接收后转发 `dataUpdated` 并缓存 `lastData()` 快照（QMutex 保护）。
5. **数据源可替换设计**：MonitorPage 只认 `onDataUpdated(QVector<DataPoint>)` 一个入口——P14 演示源与 P12 真实链路在此无缝切换，UI 零改动。
6. **元对象跨线程调用**：`QMetaObject::invokeMethod(worker, "start", Qt::QueuedConnection, Q_ARG(...))` 把"请求"作为消息投递到采集线程——跨线程函数调用的 Qt 标准姿势。

## 2. 为什么学

- 工业采集是高频 I/O（50ms/帧），绝不能阻塞 UI。多线程 + 事件驱动是性能与响应性的根基。
- 数据总线抽象让 UI 与传输解耦：后续换串口（P9）、换协议都不动 UI。

## 3. Qt 原理（本阶段，核心）

- **moveToThread 后槽的执行线程**：对象的槽由"对象所在线程"的事件循环调度。跨线程 connect 自动用 QueuedConnection（参数拷贝进队列），同线程用 DirectConnection。
- **跨线程参数元类型（大坑）**：`QVector<domain::DataPoint>` 作为 QueuedConnection 参数，moc 对**模板参数里的相对名**会规范化为不带命名空间前缀的 `QVector<domain::DataPoint>`，与 `qRegisterMetaType` 注册的全限定名不一致 → 运行时警告且参数丢失。修复：信号参数用**全限定名** `QVector<datascope::domain::DataPoint>`，保证 moc 规范化名 == 注册名 == Q_DECLARE_METATYPE 名。
- **QThread 生命周期**：析构时必须先停 Worker（队列投递 stop）→ `quit()` → `wait(3000)`，否则"线程在清理中途销毁"是崩溃温床。
- **invokeMethod 的 Q_ARG 类型匹配**：`start(const QString&, quint16)` 跨线程调用必须精确匹配参数类型（QString/uint）。

## 4. C++ 原理（本阶段重点）

| 机制 | 说明 | 与 C# 对比 |
|------|------|-----------|
| Q_DECLARE_METATYPE | 类型进入元类型系统（QVariant 可包裹） | 无需（反射内置） |
| QMutex + QMutexLocker | 快照读写的互斥保护 | `lock` 语句 |
| RAII（QMutexLocker） | 作用域退出自动解锁 | `using`/`lock` |
| `QVector::value()`/拷贝 | 返回快照拷贝，锁内读取安全 | 值类型拷贝 |

## 5. 踩坑与修复

1. **跨线程 QVector<DataPoint> 参数丢失（警告 "Cannot queue arguments"）**：根因是 moc 规范化名不一致。修复：全限定名 + 注册名三处对齐（详见第 3 节）。
2. **`onConnectedChanged(bool connected)` 参数遮蔽信号**：参数叫 `connected` 会遮蔽同名信号 `connected()`，导致 `emit connected()` 被解析成"把参数当函数调用"而编译失败。修复：参数改名 `nowConnected`。
3. **连接失败后 Worker 残留 m_client**：`start()` 里 `if (m_client) return` 会吞掉重连请求。修复（P13 前置）：错误时 `deleteLater` 销毁客户端，使下次 start 能重建。
4. **QSignalSpy 辅助函数返回冲突**：QVERIFY 展开为无值 return，与返回 quint16 的辅助函数冲突。修复：`if+return 0`，调用点加断言。
