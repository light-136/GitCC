## 1. 学了什么

1. **Meyer's Singleton**：`static LogManager &instance()` 返回函数内静态局部对象——C++11 起首次初始化由编译器保证线程安全，对应 C# `Lazy<T>` 懒加载单例，但更短、更快、零额外对象。
2. **QMutex + QMutexLocker（RAII 加锁）**：`QMutexLocker locker(&m_mutex)` 构造即 `lock()`、析构即 `unlock()`；函数内提前 `return` 也不会丢锁。
3. **锁的生命周期控制**：`log()` 里用一对花括号把"加锁 + 写盘"包成独立作用域，**在 `emit` 信号之前释放锁**——避免持锁广播信号造成的性能问题乃至死锁。
4. **QFile / QTextStream 写日志**：文件以 `Append | Text` 打开（追加不覆盖、Windows 下自动处理换行）；每次在栈上新建 `QTextStream` 包裹文件句柄，写入后 `flush()` 立即落盘。
5. **UTF-8 编码**：`stream.setCodec("UTF-8")` 显式指定编码，保证 Windows 下中文日志不乱码、跨平台一致（QTextStream 默认可能用本地 ANSI/GBK）。
6. **观察者模式**：`messageLogged` 信号让 UI 实时订阅日志流，对应 C# 的事件/回调。
7. **`QTemporaryDir` 隔离测试**：单例是进程级的，用例之间共享状态——每个用例都重新 `init()` 到全新的临时目录，杜绝相互污染，绝不触碰真实 AppData。
8. **`Q_DECLARE_METATYPE` + `qRegisterMetaType`**：把自定义枚举注册进 Qt 元类型系统，使信号可被 `QSignalSpy` 记录参数、可跨线程排队连接。

## 2. 为什么学

- **日志是工业软件的"黑匣子"**：多通道采集程序跑在客户现场，程序崩了、帧丢了、网络断了，你不可能到现场去 debugger。日志必须把"时间/级别/模块/消息"写下来，崩溃后翻日志定位。
- **Qt 没有官方日志库**：`qDebug()` 只打控制台，且开发规范 §9 禁止裸用。自建 `LogManager` 是 P6 的明确任务——它不是业务功能，是**后续所有模块（UI/采集/协议/线程）都依赖的地基**。
- WPF 里有 NLog / `Trace.WriteLine` / `Trace.Listeners` 兜底，Qt 里这些都要自己写——**把熟悉的日志能力用 Qt 的方式重建一遍**，正是这个阶段的全部意义。

## 3. Qt 原理（本阶段）

- **Meyer's Singleton 为何线程安全**：C++11 标准 `[stmt.dcl]` 保证——多个线程同时首次进入 `static LogManager s_instance;` 时，初始化完成前其他线程阻塞等待，之后都看到已初始化完的对象。编译器内部已插好一次性初始化锁，无需手写 double-checked locking。
- **为什么不用类内 static 成员**：类内静态成员的初始化顺序跨编译单元不确定（*static initialization order fiasco*），且没有线程安全保证；函数内 static 是"首次调用时初始化"，两个问题都解决。
- **`QMutexLocker` 与 C# lock 的本质差异**：C# `Monitor` **可重入**（同线程重复 lock 合法）；Qt `QMutex` **默认不可重入**（同线程连续 lock 两次 → 死锁）。"锁里再调一个也锁同一对象的函数"在 C# 里很平常，在 Qt 里是死锁。
- **`QTextStream::setCodec`**：是成员函数，必须在实例上调用（`stream.setCodec("UTF-8")`），不能写成静态调用。
- **`QStandardPaths::writableLocation(AppDataLocation)`**：返回用户可写的应用数据目录，对应 C# `Environment.GetFolderPath(ApplicationData)`；`QDir().mkpath()` 递归创建多级目录。
- **信号跨线程自动排队**：`messageLogged` 信号配合 AutoConnection——后台采集线程 `emit`，UI 线程事件循环安全收到，这正是日志面板想要的效果。

## 4. C++ 原理（本阶段重点）

| 机制 | 说明 | 与 C# 对比 |
|------|------|-----------|
| Meyer's Singleton | 函数内 static 局部变量，C++11 线程安全 | `Lazy<T>` + `ExecutionAndPublication` |
| QMutex / QMutexLocker | RAII 加锁，析构自动解锁，不可重入 | `lock` 语句（Monitor，可重入） |
| `Q_DISABLE_COPY` | 编译期禁止拷贝（单例唯一性） | C# 无直接对应（靠私有构造 + 约定） |
| RAII 文件句柄 | `QFile` 成员对象析构自动 close | `IDisposable` + `using` |
| 匿名命名空间 | `.cpp` 文件内私有常量/函数 | `private static` |
| 枚举 + 元类型注册 | `enum class` + `Q_DECLARE_METATYPE` + `qRegisterMetaType` | C# `enum`（自带反射、可序列化） |

## 6. 为什么这样设计

1. **单例 + 私有构造 + `Q_DISABLE_COPY`**：全项目唯一日志出口，杜绝"再 new 一个"和"复制一份"，保证日志不写进多个文件。
2. **锁只保护"格式化 + 写盘 + flush"这一小段**：用独立花括号作用域在 `emit` 前释放锁。信号槽可能很慢、甚至反向调用本对象——持锁广播会造成性能问题乃至死锁。这是"锁区间要短、要单层"的工程落地。
3. **每次在栈上新建 QTextStream**：`QTextStream stream(&m_file)` 包裹同一个文件句柄，析构自动 flush，再显式 flush 一次保证立即落盘——牺牲一点性能换可靠性（程序可能崩溃，崩前写进缓冲的日志就丢了）。
4. **每行都 flush**：日志可靠性优先于吞吐量；实测性能不足再改"定时批量刷盘"。
5. **`init` 失败不抛异常、写盘失败不中断**：日志系统永远不能成为崩溃源——"日志炸了不能把程序炸了"，这是日志组件与普通组件的最大区别。
6. **`messageLogged` 无论写盘是否成功都广播**：UI 日志面板实时显示不依赖磁盘成败，两者解耦。
7. **`enum class LogLevel`**：强类型枚举，不会拿 `int` 误当级别传入（C# enum 能隐式转 int，C++ enum class 不能）。

## 7. 错误案例（真实踩坑）

### 错误案例 1：`QTextStream::setCodec` 写成静态调用编译失败

- **现象**：编译 `logmanager.cpp` 报错，指向 `QTextStream::setCodec("UTF-8")`——"reference to non-static member function"（或"无法解析的外部符号"）。
- **根因**：`setCodec` 是**成员函数**，必须作用于某个 `QTextStream` 实例；写成 `QTextStream::setCodec(...)` 等于调用一个不存在的静态函数，编译器直接拒绝。
- **修复**：先在栈上创建实例，再在实例上调用：
  ```cpp
  QTextStream stream(&m_file);
  stream.setCodec("UTF-8");   // 成员函数，在实例上调用
  stream << formatLine(level, module, message) << '\n';
  stream.flush();
  ```
- **教训**：Qt 里凡是"对对象做配置"的方法几乎都是成员函数（`setCodec`/`setFileName`/`setInterval`…）；只有类名前缀出现 `static` 关键字时才能静态调用。写错了编译器会替你发现，但报错信息有时藏在"reference to non-static member function"里，要能认出来。

### 错误案例 2：QSignalSpy 无法处理自定义枚举参数 LogLevel

- **现象**：运行 `tst_logmanager` 时，`QSignalSpy` 监听 `messageLogged` 后控制台警告 `Unable to handle parameter 'level' of type 'LogLevel' ... use qRegisterMetaType to register it`，`spy.at(0).at(0).value<LogLevel>()` 取不回正确值。
- **根因**：`Q_DECLARE_METATYPE(datascope::infrastructure::LogLevel)` 用预处理字符串化注册的名字是**带命名空间**的 `"datascope::infrastructure::LogLevel"`；而 moc 解析信号声明 `void messageLogged(LogLevel, ...)` 时**不做 C++ 语义解析**，生成的参数类型名是**不带命名空间**的 `"LogLevel"`。两者名字不一致，QSignalSpy 用 `"LogLevel"` 查询元类型失败。
- **修复**：在 `LogManager` 构造函数中显式注册别名：
  ```cpp
  qRegisterMetaType<LogLevel>("LogLevel");
  ```
- **教训**：带命名空间的自定义类型用作信号参数时，`Q_DECLARE_METATYPE` 之外**通常还需要 `qRegisterMetaType<T>("T")` 显式注册别名**，让 moc 生成的"裸类型名"也能查到元类型。这是"自定义类型进信号槽"的标配操作。

### 错误案例 3（设计预警）：多线程写日志不加锁 → 日志行被撕开

- **现象**（设计文档预警的场景）：两个线程同时调 `writeLine`，日志行互相穿插（"采帧到"、"样达完"），一行被撕成两半；严重时 `QTextStream`/`QFile` 内部游标错乱、崩溃。
- **根因**：`QFile::write` 不是原子操作。C# 里你以为 `File.AppendAllText` 自带锁（其实没有）；Qt 里**没有任何隐式锁**。`QTextStream`/`QFile` 本身非线程安全。
- **修复**：`log()` 用 `QMutexLocker` 把整个"格式化 + 写入 + flush"区间保护起来，保证整行不被撕开。
- **教训**：跨线程共享的资源必须显式加锁；别用"每行 open/append/close"当无锁方案，那是用性能换安全，不如一把锁。

## 8. 推荐实践

- 单例一律 Meyer's Singleton：函数内 `static` 局部变量 + 私有构造 + `Q_DISABLE_COPY`。
- 加锁用 `QMutexLocker`（RAII），永远不裸调 `lock()/unlock()`；持锁区间要短、要单层（锁内不调也会锁同一把锁的函数）。
- 日志每行 flush，可靠性优先；日志失败永不抛异常、永不中断业务。
- 自定义枚举进信号槽：`Q_DECLARE_METATYPE` + 构造函数里 `qRegisterMetaType<T>("T")`。
- 测试隔离：单测/工具代码写日志一律 `QTemporaryDir`，绝不落真实 AppData 或工程目录。
- 日志目录用 `QStandardPaths::writableLocation(AppDataLocation)` + `QDir().mkpath()`，不污染工作目录。

## 10. 本质差异（最重要的一课）

> **C# 的日志靠框架（NLog/Trace）"开箱即用"；Qt 的日志必须自己写——而自己写日志时，最大的敌人不是"怎么写进文件"，而是"什么时候、被谁并发地写进文件"。**

- **单例与锁是同一件事的两面**：全局唯一实例意味着多线程共享，共享就意味着必须加锁。C# 里 `Trace.WriteLine` 的内部锁被框架藏起来了；Qt 里没有任何隐藏锁，**`QFile` 非线程安全**——这把"并发安全"从框架的隐性责任变成了你的显式责任。
- **锁的"可重入性"差异最反直觉**：C# 的 `lock` 可重入（锁里再锁没事），Qt 的 `QMutex` 默认不可重入（同线程重锁死锁）。从 C# 带过来的"随手嵌套 lock"习惯，在 Qt 里就是死锁。**持锁区间短、单层，是 Qt 线程安全的铁律。**
- **"日志不能成为崩溃源"**：这是日志组件与普通组件的最大区别。C# 里日志库写失败多半静默；Qt 里如果 `init` 失败抛异常，那"日志炸了把程序炸了"——所以本工程所有日志路径都选择"失败静默 + 跳过写盘"，把可靠性让位给业务。

## 11. Debug / 排错案例

- **场景**：`tst_logmanager` 首次运行出现 `Unable to handle parameter 'level' of type 'LogLevel'` 警告，`messageLogged_signalEmitted` 断言失败。
- **排查**：警告信息直接指出"用 `qRegisterMetaType` 注册"，结合 `Q_DECLARE_METATYPE` 与 moc 的命名差异分析，确认是"带命名空间 vs 不带命名空间"的元类型名不一致。
- **修复**：构造函数里 `qRegisterMetaType<LogLevel>("LogLevel")` 后，警告消失、断言通过。
- **教训**：`QSignalSpy` 的警告文本是排错的第一手线索；自定义类型进信号槽时，注册别名要"跟着 moc 的裸类型名"走。
- **场景**：`log_writesToFile` 读文件内容断言 `[Info]` 标签，中文日志是否乱码？
- **排查**：`QTextStream` 默认编码在 Windows 下可能是本地 ANSI（GBK），不指定的话写入文件的中文在 UTF-8 读取时乱码。
- **修复**：`stream.setCodec("UTF-8")` 显式指定。
- **教训**：**凡是 Qt 写文件，先想编码**；`Text` 模式处理换行、`setCodec("UTF-8")` 处理字符集，两个一起设最稳。
