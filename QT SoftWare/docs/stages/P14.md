## 1. 学了什么

1. **QWidget 自绘三件套**：继承 QWidget → 重写 `paintEvent(QPaintEvent*)` → 数据改动后调 `update()` 请求重绘。这是 Qt 最底层的自绘方式（对应 WPF 重写 `OnRender(DrawingContext)`）。
2. **QPainter 绘图命令**：`drawLine/drawRect/drawArc/drawText/drawPath/setPen/setBrush`——相当于 WPF 的 DrawingContext 命令集，但更接近 GDI+。
3. **坐标映射**：值 → 像素的线性映射是曲线控件的核心算法——`y = plot.bottom() - (value-min)/(max-min) * plot.height()`，顶部=最大值、底部=最小值，越界值钳制。
4. **角度系统（大坑）**：Qt 的 `drawArc` 角度单位是 **1/16 度**、0° 在 **3 点钟方向**、正值**逆时针**。表盘从 225° 顺时针扫 270° 到 -45°，所以 `drawArc` 跨度角必须写负数 `-270*16`。
5. **QRadialGradient 径向渐变**：LED 的发光效果用同心圆 + 径向渐变（`lighter → darker`）实现，亮/灭只改状态成员 `m_on`，绘制全权交给 paintEvent——"数据驱动绘制"。
6. **sizeHint/minimumSizeHint**：告诉布局管理器控件"想要多大/最小多大"，布局器据此分配空间（对应 WPF 的 Measure/Arrange）。
7. **契约外扩展**：LineChart 增加了 `minimum()/maximum()` 只读访问器，仅为了让单测能"读回量程"断言——接口契约允许的最小扩展，不影响契约方法。

## 2. 为什么学

- **工业监控 UI 绕不开自绘**：曲线、仪表、LED 这类专业控件没有现成的 Qt 内置控件（QChart 是 Qt Charts 模块，但本项目用 QWidget + paintEvent 自绘，锻炼底层绘图能力，且零额外依赖）。
- **WPF 的 DrawingContext vs Qt 的 QPainter**：这是从 XAML 声明式 + OnRender 命令式 迁到 Qt 的核心映射点。学会了 paintEvent，就掌握了 Qt 里所有"画点东西"的能力。
- **paintEvent 是全 Qt GUI 的基石**：不管控件多复杂，最终都是"重写 paintEvent + 画"。理解它才能看懂 Qt 生态里任何自定义控件。

## 3. Qt 原理（本阶段）

- **paintEvent 是"纯绘制"函数**：里面**绝不能做耗时操作/改数据/触发 update()**——只读取成员画图。数据更新放到业务方法（appendPoint/setValue）里，改完调 `update()` 安排重绘。
- **update() 是异步合并的**：连续调 10 次 `update()`，Qt 只在回到事件循环时**合并成一次重绘**——这就是滚动曲线能高效刷新的原因（数据高频追加，重绘低频合并）。
- **QPainter 必须在 paintEvent 里临时构造**：`QPainter p(this)` 构造函数拿绘制权、析构释放。跨函数保存 QPainter 是经典错误。
- **坐标系统**：默认原点在 widget 左上角，x 向右、y 向下。`QPainter` 提供 `translate/scale/rotate` 变换（对应 WPF RenderTransform）。
- **反锯齿**：`painter.setRenderHint(QPainter::Antialiasing)` 让曲线/圆形边缘平滑（工业界面观感刚需）。

## 4. C++ 原理（本阶段重点）

## 6. 为什么这样设计

1. **数据与绘制解耦**：控件成员只存"数据/状态"（m_data/m_value/m_on），paintEvent 只读成员画图。业务代码（采集线程）调 `appendPoint(v)` 追加数据，`update()` 触发重绘——**数据驱动绘制**，与 WPF 的 `INotifyPropertyChanged` 殊途同归。
2. **状态约束写进类内**：Gauge 的 `m_value` 恒在 `[m_min, m_max]`；`setValue` 对 NaN 用 `qIsNaN` 保护落到下限、越界 `qBound` 钳制——脏数据进不来。
3. **缓冲上限 500 点**：`appendPoint` 超出 `m_maxPoints` 就 `removeFirst` 淘汰最旧点，形成"滚动"效果——内存有界，长时间采集不膨胀。
4. **量程非法输入忽略**：`setRange(min, max)` 仅当 `min < max` 时生效，防止量程反转导致除零/倒挂。
5. **契约外最小扩展**：`minimum()/maximum()` 只读访问器只为了单测能断言"非法 setRange 后量程未变"——扩展要克制，不破坏契约方法。

## 7. 错误案例（真实踩坑）

### 错误案例 1：drawArc 角度方向画反（表盘不显示）

- **现象**：Gauge 的扇形刻度弧画不出来或角度错乱。
- **根因**：Qt 角度单位是 1/16 度（非度）、0° 在 3 点钟、正值为**逆时针**——写 `270` 而不是 `270*16`，或方向写反，弧就"消失/镜像"。
- **修复**：表盘从 225° 顺时针扫 270°，跨度角写 `-270*16`；`valueToAngle = 225 - frac*270`。
- **教训**：**Qt 的角度单位不是度、方向不是数学系**——先读文档把单位与方向写进注释，再画。

### 错误案例 2：paintEvent 里做耗时操作

- **现象**：曲线控件在数据刷新时卡顿、界面假死。
- **根因**：把浮点运算、容器遍历等放进了 paintEvent，而 paintEvent 每次重绘都会执行，高频重绘下累积卡顿。
- **修复**：paintEvent 只做"读成员 + 画"，所有计算在业务方法完成，改完 update()。
- **教训**：**paintEvent 是渲染函数，不是计算函数**。数据准备与绘制分离。

### 错误案例 3：忘记 update() 数据变了但不重绘

- **现象**：调了 `appendPoint(v)` 界面没反应。
- **根因**：修改成员变量不会自动触发重绘——Qt 没有"属性变更通知"机制（WPF 的 INotifyPropertyChanged 是显式的）。
- **修复**：每个修改状态的业务方法末尾调 `update()`。
- **教训**：**Qt 里"数据变了"和"画面刷新"是两个动作**，必须手动 update() 桥接。

## 8. 推荐实践

- 自绘控件三件套：继承 QWidget → paintEvent 绘制 → 数据方法末尾 update()。
- `QPainter p(this)` 局部构造、局部使用；反锯齿 `Antialiasing` 常开。
- 角度用 `qDegreesToRadians` 转换三角函数输入，drawArc 跨度记得 `*16`。
- 状态成员做**类内初始化 + 非法输入忽略**（量程反转、NaN、越界钳制）。
- 缓冲有上限（滚动淘汰），长时间采集内存不膨胀。
- 尺寸给足 `sizeHint/minimumSizeHint`，布局器才知道怎么排。

| 属性变更通知（INPC） | 手动 `update()`（数据与绘制解耦） |

## 10. 本质差异（最重要的一课）

> **WPF 是"声明式 + 数据绑定"：XAML 描述 UI、绑定自动推画面；Qt Widgets 是"命令式 + 手动重绘"：你在 paintEvent 里亲手用 QPainter 画每一笔，数据变了还得自己调 update()。这一课的核心不是"Qt 画图 API 长什么样"，而是**渲染模型从"框架自动刷新"切换到"你决定何时刷新、画什么"**——控制权更大，责任也更大。**

- **数据驱动绘制**：无论哪种框架，画布都是数据的"投影"。Qt 里这个投影由你主动触发（update()），所以"改数据 → 想清楚是否需要重绘 → update()"要成为肌肉记忆。
- **paintEvent 是纯函数式的**：无副作用、只读状态、画完即走——这是 Qt 渲染高性能的秘密，也是新手最容易违反的纪律。
- **自绘不是"缺库的妥协"**：它给你完全控制——工业仪表、曲线特效、性能优化全靠它。掌握了它，Qt Charts/QCustomPlot 都只是"别人写的 paintEvent"。

## 11. Debug / 排错案例

- **场景**：`tst_widgets` 里"越界钳制 150→100"——Gauge setValue(150) 后 value() 应为 100。
- **排查**：`qBound(min, val, max)` 要求 `min <= max`，先 setRange 再 setValue 顺序正确才成立；若量程没设好（min>=max）qBound 行为未定义。
- **修复**：setRange 非法输入直接忽略（不改变量程），保证 qBound 的调用前提永远成立。
- **教训**：**Qt 的工具函数通常要求前置条件**（qBound 需要 min<=max），要么在入口校验，要么在文档写死。
