## 1. 学了什么

1. **Qt 核心值类型**：`QDateTime`（日期 + 时刻）、`QTime`（一天内时刻）、`QString`（Unicode 字符串）。三者都是**值类型**——直接赋值即复制语义，不需要指针/引用去"借"数据。
2. **隐式共享（Implicit Sharing）**：`QString` / `QDateTime` 内部用"写时复制（Copy-On-Write）"共享底层数据，赋值是 O(1) 的浅拷贝，真正被修改时才深拷贝。这让"值传递"不再昂贵。
3. **const 引用入参**：`const QDateTime &dt` 表达"只读、不拷贝、不改调用方"，同时避免每一次传值引起的引用计数增减（refcount churn）。
4. **TryParse 风格**：`bool parseTime(const QString &text, QTime &out)` 用返回值报告成败、出参引用带回结果，且**失败时绝不修改 out**（对应 C# `DateTime.TryParse`）。
5. **`QString::arg` 补零**：`arg(value, 2, 10, '0')` 把数值格式化为固定两位，左侧补 '0'，对应 C# 的 `value.ToString("D2")`。
6. **字符串字面量宏**：`QStringLiteral` / `QLatin1String` 在**编译期**构造字面量，避免运行时的编码转换开销。
7. **数据驱动测试**：`_data()` 函数提供多组输入，`QFETCH` / `QCOMPARE` 消费，一套测试逻辑测多组——对应 NUnit `TestCase`。
8. **自由文本用正则校验**：`nowString()` 是"当前时刻"，无法断言固定字符串，改用 `QRegularExpression` 校验"格式形状"。

## 2. 为什么学

- P2 解决"内存谁负责"，P3 解决"**数据怎么传、怎么格式化**"——Qt 值类型的隐式共享是每个 Qt 程序员每天都会撞见的行为，不懂它就看不懂"为什么 Qt 代码敢到处按值传 QString"。
- 时间工具是**后续所有阶段的地基**：P6 日志时间戳、P6 日志文件按天命名、P8 数据打点串、耗时统计，全部依赖本阶段的格式化 / 解析 / 间隔换算。
- 对应 C# 的 `DateTime` / `TimeSpan` / `string` 这一套"日常工具箱"：先用最熟悉的时间域把 Qt 值类型练熟，后面业务代码才不卡壳。

## 3. Qt 原理（本阶段）

- **`QDateTime` = `QDate` + `QTime`**：`QDateTime(QDate(2026, 8, 14), QTime(9, 30, 12, 123))` 可构造**固定时刻**，这让单测能断言精确的格式化结果（C# 里要构造固定时刻更繁琐）。
- **格式串（format string）**：`"yyyy-MM-dd HH:mm:ss.zzz"` 里 `yyyy/MM/dd/HH/mm/ss/zzz` 是 Qt 专有字母；`.zzz` 固定输出 3 位毫秒并**自动补零**，保证数据列宽对齐。
- **`QTime::fromString` 的严格性**：Qt 5.12 中 `fromString` 遇到格式之外的多余字符（如 `"09:30:12.123"` 里的 `".123"`）会**直接失败、不做截断**。因此 parseTime 能先试 `"HH:mm:ss"`、失败再试 `"HH:mm:ss.zzz"`——带毫秒的输入天然落到第二次尝试，不会被"截断误解析"。
- **`msecsTo` 的方向语义**：`start.msecsTo(end) = end - start`，结果可为负；`end` 早于 `start` 时为负值，相同时刻为 0。这是 `elapsedMicros` 返回正负两种值的依据。
- **数据驱动测试**：`QTest::addColumn<T>("列名")` 定义表结构，`QTest::newRow("行名") << 值1 << 值2` 填行，测试函数用 `QFETCH(T, 变量)` 取出——Qt Test 会为每一行生成一条独立用例记录。
- **`QRegularExpression`**：`^\\d{4}-\\d{2}-\\d{2} \\d{2}:\\d{2}:\\d{2}\\.\\d{3}$` 校验字符串整体形状，`re.match(s).hasMatch()` 判断是否匹配——适合校验"值不可预知、只能校验格式"的场景。

## 4. C++ 原理（本阶段重点）

| 机制 | 说明 | 与 C# 对比 |
|------|------|-----------|
| 值类型 | `QDateTime`/`QTime`/`QString` 赋值即复制语义 | C# 的 `DateTime`/`TimeSpan` 是 struct（值类型）；`string` 是引用类型但不可变 |
| 隐式共享 | 浅拷贝 + 写时复制，赋值 O(1) | C# `string` 引用共享 + 不可变，行为"感觉像"但不完全等同 |
| const 引用 | `const T &x` 只读不拷贝 | C# 的 `in` 参数（较新） |
| TryParse 风格 | 返回值报成败 + 出参带结果 | `DateTime.TryParse` / `int.TryParse` |
| 匿名命名空间 | `.cpp` 文件内私有常量 | `private const` |
| 静态方法工具类 | 无状态纯函数 | `static class` |

## 6. 为什么这样设计

1. **工具类用静态方法**：无状态纯函数，最简单可靠，对应 C# `static class`；不碰 UI/IO，边界清晰，最适合教学。
2. **入参一律 const 引用**：`const QDateTime &dt` 明确"只读、不拷贝"，也避免隐式共享的引用计数无谓增减——这是 Qt 值类型入参的默认选择。
3. **TryParse 风格"失败不碰 out"**：解析失败只返回 `false`，绝不修改出参。单测 `parseTime_invalidKeepsOut` 专门预设初值验证"不被污染"。
4. **格式串集中到匿名命名空间常量**：`kDateTimeFormat` / `kFileTimestampFormat` 一处定义，避免魔法字符串散落，后续改格式只动一处。
5. **补零用 `arg(value, 2, 10, '0')`**：复用 Qt 的格式化能力，而不是手工 `"0" + value` 拼字符串——宽于两位时自动输出更多位，行为更正确。
6. **测试数据驱动 + 边界覆盖**：正常值、带毫秒、非法输入、空串、负数、0 间隔全覆盖，把真实场景的脏输入提前圈出来。

## 7. 错误案例（真实踩坑）

### 错误案例 1：文件被误写到 `D:\Gemi\QT Soft Ware\`（路径多一个空格）

- **现象**：TimeUtils 专项 Agent 把 `timeutils.h/cpp` 写到了 `D:\Gemi\QT Soft Ware\` 下，而工程真实目录是 `D:\Gemi\QT SoftWare\`（"SoftWare" 之间**没有**空格）；构建系统找不到新源文件，`tst_timeutils` 没有进入编译。
- **根因**：Windows 目录名允许包含空格，真实目录名 `QT SoftWare` 与误写路径 `QT Soft Ware` 仅一个空格之差，肉眼极易忽略；多 Agent 并行时，专项 Agent 以"记忆中的路径"写盘，没有先校验目标目录真实存在。
- **修复**：主 Agent 在评审阶段发现该文件不在工程树内，将其复制回正确目录 `D:\Gemi\QT SoftWare\DataScope\src\utils\`，并在 CMakeLists 中确认 `tst_timeutils` 正常注册。
- **教训**：**写文件前先验证目标目录存在**（`ls` / `Test-Path`）；涉及带空格的目录名时，路径必须精确书写、避免凭记忆拼接。

## 8. 推荐实践

- 传参默认 `const T &`；需要输出用引用出参；能返回值就返回值（配合隐式共享的 O(1) 拷贝）。
- 值类型不要裸用指针；`QString`/`QDateTime` 按值传、按 const 引用收，都是标准姿势。
- 解析类接口统一走 **TryParse 风格**：返回值报成败、出参带结果、失败不碰出参。
- 字符串拼接优先 `QString::arg`（可补零、可链式），少用 `+` 拼。
- 测试覆盖三类输入：正常值、边界（空串/负数/0）、脏输入（带毫秒、格式外字符）。
- 校验"值不可预知"的自由文本（如当前时刻）用正则校验格式形状，而不是断言固定串。

## 10. 本质差异（最重要的一课）

> **C# 的"值类型"拷贝昂贵但语义简单；Qt 的"值类型"用隐式共享把"拷贝"变成了 O(1) 的偷懒——但这份偷懒是建立在"写时复制"之上的，一旦被修改就会悄悄深拷贝。**

- C# 里 `string a = b;` 是引用共享（不可变所以安全）；`DateTime a = b;` 是真拷贝。
- Qt 里 `QString a = b;` 两者都不是纯粹任一方——它先**共享**底层数据，只有某一方**要改**时才深拷贝。对调用方来说"看起来像值类型"，对性能来说"大部分时间像引用传递"。
- 这条差异直接决定了 Qt 的传参风格：**默认按值传都不可怕，但按 const 引用传更显专业**——它显式声明"我不改你，也请你别多扣引用计数"。后续 P6 `LogManager`、P7 `ConfigManager` 的所有入参都沿用这一约定。

## 11. Debug / 排错案例

- **场景**：`formatDateTime_format` 单测断言 `"2026-08-14 09:30:12.123"`，首次运行失败。
- **排查**：`QCOMPARE` 输出期望值/实际值，发现是毫秒 `123` 输出成了 `12`——格式串里写成了 `"zz"` 而不是 `"zzz"`。
- **修复**：改为 `"zzz"`，`.zzz` 固定输出 3 位毫秒并补零。
- **教训**：Qt 格式串的 `z` 个数决定毫秒位数；`QCOMPARE` 直接给出期望/实际两列，是定位这类问题的利器。写格式串前先查 Qt 文档的 Date/Time Format 表。
