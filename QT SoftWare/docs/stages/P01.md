## 1. 学了什么

1. **Qt 是什么**：一个 C++ 框架 + 工具链 + IDE 生态，核心是 QObject 对象模型。
2. **Qt 模块体系**：QtCore（基础）/ QtGui（窗口系统抽象）/ QtWidgets（控件）。本阶段仅链接这三个模块。
3. **QApplication**：GUI 程序的全局对象，管理与 GUI 相关的一切（事件循环、剪贴板、样式、字体）。
4. **QMainWindow**：主窗口骨架，自带菜单栏/工具栏/状态栏/停靠区域。
5. **事件循环**：`app.exec()` 进入循环，由 Qt 分发事件驱动信号槽与定时器。
6. **CMake 组织 Qt 工程**：`find_package(Qt5)` + `AUTOMOC/AUTORCC/AUTOUIC` + `target_link_libraries`。
7. **MinGW 工具链**：g++ 编译器 + Qt 自带的 mingw73_64 套件。
8. **Q_OBJECT / moc / AUTOMOC**：头文件里的 Q_OBJECT 触发元对象编译器。

## 2. 为什么学

## 3. Qt 原理（本阶段核心）

### 3.1 QApplication 与事件循环

```cpp
QApplication app(argc, argv);   // ① 构造：初始化 GUI 子系统
MainWindow window;              // ② 创建窗口（此时还未显示）
window.show();                  // ③ 显示
return app.exec();              // ④ 进入事件循环（阻塞）
```

- `exec()` 是一个**阻塞调用**：它在一个 `while(true)` 中不断取事件、分发事件，直到所有窗口关闭。
- 这正是 WPF `Application.Run()` 的等价物。Qt 的一切"看似同时发生"（定时器、网络、用户点击）其实都是这个循环在推动。

### 3.2 窗口与 QMainWindow

- `QMainWindow` 预置了四个区域：`menuBar()` / `toolBar` / `statusBar()` / 中央区。
- 本阶段未用这些区域，P5 填充。

### 3.3 Q_OBJECT 与 moc

- 头文件写 `class MainWindow : public QMainWindow { Q_OBJECT ... }`。
- CMake 的 `AUTOMOC ON` 会在编译前调用 `moc`（Meta-Object Compiler）扫描含 Q_OBJECT 的头文件，生成 `moc_mainwindow.cpp`，实现元对象代码（信号槽索引、属性、类型信息）。
- 这相当于 C# 编译器的"编译器生成"（partial class、反射元数据）——**Qt 用"代码生成"实现元编程，而不是运行时反射**。

## 4. C++ 原理

- `MainWindow window;` 创建在**栈上**，main 结束自动析构——这是 RAII 的体现：**不需要手动 delete**。
- `Q_DISABLE_COPY(MainWindow)`：删除拷贝构造与拷贝赋值。QObject 语义上"不可复制"（对象有身份、有父子关系），这与 C# 的引用类型完全不同——C# 随便拷贝引用，C++ QObject 直接禁止。
- `#include` 组织：工程内用 `#include "ui/mainwindow.h"`，通过 `target_include_directories` 把 `src` 加入头文件搜索路径。

## 6. 为什么这样设计

1. **CMake 而非 qmake**：现代 Qt 主流、社区与就业趋势、与 Qt6 一致。虽然本机是 Qt5.12，但 CMake 工程可在 Qt6 下复用（只需改 find_package 名字）。
2. **分层目录**：`app/ui/domain/...` 按职责分，而非按类型分，为后续 P5-P15 的模块挂载预留位置。
3. **WIN32_EXECUTABLE TRUE**：Windows 下以 GUI 子系统链接，启动不弹控制台黑窗。
4. **栈上创建窗口**：展示 RAII 心智模型；后续需要跨函数存活的对象再改堆 + 父子挂接。
5. **构建目录独立 `build/`**：源码与产物分离，`.gitignore` 排除，保证仓库干净。

## 7. 错误案例（重要！真实踩坑）

### 错误案例 1：中文路径导致 moc 崩溃

- **现象**：AUTOMOC 阶段失败，报错 `Warning: Failed to resolve include "D:/Gemi/QT??/DataScope/build/DataScope_autogen/moc_predefs.h"`，`QT??` 处的中文"软件"变成乱码。
- **为什么能编译**：不会编译——直接在 moc 阶段失败。
- **为什么运行时出问题**：无（编译就挂了）。
- **根因**：Qt 5.12 的 MinGW 工具链（moc/g++）在 Windows 上以 ANSI 编码处理路径，源码路径含非 ASCII 字符（"软件"）时路径解析乱码。这是 **Qt MinGW 的已知限制：工程路径必须纯 ASCII**。
- **正确写法**：工程根目录 `QT软件` 改名 `QT SoftWare`（纯 ASCII + 空格），问题立即消失。
- **验证**：同一工程在 `C:\DsTest`（无中文）编译通过，在中文路径失败，证明根因。

### 错误案例 2：双击 exe 报"找不到 Qt5Widgets.dll"

- **现象**：构建成功后直接双击 `DataScope.exe`，弹出"由于找不到 Qt5Widgetsd.dll，无法继续执行代码"。
- **根因**：Qt 程序运行时动态链接 Qt 的 DLL（Qt5Core/Qt5Gui/Qt5Widgets 及其 platform 插件 qwindows）。开发机这些 DLL 在 `D:\Qt\5.12.2\mingw73_64\bin`，但**不在 exe 目录、不在系统 PATH**，双击自然找不到。
- **错误验证**：我之前用 `Start-Process` 只检查"进程是否存活"，结果进程因**错误弹窗挂起**而被误判为"运行正常"——这是本次验证方法的漏洞。
- **正确做法**：
  1. 用 Qt 官方 `windeployqt --dir <exe目录> <exe>` 部署运行库（DLL + platforms + 翻译文件）；
  2. 验证时检测 `MainWindowTitle`（真正出现窗口）而非进程存活。
- **工程化收尾**：把 windeployqt 写进 CMake 的 `POST_BUILD`，此后每次构建自动部署，双击即跑。
- **教训**：GUI 程序"能启动"≠"正常显示窗口"；验证 GUI 必须检查窗口句柄/标题。

### 错误案例 3：pip 安装的 cmake 位置

- `pip install --user cmake` 装到 `AppData\Roaming\Python\Python310\Scripts\`，不在 PATH，直接调用报错。
- 解法：用全路径调用，或 `python -m pip` 验证。

## 8. 推荐实践

- **Qt 工程路径一律纯 ASCII**（英文/数字/下划线/空格），中文只出现在文档和 UI 文案里。
- 用 CMake + Ninja 做命令行构建（快、可脚本化），QtCreator 负责编辑与调试。
- 每阶段编译后立即运行验证（启动→存活→关闭），不留"最后一刻才跑"的隐患。

## 9. WPF 对照

| WPF / C# | Qt / C++ | 备注 |
|----------|----------|------|
| `App.xaml` + `App.xaml.cs` | `main.cpp` + `QApplication` | 入口与全局对象 |
| `Application.Run()` / `ShowDialog` | `app.exec()` 事件循环 | 都阻塞并驱动 UI |
| `MainWindow.xaml` | `MainWindow` 类 + C++ 代码 | XAML vs 代码构建 |
| `.csproj` | `CMakeLists.txt` | 工程描述 |
| NuGet 引用 | `find_package(Qt5)` + `target_link_libraries` | 依赖管理思路相同 |
| 反射 / 编译器生成 | moc + Q_OBJECT | 元编程方式不同 |
| WinExe 输出 | `WIN32_EXECUTABLE` | 无控制台窗口 |

## 10. Qt 与 WPF 的本质差异（本阶段领悟）

1. **UI 声明方式**：WPF 用 XAML（声明式），Qt Widgets 用 **C++ 代码构建**（命令式）。没有"设计器自动绑定"，UI 结构要靠代码可读性维护。
2. **对象生命周期**：C# 一切是堆上引用 + GC；C++ 栈对象由作用域管理（RAII），QObject 对象树在 P4 深入。
3. **元编程时机**：WPF/反射在运行时，Qt 的 moc 在**编译时**生成代码。

## 11. Debug / 排错案例

- **场景**：AUTOMOC 失败、路径显示 `QT??`。
- **排查链**：看 build 日志 → 发现 moc 命令的 `-I` 路径含 `QT??` → 联想到中文路径 → 在无中文路径复制工程测试通过 → 定位为中文路径问题 → 改名解决。
- **教训**：遇到"乱码/问号"类错误，第一时间怀疑**编码与路径**。
