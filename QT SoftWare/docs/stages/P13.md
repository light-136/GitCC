## 1. 学了什么

1. **显式状态机建模**：设备连接是典型的状态机（未连/连接中/已连/出错）。用一个枚举 + 转移函数显式管理，比散落的 bool 标志（isConnected + isAcquiring...）可靠得多——对应 C# 里用状态模式或状态枚举管理连接。
2. **状态转移的四类驱动**：用户操作（connect/disconnect）、外部事件（TCP connected/error/disconnected）、定时器（重连）、以及"状态不变不发信号"的幂等保护（setStatus 里 `if (m_status == s) return`）。
3. **主动断开 vs 意外断线的语义判别**：DataService 的 `disconnected` 信号在两种情况下都触发，控制器必须用 `m_userDisconnected` 标志区分——主动断开安静退出，意外断线进 Error 并自动重连。
4. **退避重连策略**：1s→2s→4s→...封顶 30s，防止重连风暴（对应工业上位机"设备离线自动恢复"的标准做法）。
5. **错误降级路径**：连接失败/断线/通信异常 → Error + errorOccurred 字符串透传（UI 状态栏 + 日志），帧校验失败由 P10 解析器静默丢弃（不污染上层）。

## 2. 为什么学

- 工业现场设备随时可能掉线（断电、网线松动、设备复位），"能自动恢复"是可靠性的分水岭。
- 状态机让"连接"这个复杂时序变得可测试、可推理——6 个强制项全部 QSignalSpy/QTRY 验证，比人肉点界面可靠得多。

## 3. Qt 原理（本阶段）

- **QTimer::setSingleShot(true)**：重连定时器单次触发，每次超时由槽决定是否再起——避免周期定时器在 Error 态反复空转。
- **QSignalSpy 参数类型注册**：`statusChanged(datascope::domain::DeviceStatus)` 的参数是命名空间内 enum class，QSignalSpy 必须 `qRegisterMetaType`（三种名字别名）才能取出参数值，否则警告"Unable to handle parameter"且参数为空。
- **对象树析构安全**：DeviceController 的 DataService/QTimer 都是 child，随控制器析构自动回收；DataService 析构会安全退出采集线程（quit+wait）。

## 4. C++ 原理（本阶段重点）

| 机制 | 说明 | 与 C# 对比 |
|------|------|-----------|
| `enum class` | 强类型枚举（不隐式转 int） | `enum`（C# 9 后相似） |
| 退避 `min(1s << n, 30s)` | 位运算实现指数退避 | `Math.Min` |
| 幂等 setter | 状态不变不发信号 | 属性 setter 判等 |
| lambda 捕获 `[&]` | 引用捕获外围变量（计数器等） | 闭包捕获 |

## 5. 踩坑与修复

1. **QSignalSpy 无法处理 enum class 参数**（警告 "Unable to handle parameter"）：`statusChanged(DeviceStatus)` 参数取不出 → `toInt()` 得 0 → 断言失败。修复：`Q_DECLARE_METATYPE(DeviceStatus)` + initTestCase 注册 裸名/相对名/全限定名 三种别名。
2. **连接失败到 Error 超过 3s**（实测最快 ~3.3s）：Windows 对"刚释放的 LISTEN 端口"约 2s 才回 RST，叠加线程投递。修复：等待放宽到 6s（与 tst_tcpclient 的 5s 同源教训）。
3. **worker 残留 m_client 吞重连**（P12 遗留缺陷）：错误时不销毁客户端，`start()` 的 `if (m_client) return` 让重连永远发不出去。修复：errorOccurred 时 `deleteLater` + 置空（在 P12 阶段末完成，P13 重连测试验证生效）。
