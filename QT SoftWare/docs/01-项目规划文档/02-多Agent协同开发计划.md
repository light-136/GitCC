## 一、协作模型总览

```
                      主 Agent（本会话 = Project Lead / Architect）
                          │
        ┌─────────────────┼─────────────────┐
        ↓                 ↓                 ↓
     专项 Agent A      专项 Agent B      专项 Agent C ...
   （按阶段动态创建，职责见下表）
        ↓                 ↓                 ↓
  └───────────────┬───────────────┬─────────┘
                  ↓
            主 Agent Review
        （编译/架构/API/线程/生命周期/错误/测试/文档）
                  ↓
              Merge → Build → Test
                  ↓
             进入下一阶段
```

### 主 Agent（我）职责
1. 总体架构与技术决策，唯一可修改总体架构者。
2. 阶段拆分、并行编排、**接口契约先行**。
3. Git 管理、文件所有权划分（避免冲突）。
4. 统一编译（单一 build 目录，串行执行，杜绝并发构建冲突）。
5. 专项 Agent 产出 Review → 修复要求 → Merge。
6. 集成测试、最终验收、文档汇总。

### 专项 Agent 铁律
- **不得擅自修改总体架构**；发现更优方案 → 提交《架构变更建议》（原设计/新设计/原因/优缺/影响面），由主 Agent 决策。
- **只写分配给自己的文件**，禁止碰其他 Agent 的文件与共享文件（CMakeLists 由主 Agent 集成）。
- 测试 Agent 独立于开发 Agent，用"找问题"视角验收，禁止"自写自测"。

## 二、并行度矩阵（P1→P15）

> 原则：**有依赖→串行；无依赖→并行；接口已定→可并行；接口未定/冲突风险高→不并行。**

| 阶段 | 并行度 | 专项 Agent | 串行/并行决策依据 |
|------|--------|-----------|-------------------|
| P1 环境与骨架 | 低 | 无 | 架构未定、环境未稳，主 Agent 串行夯实 |
| P2 C++筑基 | 中 | `U1`工具库、`T1`测试、`D1`教学(WPF→C++对照框架) | utils 各文件独立；教学文档基于需求先行 |
| P3 Qt类型 | 中 | 同 P2 三个 Agent | 文件独立、接口=纯函数 |
| P4 信号槽 | 低 | `D2`教学(信号槽原理/错误案例) | 教学重点、风险高，主 Agent 示范 |
| P5 UI主窗口 | 中 | `U2`UI(页签/Dock/QSS)、`D3`教学(QSS/布局) | MainWindow 集成由主 Agent 做，避免页签冲突 |
| P6 日志 + P7 配置 | **高** | `G1`日志、`G2`配置、`T2`测试、`D4`教学 | 两模块完全独立；接口预定义后并行 |
| P8 Domain+Model/View | **高** | 先主 Agent 定领域模型接口 → `M1`Model/View、`T3`模型测试、`D5`教学 | 接口确定后 UI/Test/Doc 三线并行 |
| P9 串口 + P10 协议 | **高** | `C1`协议引擎、`C2`串口、`T4`协议测试 | 先定帧格式契约；P9 串口做"回环收发"不依赖协议 |
| P11 TCP+模拟设备 | 中 | `S1`模拟设备、`N1`TCP客户端、`T5`集成 | 依赖 P10 协议；模拟设备与客户端可并行 |
| P12 多线程 | 低 | `D6`教学(线程/QA文档) | 线程风险最高，主 Agent 亲写并统一验收 |
| P13 状态机 + P14 控件 | **高** | `S2`状态机、`W1`自绘控件(曲线/仪表/LED) | 控件不依赖状态机，天然可并行 |
| P14 监控页 | 高 | `U3`监控页、`T6`控件测试、`D7`教学 | DataService 接口已定，三线并行 |
| P15 集成冻结 | 集成冻结 | `A1`部署、`T7`集成/冒烟、`D8`总结/报告 | 停止新增功能，串行收口 + 并行 QA/文档 |

## 三、文件所有权隔离（防冲突核心）

- **共享文件（仅主 Agent 可写）**：顶层 `CMakeLists.txt`、`src/app/main.cpp`、`src/ui/mainwindow.cpp/h`、`resources/resources.qrc`。
- **专项 Agent 专属文件**：按阶段分配（例：`G1`只写 `infrastructure/logmanager.*` + `ui/pages/logpage.*` + 对应测试；`G2`只写 `infrastructure/configmanager.*` + `ui/pages/settingspage.*`）。
- **冲突规避**：任何 Agent 的新增文件需在主 Agent 登记的"文件登记表"中认领，先到先得；需要修改共享文件时，提出修改需求由主 Agent 落笔。
- **构建目录**：全局仅一个 `DataScope/build/`，只有主 Agent 执行编译。

## 四、接口契约先行

凡并行点，主 Agent 先发布接口契约文件（写入阶段文档），专项 Agent 依契约开发，不越界：

| 契约 | 内容 | 前置阶段 |
|------|------|---------|
| 领域模型接口 | Device/Channel/DataPoint/AlarmRule 的字段与 getter | P8 前 |
| 帧格式契约 | SOF/FUNC/CMD/LEN/DATA/CRC 的字节布局 | P9/P10 前 |
| 数据总线接口 | DataService 的 signal 签名（dataUpdated 等） | P12 前 |
| 状态机事件集 | 状态枚举与转换事件 | P13 前 |

## 五、质量保障双轨

1. **开发轨**：专项 Agent 写功能 + 自带基本测试。
2. **测试轨**：独立 `T*` 测试 Agent 以"找问题"视角补充边界/异常/生命周期用例，负责断言通过。
3. **主 Agent Review 清单**：能编译 → 符合架构 → Qt API 正确 → 线程安全 → 生命周期正确 → 错误处理完整 → 测试存在且真实 → 文档与代码对应。
4. 禁止：空壳类 / TODO 冒充 / 只写名字的测试 / 文档与代码不符。

---

## 六、集成冻结（P15）

停止新增功能 → 所有 Agent 提交 → 主 Agent 合并 → 完整 Build → 完整 Test → 修复 → 再 Build/Test → Release → windeployqt → 无 Qt 环境验证。

---

## 七、最终报告增加《Agent 协作报告》

包含：主 Agent 职责 / 各专项 Agent 职责 / 并行任务清单 / 串行任务清单 / 各 Agent 发现的问题 / 经 Review 的代码清单 / 冲突与解决 / 最终合并代码 / 最终测试负责人。
