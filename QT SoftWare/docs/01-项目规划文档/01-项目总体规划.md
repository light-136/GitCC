## 〇、规划摘要（一句话）

> 以一个 **具有真实工业价值的「多通道数据采集与实时监控系统」** 作为载体，
> 用 WPF/C# 作为认知锚点，把 Qt 的核心知识体系（对象系统 / 信号槽 / 事件循环 / Model-View / 线程 / 网络 / 串口 / 状态机 / 配置 / 日志 / 测试 / 部署）**全部融入一个可运行、可测试、可发布、可扩展的中大型工程** 中学习。

**文档先行，代码在后。** 本文只做总体规划，不写业务代码。

## ① 项目选型

### 1.1 项目名称

- 中文名：**DataScope Studio —— 工业多通道数据采集与实时监控系统**
- 英文名：**DataScope Studio (Industrial Multi-Channel Data Acquisition & Monitoring System)**
- 形态：Windows 桌面应用，Qt Widgets + C++17 + CMake

### 1.2 一句话定位

> 通过 **串口 / TCP** 连接多台工业设备，按 **自定义通信协议** 完成数据采集、协议解析、实时展示（表格 / 曲线 / 仪表）、**报警、数据记录与历史回放** 的一站式监控上位机软件。

### 1.3 技术选型表

| 维度 | 选型 | 选型理由 |
|------|------|----------|
| 语言 | C++17 | 现代 C++，与 Qt 完全匹配，覆盖 RAII / move / 智能指针 |
| GUI 框架 | Qt 6.x **Widgets** | 学习 Qt 正统路径；Widgets 是 Qt 工程的主力，Model/View 机制完整 |
| 构建 | **CMake**（对比 qmake） | 现代 Qt 官方推荐，就业与工程主流 |
| 通信 | Qt Network + Qt SerialPort | 覆盖需求文档第十四、十五节 |
| 并发 | QThread + moveToThread、QThreadPool、QtConcurrent | 完整覆盖需求文档第十二节 |
| 曲线/仪表 | **自绘 QWidget**（paintEvent） | 以"自定义控件 + 事件系统"为教学点，同时发布无需第三方闭源库 |
| 配置 | QSettings(INI) + JSON | 需求第十七节 |
| 日志 | 自研 LogManager（分级 + 轮转） | 需求第十八节 |
| 存储 | CSV + 二进制文件 | 需求第十六节 |
| 测试 | Qt Test + CTest + 模拟设备 | 需求第二十三节 |
| 部署 | windeployqt + 发布目录规范 | 需求第二十四节 |

### 1.4 关键工程决策

1. **自带"模拟设备"程序**：由于学习环境没有真实硬件，本项目同时开发一个用 `QTcpServer` 实现的虚拟设备，按真实协议应答。这样**每个通信阶段都能在没有硬件的情况下运行验证**（也满足项目规范第 9 条"运行起来看有无错误"）。
2. **曲线控件自绘**：第一版自己绘制实时曲线（paintEvent + QTimer），文档中说明工业界常用 QCustomPlot / QCharts 作为后续替换方案。
3. **模块边界清晰**：UI / 控制器 / 服务 / 领域 / 协议 / 基础设施严格分层，天然支撑 15 个阶段的教学推进。

### 2.3 为什么"正好"是它

1. **规模合适**：中大型，能支撑 15 个阶段、每阶段独立验证，又不会大到失控。
2. **与你的工业背景自然衔接**：设备、协议、采集、监控正是你的领域，学习迁移成本低；但它**不是** GD32 升级工具的简单复制，而是全新的上位机形态，避免"用旧经验套新框架"。
3. **每个 Qt 知识点都有"不得不用的理由"**：例如没有 Model/View 就无法高效刷新实时数据表格、没有跨线程信号槽就无法把采集线程数据送到 UI——知识是**长出来的**，不是硬塞的。
4. **可运行、可演示**：模拟设备保证全程能跑起来，最终验收时也能现场演示完整流程。
5. **发布与扩展干净**：自绘曲线、无第三方闭源依赖，发布包最小化。

> 注：按需求第 29 节原则，个别无合理场景的知识点（如 XML、QUdpSocket、QStateMachine 正式采用）只做原理介绍 + 对比，**不强塞进项目**，在文档中明示。

### 3.2 交互效果

- **添加设备**：弹窗选择通信方式（串口/TCP）、填写参数、配置 N 个采集通道（名称/单位/缩放/报警阈值）。
- **启动采集**：状态栏变绿，每台设备由独立线程按周期轮询；实时表格每秒刷新（Model/View 增量更新）；曲线滚动推进；LED 指示灯按通信状态变色。
- **断线/超时**：设备状态机进入 Error → 自动 Retry（可配次数与间隔），日志记录，状态栏变红，曲线停止但不丢 UI。
- **报警**：数值越限 → 报警条目插入报警表 + 声音提示 + 曲线打标。
- **历史回放**：选择时间范围，从记录文件加载并重放到表格与曲线，支持导出 CSV。
- **关闭软件**：自动保存工程配置、优雅停止采集线程（join，无泄漏、无崩溃）。

### 3.3 非功能效果

- 启动 < 1s，UI 不卡顿（采集在后台线程，UI 线程只收数据刷新）。
- 日志 24h 不爆盘（轮转策略）。
- 单机可管 8~32 台设备，单设备 8~64 通道。
- 打包后拷贝到无 Qt 环境的 Windows 电脑双击即运行。

### 5.3 线程模型

```
┌────────────────────────── GUI 线程（主线程） ──────────────────────────┐
│  QApplication + 事件循环                                                │
│  MainWindow │ Controllers │ DataService │ 各 Model │ 曲线/表格/日志页     │
│  · 只在本线程创建和操作 QWidget（Qt 铁律）                               │
└──────────▲──────────────────────────▲──────────────────────────────┘
           │ QueuedConnection         │ QueuedConnection
   dataUpdated / logPosted          (信号跨线程自动排队，绝不直接跨线程调UI)
           │                          │
┌──────────┴──────────────────────────┴──────────────────────────────┐
│  采集工作线程（每台设备一个 Worker 对象，moveToThread）                 │
│  设备A Worker │ 设备B Worker │ ...                                    │
│  · 持有 QSerialPort/QTcpSocket（在本线程创建/使用）                    │
│  · QTimer 轮询 → 发送请求 → 等待应答 → 解析 → emit 数据信号              │
└─────────────────────────────────────────────────────────────────────┘
线程安全：跨线程共享数据一律用 QMutex / 信号槽参数拷贝 / 不可变对象传递；
         队列式信号槽是线程间通信的第一手段（对比 C# Dispatcher.BeginInvoke）。
```

### 5.4 设备通信状态机（M04/M08 核心）

```
        open()成功                   首帧解析成功
 Idle ───────────▶ Connecting ─────────────▶ Connected ──── 启动采集 ────▶ Running
  ▲                  │ 失败/超时                 │ 断线/超时                   │ 断线/超时
  │                  ▼                          ▼                            ▼
  └──────── Error ◀──────────────────────────────┴───────────────────────────┘
     │ 重试次数 < N      │ 重试次数 ≥ N
     │                  ▼
     │             Failed（提示用户，需人工干预）
     ▼
  Retry(延迟后回 Connecting) ── 重连成功 → Connected
状态与事件：状态机把"收发数据的时序逻辑"集中化，避免 if 嵌套地狱（对比 WPF 中手写 enum+switch）。
超时均由 QTimer::singleShot 驱动（对比 C# CancellationTokenSource.CancelAfter 的思路）。
```

## ⑧ WPF → Qt 映射

### 8.1 可直接类比（迁移锚点）

| WPF / C# | Qt / C++ | 类比程度 | 关键差异提醒 |
|----------|----------|---------|-------------|
| Window | QMainWindow / QWidget | ★★★ | Qt 无 XAML，UI 靠代码或 Designer 生成 C++ |
| UserControl | QWidget | ★★★ | 一切 UI 都是 QWidget，组合即继承布局 |
| XAML + 资源字典 | Designer + .qrc 资源 | ★★★ | 属性和事件都在 C++ 代码里 |
| DataContext + Binding | Model + 信号槽手动刷新 | ★★☆ | Qt 没有自动绑定引擎，需手动连接 |
| ICommand | QAction / 信号槽 | ★★★ | QAction 自带图标/文本/触发 |
| INotifyPropertyChanged | 数据变化信号 | ★★★ | 更直白：字段变了就 emit |
| ObservableCollection | QList/QVector + 模型 | ★★☆ | Qt 用模型通知视图，不是集合自身 |
| Dispatcher | QEventLoop + QueuedConnection | ★★★ | 跨线程投递对象类似，但 QObject 亲和线程是铁律 |
| async/await | 信号槽 / QFuture | ★★☆ | 没有语言级 await，用回调链/状态机表达 |
| CancellationToken | 原子标志 + 状态机 | ★★☆ | 需自行设计取消协议 |
| DispatcherTimer | QTimer | ★★★ | QTimer 依赖事件循环驱动 |
| SerialPort | QSerialPort | ★★★ | 事件驱动 readyRead，非同步读 |
| TcpClient / NetworkStream | QTcpSocket / QIODevice | ★★★ | QIODevice 统一读写抽象 |
| DataGrid | QTableView + QAbstractTableModel | ★★☆ | 必须实现模型，绑定是显式的 |
| Style / 触发器 | QSS | ★★☆ | QSS 是 CSS 子集，无 DataTrigger |
| app.config | QSettings | ★★★ | Qt 用 INI/注册表/JSON |
| NLog / log4net | qDebug + 自研 LogManager | ★★☆ | 需自建分级/轮转 |
| NuGet | vcpkg / CMake FetchContent | ★★★ | 概念相同，命令不同 |

### 8.2 不可类比（必须切换思维的地方）⚠️

1. **内存管理**：C# 靠 GC，Qt 靠 **Object Tree + parent 自动析构**；堆对象生命周期由父子关系决定，`deleteLater()` 配合信号槽使用。RAII 是 Qt/C++ 的第一性原理。
2. **没有语言级异步**：C# 有 `async/await` 语法糖；Qt 用**事件驱动 + 信号槽回调 + 状态机**表达异步，这是设计思维的不同，不是简单 API 替换。
3. **UI 线程规则**：WPF 强调"UI 只能在 Dispatcher 线程"，但跨线程调用会被包装/检查；Qt 是**硬性约束**——非 GUI 线程绝不允许创建/操作任何 QWidget，否则是未定义行为（崩溃），必须靠 QueuedConnection 投递。
4. **绑定机制**：WPF 的数据绑定是声明式的（XAML 里自动同步）；Qt 的 Model/View 需要**显式实现模型接口**（data/rowCount...）并手动发 `dataChanged`。没有"魔法"，更接近底层。
5. **事件路由**：WPF RoutedEvent 自动冒泡/隧道；Qt 事件是**按对象分发**，要靠 `eventFilter` 拦截或重写 `event()`，没有全局路由表。
6. **UI 定义方式**：WPF 分离 XAML 与 code-behind；Qt Widgets 常用**纯 C++ 代码构建 UI**（Qt Designer 生成的是 C++），没有"声明式"层，习惯差异大。
7. **接口/依赖注入**：C# 有语言级 interface + DI 容器；Qt/C++ 用**抽象基类 + 虚函数 + 构造注入**，DI 容器在 Qt 生态不流行。

> 详细展开（含代码级对比）在 `04-WPF转Qt对照指南/` 中随阶段建立。

## ⑩ 每阶段学习目标

> 每阶段交付后附《阶段小结》：本阶段 Qt 知识 → 代码位置 → 运行验证 → 练习 → 与 WPF 对比。

### P1 环境搭建与工程骨架
- **目标**：装好工具链；理解 `main.cpp`、`QApplication`、`QMainWindow` 关系；理解 CMake 如何描述一个 Qt 工程（target/include/link）。
- **Qt 知识**：Qt Creator/CMake、`.pro` vs `CMakeLists.txt`、Debug/Release、构建目录。
- **WPF 对照**：`main.cpp` ≈ `App.xaml.cs` 里的 `[STAThread] Main()`；`CMakeLists.txt` ≈ `.csproj` + NuGet。
- **产出**：可运行的空白主窗口。

### P2 C++ 现代特性筑基
- **目标**：掌握值语义/引用/const/const 引用；**RAII 思维**；unique_ptr/shared_ptr/weak_ptr；move 语义；lambda；STL 容器。
- **核心**：反复解释"C# GC vs C++ RAII"的本质差异（内存所有权转移、作用域决定生命周期）。
- **产出**：ByteUtils/TimeUtils 工具库 + 对应单测。

### P3 Qt 核心类型与隐式共享
- **目标**：QString/QByteArray/QVariant/QList/QMap；**隐式共享与写时复制**；QString vs std::string；QByteArray vs std::vector<char>。
- **产出**：类型转换工具 + 单测。

### P4 元对象系统与信号槽
- **目标**：Q_OBJECT/MOC 机制；信号槽五种 connect 写法（含 lambda）；connection type 与跨线程；生命周期与 deleteLater。
- **核心**：讲透"为什么点击按钮能触发槽"的机制链。
- **产出**：跨模块信号槽连通演示（如"设置页改主题 → 主窗口变色"）。

### P5 UI 基础与主窗口框架 + QSS
- **目标**：布局系统、SizePolicy、控件族、Menu/ToolBar/StatusBar、Dock、Tab；QSS 主题；高 DPI。
- **产出**：完整主窗口框架 + 深色工业主题。

### P6 日志系统
- **目标**：分级日志、线程标记、文件轮转、捕获 qDebug；理解与 WPF NLog 的异同。
- **产出**：LogManager + 日志页实时滚动。

### P7 配置系统
- **目标**：QSettings(INI)、JSON 配置、默认值、校验、版本升级；与 app.config/JsonConfig 对照。
- **产出**：ConfigManager + 设置页。

### P8 领域模型与 Model/View
- **目标**：QAbstractTableModel 完整实现（data/setData/flags/headerData/beginEndInsert/dataChanged）；理解 QTableView vs QTableWidget。
- **产出**：设备表/通道表增删改查，Model 持久化到 JSON。

### P9 串口通信模块
- **目标**：QSerialPortInfo 扫描、参数配置、readyRead 事件驱动收发、与同步读的本质差异。
- **产出**：串口连接模拟设备（或回环）收发验证。

### P10 协议引擎
- **目标**：设计帧协议（帧头/长度/命令/数据/CRC）；QByteArray 缓冲；**粘包/分包**状态机解析；CRC16。
- **产出**：FrameParser 单元测试（含粘包/分包/坏帧边界用例）。

### P11 TCP 通信与模拟设备
- **目标**：QTcpSocket 客户端、QTcpServer 模拟设备、心跳、断线检测、重连；与 TcpClient/TcpListener 对照。
- **产出**：模拟设备程序 + TCP 全链路联调。

### P12 多线程采集与异步
- **目标**：QThread + moveToThread Worker 模式；每设备一线程；跨线程 QueuedConnection；QThreadPool/QtConcurrent/QFuture；QMutex 线程安全；解释"为什么 Worker 线程不能碰 QWidget"。
- **产出**：多设备并发采集、UI 实时刷新不卡顿。

### P13 通信状态机与错误处理
- **目标**：自定义状态机（Idle→Connecting→Connected→Running→Error→Retry）；超时与重连；错误分级处理；对比 QStateMachine。
- **产出**：断线/超时/重连/报警联动现场演示。

### P14 实时监控 UI（自绘控件）
- **目标**：paintEvent/重绘机制、双缓冲、自定义控件封装（信号槽对外）、Qtimer 驱动刷新；RealTimeCurve/Gauge/LED。
- **产出**：监控页实时曲线/仪表推进。

### P15 记录回放 + 集成测试 + 部署 + 总结

## ⑫ 测试方案

### 12.1 测试分层

| 层级 | 工具/手段 | 覆盖对象 | 运行时机 |
|------|----------|---------|---------|
| 单元测试 | Qt Test (`QTEST_MAIN`) | ByteUtils / CRC16 / FrameParser / ConfigManager / DeviceState / DataModel | 每阶段随代码编写 |
| 协议测试 | Qt Test（构造字节流） | 帧解析、命令构造、粘包/分包、坏帧 | P10 |
| 边界测试 | Qt Test（空/满/超长/非法参数） | 解析器、配置校验、通道缩放 | 随各模块 |
| 错误测试 | Qt Test（异常输入/超时模拟） | 状态机、通信层 | P13 |
| 集成测试 | 模拟设备 + 真实时序 | 串口/TCP 全链路、多设备并发、断线重连 | P11/P12/P15 |
| 冒烟测试 | `smoke.bat` 脚本 | 启动→连接模拟设备→采集→报警→记录→回放→退出 | 每阶段末 / 发布前 |
| 发布测试 | windeployqt 后手动清单 | 无 Qt 环境运行、启动、核心流程 | P15 |

### 12.2 测试工程组织

```
tests/
├── unittests/   # Qt Test target，CMake 一键 `ctest`
├── integration/ # 启动模拟设备 + 主程序做场景断言
└── smoke/       # smoke.bat 冒烟脚本
```

### 12.3 典型测试用例（示例）

| 用例 | 输入 | 期望 |
|------|------|------|
| FrameParser 正常帧 | 完整一帧字节流 | 正确解析出命令与数据 |
| FrameParser 粘包 | 两帧合并一次到达 | 拆出两帧 |
| FrameParser 分包 | 一帧分两次到达 | 缓存后再拼出完整帧 |
| CRC16 校验 | 合法/非法数据 | 校验通过/拒绝 |
| ConfigManager 版本升级 | 旧版配置 | 自动升级不丢默认值 |
| DeviceState 重试 | 连续失败 N 次 | 状态机进入 Failed |
| Channel 缩放 | 原始值+缩放系数 | 物理量正确 |
