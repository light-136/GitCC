## 二、协议层设计

### 2.1 帧格式

```
字节偏移:  0      1     2-3      4-5       6~N     (N+1)~(N+2)
字段:     SOF   FUNC   CMD     DATALEN    DATA       CRC
固定值:   0x01  0x06  大端模式  小端模式    变长     小端模式
```

**CRC计算范围**: 从SOF到DATA区域（不含CRC本身）

### 2.2 CRC16/Modbus算法

- 多项式: 0xA001（反转形式）
- 初始值: 0xFFFF
- 存储方式: 小端（低字节在前）

### 2.3 指令定义

| 指令名 | CMD码 | 方向 | 说明 |
|--------|-------|------|------|
| UPGRADE_REQ | 0x0010 | 上位机→驱动器 | 升级请求 |
| UPGRADE_START | 0x0011 | 上位机→驱动器 | 启动升级(含文件大小) |
| UPGRADE_DATA | 0x0012 | 上位机→驱动器 | 发送数据(≤128B/帧) |
| JUMP_APP | 0x0013 | 上位机→驱动器 | 完成升级跳转 |
| VER_REQ | 0x0014 | 上位机→驱动器 | 查询版本号 |

### 2.4 ProtocolFrame类设计

- `Serialize()`: 将帧对象序列化为字节数组（注意大端/小端差异）
- `Deserialize()`: 从字节数组反序列化，含SOF/CRC校验
- `FrameBuilder`: 静态工厂，快速构建各指令帧

## 三、通讯服务设计

### 3.1 SerialPortService

**核心机制**: 事件驱动 + 异步等待

```
发送请求 → 清空接收缓冲区 → 创建TaskCompletionSource
         → 写入串口 → 等待DataReceived事件
         → 接收数据追加到缓冲区 → 尝试解帧
         → 解帧成功 → 通过TCS返回结果
```

**粘包/分包处理**:
1. 接收数据追加到`_receiveBuffer`
2. 在缓冲区中搜索SOF(0x01)作为帧起始
3. 丢弃SOF前的无效数据
4. 根据DATALEN判断帧是否完整
5. 完整则解析，不完整则等待更多数据

### 3.2 FirmwareUpgradeService 状态机

```
Idle → Requesting → Erasing → Transferring → Finishing → Completed
  │       │            │           │             │
  └───────┴────────────┴───────────┴─────────────┴──→ Failed
```

**关键设计**:
- 每步均有重试机制(MAX_RETRY=3)
- 擦除Flash超时延长至30秒
- 分包传输每帧≤128字节
- 支持CancellationToken取消
- 进度报告: 数据传输阶段占10%-95%

## 五、线程安全设计

1. **串口数据接收**: DataReceived事件在后台线程触发
2. **UI更新**: 通过`Application.Current.Dispatcher.Invoke()`切换到UI线程
3. **接收缓冲区**: 使用`lock(_bufferLock)`保护
4. **异步等待**: 使用`TaskCompletionSource`连接接收线程和等待线程
5. **取消支持**: 通过`CancellationTokenSource`实现
