## 二、协议要点总结（依据 docx 原文）

### 2.1 帧格式（固定）

```
| 字节0 | 字节1 | 字节2-3 | 字节4-5 | 字节6 ~ N | (N+1)-(N+2) |
|  SOF  |  FUNC |  CMD    | DATALEN |   DATA    |    CRC      |
| 0x01  | 0x06  | 大端2B  | 小端2B  |  变长     | 小端2B      |
```

- **SOF** = 0x01（帧头）；**FUNC** = 0x06（功能码）
- **CMD**：2 字节，**大端**（高字节在前）
- **DATALEN**：2 字节，**小端**（低字节在前），表示 DATA 长度
- **CRC**：2 字节，**小端**，CRC 校验范围 = SOF 到 DATA 全部字节

### 2.2 CRC16 算法（CRC16/Modbus）

| 参数 | 值 |
|------|-----|
| 多项式 | 0xA001（反向形式，等价标准多项式 0x8005 反向） |
| 初值 | 0xFFFF |
| 输出 | 2 字节，小端存储 |

### 2.3 五条指令

| # | 名称 | CMD | 发送 DATA | 回复 DATA[0] 含义 |
|---|------|-----|-----------|-------------------|
| 1 | UPGRADE_REQ | 0x0010 | [0x01=请求升级 / 0x02=查询状态, 0x00保留] | 0x00=在Boot已就绪 / 0x01=App中跳转Boot / 0x02=App仅回状态 / 0x03=Boot仅回状态 |
| 2 | UPGRADE_START | 0x0011 | [文件总大小 uint32 小端 4B] | 0x00=擦除完成可升级 / 0x01=擦除失败 |
| 3 | UPGRADE_DATA | 0x0012 | [偏移地址 uint32 小端 4B + 数据 ≤128B] | 0x00=本帧完成 / 0x01=本帧失败 |
| 4 | JUMP_APP | 0x0013 | [0x01=升级完成请求] | 0x00=升级成功 / 0x01=升级失败 |
| 5 | VER_REQ | 0x0014 | [0x01=请求版本号] | 回复 5 字节版本号（各字节为版本分量） |

### 2.4 升级四步时序（上位机视角）

```
Step1: 发 UPGRADE_REQ(0x0010) → 收到 "在Boot已就绪"(0x00) 才继续
       （若返回 0x01 App跳转Boot，等2秒重试）
Step2: 发 UPGRADE_START(0x0011, 文件大小) → 驱动器擦除 Flash → 收到 0x00
Step3: 循环发 UPGRADE_DATA(0x0012)：
       - 每帧 DATA ≤ 128 字节
       - 每帧带文件内偏移地址
       - 每帧需等回复 0x00 才发下一帧
       - 超时/失败可重试（最多3次）
Step4: 发 JUMP_APP(0x0013) → 驱动器跳转 App → 收到 0x00 即成功
```

### 2.5 串口参数（来源：官方工具 ConfigInfo.ini + WPF 版默认值）

| 参数 | 默认值 |
|------|--------|
| 波特率 | 115200 |
| 数据位 | 8 |
| 停止位 | 1 |
| 校验位 | EVEN（偶校验） |
| 升级数据每帧 | ≤ 128 字节 |
| 通讯超时 | 5 秒（擦除阶段 30 秒） |

## 三、技术选型

| 层次 | 技术 | 说明 |
|------|------|------|
| 语言/框架 | C++17 + Qt Widgets | 稳定、贴近硬件、无需 QML 运行时 |
| 构建系统 | qmake (.pro) | Qt Creator 原生支持，本机 qmake 3.1 直接可用 |
| 串口模块 | QtSerialPort (`QT += serialport`) | Qt 官方串口库，事件驱动 |
| GUI | QWidget 手写布局 + QSS 样式 | 界面风格参考 WPF 版（分组框布局） |
| 通讯架构 | 信号槽 + 状态机 | 替代 C# 的 async/await，QSerialPort 异步事件驱动 |
| 日志 | QPlainTextEdit 实时显示 | 参考 WPF 版日志区 |
| 测试 | Qt Test (`QT += testlib`) | CRC、帧组拆、解析器单元测试 |

> **设计取舍说明**：C# 版用 `async/await + TaskCompletionSource` 实现"发一帧等一帧"。Qt 中没有等价物，本项目采用**串口服务层做单请求-单响应封装 + 升级引擎状态机**的经典 Qt 模式：
> - `SerialPortService`：负责收发、粘包拆帧、超时，每次只服务一个待响应请求；
> - `FirmwareUpgradeService`：以 `QStateMachine` 风格的状态枚举驱动四步流程，收到回复信号后推进到下一步。

### 4.3 核心类设计（信号槽契约）

**SerialPortService（QObject）**
```
公开方法: open(config) / close() / sendRequest(frame, expectedCmd, timeoutMs)
          / queryVersion() / refreshPorts()
信号:    requestCompleted(ProtocolFrame) / requestFailed(int原因)
         logMessage(QString) / connectionChanged(bool)
内部:    QSerialPort + QTimer(超时) + QByteArray(粘包缓冲) + 待响应CMD
```

**FirmwareUpgradeService（QObject，状态机引擎）**
```
状态:    Idle → Requesting → Erasing → Transferring → Finishing → Completed/Failed
公开:    startUpgrade(QByteArray固件) / cancel() / queryVersion()
信号:    progressChanged(int%, QString) / stateChanged / logMessage / finished(bool)
```

**FirmwareParser（静态工具）**
```
LoadFirmware(path) → FirmwareInfo{path, name, QByteArray data, 大小友好文本}
校验: .bin 扩展名、非空、≤ 2MB
```

**MainWindow（QWidget）**
```
区域:  ①串口配置  ②固件文件  ③操作按钮  ④进度+状态  ⑤日志
按钮:  打开/关闭串口 / 选择固件 / 查询版本 / 开始升级 / 取消升级 / 清空日志
```
