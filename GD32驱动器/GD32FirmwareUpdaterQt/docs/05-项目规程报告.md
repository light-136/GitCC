## 一、项目概述

### 1.1 项目背景

用户具备两个既有资源：
1. **旧烧录软件**：他人提供的 Qt 编写的烧录软件（仅发布 exe，无源码，不可维护）
2. **新版烧录软件**：Claude 编写的 C# WPF 版 `GD32FirmwareUpdater`（有完整源码，功能完整）

技术协议：`GD32低压驱动器Boot升级协议.docx`（帧格式、命令、时序的权威来源）。

### 1.2 项目目标（双目标）

| 目标 | 内容 | 优先级 |
|------|------|--------|
| **功能目标** | 用 Qt/C++ 仿写功能等价的烧录软件 | 必须 |
| **学习目标** | 以本项目为契机构建 WPF→Qt 系统化知识体系 | 同等重要 |

> 用户明确："我是熟悉 WPF 的，想借助这个契机了解学习 Qt。功能开发是一方面，最重要的是完整呈现 Qt 技术知识。"

### 1.3 交付成果

- 可运行、可部署的 Qt 烧录软件（源码 + 发布包）
- 25 个单元测试全部通过
- 5 份项目文档（规划/详细设计/学习指南/使用说明/本报告）

## 二、项目规程

### 2.1 开发流程

```
需求理解 ──→ 技术选型 ──→ 规划文档 ──→ 详细设计 ──→ 编码实现 ──→ 单元测试
                                                              │
    部署验证（windeployqt）←── 冒烟测试 ←── 编译构建 ←─────────┘
```

### 2.2 阶段记录

| 阶段 | 主要工作 | 产出 |
|------|----------|------|
| **1. 需求分析** | 解读 3 项资源；确认真实环境（仅 Qt 5.12.2 MinGW） | `01-完整规划文档.md`（含 17 项 WPF→Qt 映射） |
| **2. 技术选型** | qmake + Qt Widgets + QSerialPort + Qt Test；C++17；单线程事件驱动 | 工程骨架 |
| **3. 详细设计** | 四层架构（View/Service/Protocol/Model）；升级状态机；拆帧算法 | `02-详细设计文档.md` |
| **4. 编码实现** | 协议层 → 服务层 → 模型层 → 界面层 逐层实现 | `src/` 全部源码 |
| **5. 单元测试** | CrcTest / FrameTest / ParserTest 三组 | `tests/`，25 用例全通过 |
| **6. 构建验证** | qmake + mingw32-make 编译 0 错误；`--smoke` 冒烟通过 | `build/` |
| **7. 部署验证** | windeployqt 打包；脱离 Qt 环境独立运行成功 | 发布包 |
| **8. 文档收尾** | 学习指南 / 使用说明 / 本报告 | `docs/` |

### 2.3 工程质量保障措施

| 措施 | 具体做法 |
|------|----------|
| **架构分层** | Protocol/Service/Model/View 四层解耦，信号槽通讯 |
| **契约先行** | 协议帧/CRC/命令常量独立成层，可单测 |
| **单元测试** | 算法类（CRC/帧/解析）100% 覆盖核心路径 |
| **冒烟模式** | `--smoke` 参数支持自动化启动验证 |
| **日志审计** | 全流程 TX/RX 十六进制日志，可追溯 |
| **版本兼容** | 仅使用 Qt 5.12 可用 API（如无 connectOnce 用 QSharedPointer 替代） |
