## 一、项目概述

### 1.1 项目简介

**Claude Code** 是由 Anthropic 公司开发的一款**智能体编程工具（Agentic Coding Tool）**。它运行在终端（Terminal）中，能够理解你的整个代码库，并通过自然语言命令帮助开发者更快地编写代码。

**核心定位**：一个"住在终端里的AI程序员"——通过自然语言交互完成代码编写、解释、调试、Git操作等日常开发任务。

### 1.2 仓库统计

| 指标 | 数值 |
|------|------|
| GitHub Stars | 129,000+ |
| Forks | 21,000+ |
| 当前版本 | 2.1.159 |
| 主要语言 | Python (79.7%), Shell (13.7%), TypeScript (5.0%) |
| 支持平台 | macOS, Linux, Windows |
| 运行要求 | Node.js 18+ |

### 1.3 使用方式

Claude Code 提供三种使用入口：
1. **终端（Terminal）**：直接在命令行中运行 `claude` 命令
2. **IDE集成**：在 VS Code、Cursor、Windsurf 等编辑器中使用
3. **GitHub集成**：在 GitHub PR/Issue 中通过 `@claude` 标签触发

## 三、六大核心子系统

Claude Code 的架构可以分为 **六大子系统**，它们协同构成了一个完整的 AI 辅助开发平台：

```
┌─────────────────────────────────────────────────────────────┐
│                    Claude Code 架构全景                       │
│                                                             │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐                  │
│  │ 1.插件   │  │ 2.命令   │  │ 3.智能体 │  ← 扩展层       │
│  │   系统   │  │   系统   │  │   系统   │                  │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘                  │
│       │              │              │                        │
│  ┌────┴──────────────┴──────────────┴─────┐                 │
│  │           4. 钩子系统（Hook）           │  ← 拦截层      │
│  └────────────────┬───────────────────────┘                 │
│                   │                                         │
│  ┌────────────────┴───────────────────────┐                 │
│  │         5. MCP 集成系统                │  ← 连接层      │
│  └────────────────┬───────────────────────┘                 │
│                   │                                         │
│  ┌────────────────┴───────────────────────┐                 │
│  │     6. 权限与安全系统                  │  ← 基础层      │
│  └────────────────────────────────────────┘                 │
│                                                             │
│  ╔═══════════════════════════════════════╗                   │
│  ║     Claude AI 核心引擎（闭源）        ║  ← 核心引擎     │
│  ╚═══════════════════════════════════════╝                   │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 子系统一：插件系统（Plugin System）

**作用**：可扩展性基座——所有功能扩展都通过插件实现。

每个插件遵循标准化目录结构：
```
plugin-name/
├── .claude-plugin/plugin.json    # 插件元数据清单
├── commands/                     # 斜杠命令（.md 文件）
├── agents/                       # 自主智能体定义（.md 文件）
├── skills/                       # 技能包
│   └── skill-name/
│       ├── SKILL.md              # 核心技能文档
│       ├── references/           # 参考资料
│       └── examples/             # 代码示例
├── hooks/                        # 事件处理器
│   ├── hooks.json                # 钩子注册配置
│   └── *.py / *.sh               # 钩子处理脚本
└── README.md                     # 插件说明文档
```

**设计原则**：
- **约定优于配置**：固定目录名自动发现
- **路径可移植**：使用 `${CLAUDE_PLUGIN_ROOT}` 环境变量
- **渐进披露**：元数据 → 主文档 → 资源文件（三级加载）

### 3.2 子系统二：命令系统（Command System）

**作用**：可复用的提示词模板——用户通过 `/command` 触发。

命令是带有 YAML 前置元数据的 Markdown 文件：
```markdown
---
description: 简要描述（≤60字符）
allowed-tools: Read, Write, Edit, Bash(git:*)
model: sonnet
argument-hint: [参数1] [参数2]
---

你是一个专门处理xxx的助手...
当前上下文: `!git status`
用户参数: $ARGUMENTS
```

**存储层级**（优先级从低到高）：
| 层级 | 路径 | 共享范围 |
|------|------|----------|
| 插件分发 | `plugin/commands/` | 社区共享 |
| 个人专属 | `~/.claude/commands/` | 仅个人 |
| 团队共享 | `.claude/commands/` | 项目团队 |

### 3.3 子系统三：智能体系统（Agent System）

**作用**：自主子进程——可并行执行复杂多步骤任务。

智能体是 Markdown 定义的自治工作单元：
```markdown
---
name: code-explorer
description: |
  用于探索代码库功能...
model: sonnet
color: blue
tools: ["Read", "Grep", "Glob"]
---

你是一个代码探索专家...
```

**命令 vs 智能体 对比**：

| 维度 | 命令（Command） | 智能体（Agent） |
|------|----------------|----------------|
| 触发方式 | 用户手动调用 `/xxx` | 系统根据描述自动匹配 |
| 执行环境 | 主对话上下文 | 独立子进程 |
| 适用场景 | 标准操作 | 复杂多步骤任务 |
| 并行能力 | 串行执行 | 可多个并行 |

### 3.4 子系统四：钩子系统（Hook System）

**作用**：事件驱动的生命周期拦截器——在关键节点插入自定义逻辑。

**完整生命周期事件链**：
```
SessionStart → UserPromptSubmit → PreToolUse → [工具执行] → PostToolUse → Stop
    │                                                                      │
    │              PreCompact ← 上下文压缩时                               │
    │              SubagentStop ← 子智能体停止时                           │
    │              Notification ← 通知触发时                                │
    └──────────────────── SessionEnd ← 会话清理 ──────────────────────────┘
```

**钩子类型**：
| 类型 | 实现方式 | 适用场景 | 速度 |
|------|---------|---------|------|
| 命令钩子 | Shell脚本 | 确定性校验 | ⚡ 快速 |
| 提示词钩子 | LLM调用 | 上下文感知决策 | 🐢 较慢 |

### 3.5 子系统五：MCP 集成系统

**作用**：外部服务连接器——通过 Model Context Protocol 对接外部工具。

| 传输协议 | 通信方式 | 典型用途 |
|----------|---------|---------|
| stdio | 本地进程 | 本地文件系统、数据库 |
| SSE | 服务端推送 | 云服务（Asana、GitHub） |
| HTTP | REST API | RESTful 后端 |
| WebSocket | 双向通信 | 实时数据流 |

### 3.6 子系统六：权限与安全系统

**作用**：安全基座——多层权限管控与沙箱机制。

**配置优先级层级**（从高到低）：
```
┌─────────────────────────────────┐
│ managed-settings.json           │ ← 企业/MDM 策略（最高优先级）
├─────────────────────────────────┤
│ .claude/settings.json           │ ← 项目级配置（团队共享）
├─────────────────────────────────┤
│ .claude/settings.local.json     │ ← 用户本地覆盖
├─────────────────────────────────┤
│ ~/.claude/settings.json         │ ← 用户全局配置（最低优先级）
└─────────────────────────────────┘
```

**权限级别**：
- `allow`（允许）：无需确认，直接执行
- `ask`（询问）：每次执行前确认
- `deny`（拒绝）：完全阻止执行

**沙箱机制**：
- 网络隔离（域名白名单、Socket限制）
- 命令黑名单排除
- HTTP/SOCKS 代理配置

## 四、13 个官方插件详解

### 4.1 开发流程类插件（5个）

| 插件 | 用途 | 核心组件 |
|------|------|---------|
| **feature-dev** | 7阶段结构化功能开发 | `/feature-dev` 命令 + 3个智能体 |
| **agent-sdk-dev** | Agent SDK 项目脚手架 | `/new-sdk-app` + 验证智能体 |
| **plugin-dev** | 插件开发工具包 | 7项专业技能 + 3个智能体 |
| **claude-opus-4-5-migration** | 模型版本迁移 | 迁移技能 |
| **frontend-design** | 生产级UI设计指引 | 设计技能 |

**feature-dev 的7阶段工作流**（最具代表性）：
```
阶段1：需求发现 → 澄清需求
    ↓
阶段2：代码库探索 → 启动 2-3 个 code-explorer 智能体并行扫描
    ↓
阶段3：澄清问题 → 列出疑问等待回答
    ↓
阶段4：架构设计 → 启动 2-3 个 code-architect 智能体提出方案
    ↓
阶段5：代码实现 → 等待用户批准后执行
    ↓
阶段6：质量审查 → 启动 3 个 code-reviewer 智能体并行审查
    ↓
阶段7：总结输出 → 文档化变更
```

### 4.2 代码质量类插件（3个）

| 插件 | 用途 | 智能体数量 |
|------|------|-----------|
| **code-review** | 多智能体PR审查 | 4个并行（CLAUDE.md合规×2 + Bug检测 + 历史分析） |
| **pr-review-toolkit** | 全面PR分析 | 6个专业智能体 |
| **commit-commands** | Git工作流自动化 | `/commit`、`/commit-push-pr`、`/clean_gone` |

### 4.3 行为修改类插件（4个）

| 插件 | 用途 | 机制 |
|------|------|------|
| **hookify** | 从模式创建钩子 | 规则引擎 + Python |
| **ralph-wiggum** | 自引用迭代循环 | Stop钩子拦截 |
| **explanatory-output-style** | 教育性输出模式 | SessionStart钩子 |
| **learning-output-style** | 交互式学习模式 | SessionStart钩子 |

### 4.4 安全类插件（1个）

**security-guidance**（三层安全审查）：
```
第1层：模式警告 → 正则匹配 ~25 种危险模式（即时反馈）
  ↓
第2层：LLM差异审查 → 快速模型审查变更文件（会话结束时）
  ↓
第3层：智能体提交审查 → SDK驱动的跨文件漏洞检测（异步）
```

                    ┌─────────────┐

### 5.2 @claude 工作流

当在 Issue/PR 中 `@claude` 时：
1. `claude.yml` 工作流触发
2. 使用 `anthropics/claude-code-action@v1` Action
3. 通过 Workload Identity Federation 安全认证
4. Claude 使用 Sonnet 4.5 模型处理请求
5. 结果以评论形式回复

## 七、关键架构洞察

1. **闭源核心 + 开源插件生态**：CLI 运行时是闭源的，但整个插件系统完全开放可扩展
2. **Markdown即代码**：命令、智能体、技能全部用 Markdown 定义，极大降低了开发门槛
3. **多智能体并行编排**：大量使用并行智能体实现全面分析（代码审查、功能开发、PR审查）
4. **安全优先架构**：多层防护——模式检测、LLM审查、智能体分析、权限层级
5. **GitHub原生自动化**：深度集成 GitHub Actions 实现 Issue 分类、去重和 @claude 交互
6. **企业就绪**：支持 MDM、Workload Identity Federation、托管配置、网络隔离
