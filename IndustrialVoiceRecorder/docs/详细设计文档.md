### 1.1 项目名称

v1.0.0

## 3. 模块设计

### 3.1 音频采集模块 (NAudioCaptureService)
**文件**: Infrastructure/Audio/NAudioCaptureService.cs

**设计思路**:
- 使用NAudio库的WaveInEvent类进行音频采集
- 支持枚举所有音频输入设备（包括蓝牙设备）
- 配置16kHz采样率、单声道、16位深度
- 通过事件驱动方式将音频数据传递给上层

**关键参数**:
- 采样率: 16000Hz
- 声道: 1（单声道）
- 位深: 16bit
- 缓冲: 100ms

### 3.2 语音识别模块 (WhisperRecognitionService)
**文件**: Infrastructure/SpeechRecognition/WhisperRecognitionService.cs

**设计思路**:
- 使用Whisper.net（Whisper.cpp的C#绑定）实现离线识别
- 启动时异步加载模型，避免阻塞UI
- 使用信号量确保同一时刻只有一个识别任务
- 内置简单VAD，跳过静音段以提高效率

**识别流程**:
```
PCM字节数据
    ↓ ConvertBytesToFloatSamples()
归一化float数组 [-1.0, 1.0]
    ↓ HasValidAudio() [VAD检测]
有效语音段
    ↓ WriteWavToStream() [构造WAV]
WAV流数据
    ↓ WhisperProcessor.Process()
识别文本
```

### 3.3 文本处理模块 (TextProcessor)
**文件**: Infrastructure/SpeechRecognition/TextProcessor.cs

**设计思路**:
- 词汇纠正：修正常见识别错误（如"思印"→"丝印"）
- 产品编号提取：支持多种格式（1号、第1个、1#）
- 状态判定：基于关键词列表判定OK/NG
- 分类归属：按关键词匹配到7个分类

**处理流程**:
```
原始识别文本
    ↓ CorrectText() [词汇纠正]
纠正后文本
    ↓ ExtractProductId() [提取编号]
    ↓ DetermineStatus() [判定状态]
    ↓ DetermineCategory() [分类]
    ↓ ExtractRemarks() [提取备注]
结构化记录
```

### 3.4 协调服务模块 (VoiceProcessingService)
**文件**: Infrastructure/Services/VoiceProcessingService.cs

**设计思路**:
- 作为核心协调器，串联音频采集→识别→处理→存储
- 实现音频缓冲区管理（累积3-5秒再识别）
- 基于VAD的智能触发机制
- 通过事件通知UI更新

**触发识别条件**:
1. 检测到语音活动后，静音超过1.5秒
2. 缓冲区超过最大值（5秒音频数据）

### 3.5 数据存储模块 (VoiceRecordRepository)
**文件**: Infrastructure/Persistence/VoiceRecordRepository.cs

**设计思路**:
- 使用SQLite作为本地数据库
- 使用Dapper作为轻量级ORM
- 启动时自动创建表结构
- 支持按日期、关键词查询
- 内置统计查询功能

### 3.6 Excel导出模块 (ExcelExportService)
**文件**: Infrastructure/Export/ExcelExportService.cs

**设计思路**:
- 使用EPPlus库生成Excel文件
- 支持表头样式、状态着色（NG行标红）
- 支持进度回调
- 同时支持CSV格式导出

## 7. 线程模型

### 7.1 线程分布
| 线程 | 职责 |
|------|------|
| UI线程 | WPF界面渲染和交互 |
| NAudio回调线程 | 音频数据采集回调 |
| 识别工作线程 | Whisper模型推理 |
| 数据库IO线程 | SQLite读写操作 |

### 7.2 线程安全
- 音频缓冲区使用lock保护
- 识别任务使用SemaphoreSlim(1,1)确保单任务
- UI更新通过Dispatcher.Invoke回到主线程
- 数据库操作使用async/await异步执行

## 8. 错误处理

### 8.1 异常策略
- 音频设备异常：自动停止录音，提示用户重连
- 识别引擎异常：记录日志，返回空结果
- 数据库异常：记录日志，抛出异常
- 导出异常：显示错误消息，记录日志

### 8.2 日志策略
- 使用Serilog结构化日志
- Debug级别：音频数据处理、识别中间结果
- Information级别：关键操作（启动、停止、保存）
- Warning级别：非致命问题（设备未找到、模型缺失）
- Error级别：异常和错误
